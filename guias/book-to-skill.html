01 · la analogía explicada a fondo

Qué hace book-to-skill (sin marketing)

La analogía corta

Imaginate que cada chat de Claude es un cuarto vacío y cada libro tuyo es un experto encerrado en una caja. Book-to-skill agarra la caja, abre el experto, lo desempaca capítulo por capítulo y lo deja viviendo en el pasillo · listo para entrar al cuarto cuando vos mencionás su tema.

La analogía larga · explicada a fondo

Si vos abrís un chat de Claude y le pegás el capítulo 5 de un libro técnico, Claude lo lee, te contesta una vez, y cuando cerrás el chat se borra todo. La próxima vez que abrís Claude para preguntarle del mismo tema, le tenés que volver a pegar el capítulo. Multiplicalo por veinte capítulos y cinco libros y ves por qué la gente termina rendida.

Book-to-skill rompe ese loop. Le pasás el PDF entero (o el EPUB, el DOCX, el MOBI · acepta 8+ formatos), corre adentro de Claude Code, y descompone el libro en cinco archivos markdown que viven en `~/.claude/skills/<nombre-del-libro>/`. Esos cinco archivos son la habilidad. Y Claude la trata como cualquier otra skill · si hablás del tema, la carga sola; si no, ni la toca.

Lo importante de esa descomposición es que NO mete los 400 páginas del libro adentro del system prompt cada vez que abrís un chat. Mete solo el SKILL.md que pesa unos 4k tokens (mental models + índice de capítulos) y carga los capítulos uno por uno on-demand. O sea · podés tener veinte libros instalados sin que tu cuenta se queme.

Qué es de verdad (sin analogías)

Es una skill de Claude Code (no una app aparte, no un servicio en la nube) escrita 100% en Python por Virgilio Jr. (`virgiliojr94`), MIT, con 1.3k estrellas en GitHub al momento de escribir esta guía. Por debajo usa Docling para libros técnicos (preserva tablas y bloques de código), pdftotext / PyPDF2 / pdfminer como fallback para PDFs texto-heavy, ebooklib para EPUB, python-docx para Word, Calibre para MOBI/AZW y la stdlib para los formatos planos. Vos no tenés que saber ni instalar nada de eso a mano · la skill se encarga de pedirte permiso e instalar lo que falte.

Por qué importa

Porque resuelve el problema más grande de Claude · la memoria de cero por cada chat. Cuando convertís el manual de tu producto, el libro técnico de tu industria o los procesos de tu negocio en una skill, dejás de explicarle a Claude desde cero cada vez. La próxima vez que abrís un chat y mencionás el tema, Claude ya es experto · sin que vos hagas nada extra.

03 · los 8+ formatos que come la skill

Qué formatos acepta · y qué librería usa cada uno

Esto es lo que casi nadie te explica · book-to-skill no usa una sola librería para todo. Por debajo elige la herramienta correcta según el tipo de archivo y el contenido. Antes de empezar la extracción, la skill te pregunta si el libro es técnico (con código y tablas) o texto-heavy (novela, ensayo, manual narrativo), y con esa respuesta decide cuál librería usar.

PDF técnicos

.pdf · libros con código, tablas, fórmulas

Librería que usa

Docling (`pip3 install docling`)

Preserva tablas, bloques de código y estructura · ideal para libros de programación, manuales técnicos, papers académicos. Tarda ~1.5 segundos por página pero la calidad de la extracción es muy superior.

PDF texto-heavy

.pdf · novelas, ensayos, manuales narrativos

Librería que usa

pdftotext (poppler) · PyPDF2 · pdfminer.six como fallback

Más rápido que Docling pero no preserva tablas. Si el libro es todo prosa, pdftotext basta. La skill cae a PyPDF2 o pdfminer si el primero falla.

EPUB

.epub · ebooks libres y de tienda

Librería que usa

ebooklib + beautifulsoup4 (`pip3 install ebooklib beautifulsoup4`)

El formato preferido si lo tenés a mano · ya viene estructurado por capítulos, la extracción es casi perfecta. Si ebooklib falla, cae a stdlib zipfile.

DOCX

.docx · documentos Word

Librería que usa

python-docx (`pip3 install python-docx`)

Útil para procesos de negocio o manuales internos que viven en Word. Preserva headings, listas y tablas básicas.

MOBI / AZW / AZW3

.mobi · .azw · .azw3 · ebooks de Kindle

Librería que usa

Calibre `ebook-convert` (externo · https://calibre-ebook.com/download)

Necesitás Calibre instalado en tu sistema (no es una pip install, es una app aparte). Una vez instalado, book-to-skill lo invoca por debajo · vos no tocás nada.

HTML

.html · .htm · páginas web exportadas

Librería que usa

beautifulsoup4 (`pip3 install beautifulsoup4`)

Si guardaste documentación o un blog completo como HTML, la skill limpia el ruido (nav, footer, ads) y se queda con el contenido principal.

RTF

.rtf · Rich Text Format

Librería que usa

striprtf (`pip3 install striprtf`)

Formato viejo de Word/WordPad. Si tenés manuales de hace 15 años todavía en RTF, sirve.

Texto plano

.txt · .md · .rst · .adoc

Librería que usa

stdlib (no requiere instalar nada)

Markdown, reStructuredText, AsciiDoc y plain text · todo se procesa sin librerías externas. Si tu documentación ya está en markdown, este es el camino más limpio.

OCR · no soportado

Importante · book-to-skill NO tiene OCR. Si tu PDF es un escaneo (imágenes de páginas, no texto extraíble), la skill no va a poder leerlo. Probá abriendo el PDF y seleccionando texto · si podés copiar y pegar, sirve; si no podés porque son imágenes, primero corré OCR con otra herramienta (Tesseract, Adobe Acrobat o un servicio en la nube) y después usás book-to-skill sobre el PDF resultante.

04 · qué deja la skill en tu disco

Los 5 archivos que aparecen en ~/.claude/skills/<slug>/

Cuando la skill termina de procesar tu libro, deja una carpeta nueva dentro de `~/.claude/skills/<slug>/` con cinco archivos. Cada uno tiene un trabajo distinto y se carga en momentos distintos · esto es lo que hace que tener veinte libros instalados no queme tu budget.

Cómo queda en tu disco

~/.claude/skills/<slug>/
├── SKILL.md                     ← se carga siempre que mencionás el tema (~4k tokens)
├── chapters/
│   ├── ch01-introduccion.md     ← carga solo si preguntás del cap 1 (~1k tokens c/u)
│   ├── ch02-fundamentos.md
│   ├── ch03-...
│   └── ch20-conclusion.md
├── glossary.md                  ← carga si preguntás por un término (~1.5k tokens)
├── patterns.md                  ← carga si preguntás por técnicas/algoritmos (~2k tokens)
└── cheatsheet.md                ← carga si pedís reglas rápidas (~1k tokens)

SKILL.md

~4,000 tokens

El cerebro de la skill · mental models + índice de capítulos.

Qué guarda

Resumen ejecutivo del libro, los conceptos centrales que el autor usa una y otra vez, y un índice con los nombres de cada capítulo y sus archivos correspondientes. Es lo primero que Claude ve cuando carga la skill.

Cuándo se carga

Siempre que mencionás el tema. Claude lo lee, entiende el mapa del libro, y después decide si necesita cargar un capítulo específico, el glossary o los patterns.

chapters/ch01-<titulo>.md ... chN.md

~1,000 tokens cada uno

Un archivo por capítulo · cargan on-demand, no muerden budget hasta que aplica.

Qué guarda

El contenido del capítulo limpio · sin headers de página, sin números de paginación rotos, sin ruido. Si el libro tiene tablas o código, Docling las preservó tal cual.

Cuándo se carga

Solo cuando le preguntás algo de ese capítulo · o cuando pedís el capítulo explícitamente con `/<slug> ch05`. El resto del tiempo, no existe para Claude.

glossary.md

~1,500 tokens

Los términos clave del libro ordenados alfabéticamente con referencias.

Qué guarda

Cada término técnico que el libro define, con una explicación corta y el número de capítulo donde se introduce. Pensado para que Claude pueda contestar 'qué significa X según este libro' sin tener que cargar el capítulo entero.

Cuándo se carga

Cuando preguntás por un concepto o término específico · Claude detecta que está en el glossary y lo trae.

patterns.md

~2,000 tokens

Las técnicas, algoritmos y patrones de diseño del libro · todos juntos.

Qué guarda

Si es un libro técnico, acá viven los patrones (patterns de diseño, algoritmos, recetas de arquitectura). Cada uno con su nombre, problema que resuelve y mini-ejemplo. Si es un libro narrativo, este archivo puede quedar vacío o resumido.

Cuándo se carga

Cuando pedís 'aplicar' algo del libro · Claude levanta patterns y combina con el contexto de tu pregunta.

cheatsheet.md

~1,000 tokens

Reglas rápidas, tablas de decisión, atajos · todo en una hoja.

Qué guarda

Tablas comparativas, reglas de bolsillo, 'cuándo usar X vs Y'. Es lo que vos imprimirías y pegarías en la pared al lado del monitor.

Cuándo se carga

Cuando hacés una pregunta de decisión rápida tipo 'cuándo conviene tal cosa' · Claude trae la cheatsheet en vez del capítulo entero.

Pum. Lo hizo. Cinco archivos, una carpeta nueva, y Claude ya sabe del tema · sin que vos hayas pegado el libro en ningún chat.

Invocar la skill ya creada · las 4 formas distintas

Una vez que la skill existe en disco, la usás como cualquier otra skill de Claude Code. El slash command es el slug que elegiste. Estas son las 4 formas distintas de invocarla, cada una hace algo distinto por debajo.

Cargar los mental models · sin pedir nada específico

Comando

/designing-data-intensive-apps
Copiar comando

Claude carga solo el SKILL.md · los conceptos centrales y el índice. Útil para preguntarle algo amplio del libro sin saber todavía qué capítulo te conviene leer.

Buscar un tema dentro del libro

Comando

/designing-data-intensive-apps replication
Copiar comando

Claude lee el SKILL.md, busca dónde aparece 'replication' (en qué capítulos, en el glossary, en patterns), y trae los fragmentos relevantes · sin cargar capítulos enteros.

Pedir un capítulo específico

Comando

Copiar comando

Claude carga directamente `chapters/ch05-<titulo>.md` y lo mantiene como contexto activo. Útil cuando estás estudiando un capítulo en particular.

Pregunta abierta sobre el libro

Comando

/designing-data-intensive-apps "what chapters do you have?"
Copiar comando

Claude responde la pregunta literal usando el SKILL.md como referencia. Sirve para listar capítulos, pedir resumen del libro, comparar enfoques, etc.

Útil cuando tenés dos skills (dos libros) y querés ver cómo cada autor encara el mismo concepto. Claude carga ambos SKILL.md y compara sin pegar libros enteros.

Carga directamente un capítulo concreto y te lo resume. Ideal cuando estás estudiando algo en particular y querés un repaso rápido.

El prompt más útil · le pedís a Claude que use la skill al responder cualquier tarea que esté relacionada con el tema del libro. No hace falta llamar el slash directamente.

07 · qué libros te conviene convertir

Cuatro casos de uso reales · con qué ganar ya

¿El manual de tu producto? Ya es una habilidad. ¿El libro técnico de tu industria? Habilidad. ¿Los procesos de tu negocio? Habilidad. Estos son los cuatro casos donde book-to-skill paga el costo de la instalación en la primera semana. Cada uno con qué cargás, qué le pedís a Claude después y un ejemplo concreto.

Caso 01soporte

Manual de tu producto → habilidad de soporte interno

Qué cargás

Convertís el manual de usuario, la documentación interna o las preguntas frecuentes (FAQ) de tu producto en una skill. Si tenés Notion, exportalo a markdown · si está en Google Docs, exportá a DOCX · si está en PDF, mejor.

Qué le pedís después

Después le pedís a Claude que conteste preguntas de clientes usando esa skill como única fuente · sin inventar features que no existen. Sirve para entrenar a soporte nuevo o para autoresponder primer-nivel.

Ejemplo concreto

Ejemplo · convertís el manual de tu SaaS en `~/.claude/skills/manual-mi-producto/`. Después le pedís: '/manual-mi-producto · cliente pregunta cómo configurar webhooks · respondé usando el manual y citá el capítulo'.

Caso 02mentor

Libro técnico de tu industria → habilidad de mentor permanente

Qué cargás

El libro de cabecera de tu disciplina. Si sos dev · Clean Code, Designing Data-Intensive Applications, Domain-Driven Design. Si sos diseñador · Refactoring UI, Don't Make Me Think. Si sos marketer · Influence, Building a StoryBrand.

Qué le pedís después

Cada vez que tomás una decisión técnica le pedís a Claude que la fundamente contra ese libro. Termina siendo como tener al autor sentado al lado.

Ejemplo concreto

Ejemplo · `/designing-data-intensive-apps · estoy diseñando el sistema de notificaciones de mi app, ¿qué dice el libro sobre el trade-off entre consistencia eventual y disponibilidad?'. Claude carga el capítulo correcto, te trae la cita exacta y razona desde ahí.

Caso 03operaciones

Procesos de tu negocio → habilidad de operaciones

Qué cargás

Los SOPs (Standard Operating Procedures), los runbooks, las políticas internas, los protocolos de atención. Todo lo que normalmente queda perdido en una carpeta de Drive que nadie consulta.

Qué le pedís después

Cuando alguien tiene una duda operativa (cómo hacer X, cuál es la política sobre Y), Claude responde usando esa skill como fuente única. Reduce las preguntas repetidas y deja el conocimiento del equipo accesible.

Ejemplo concreto

Ejemplo · convertís el playbook de onboarding de nuevos empleados en `~/.claude/skills/onboarding-empleados/`. La próxima vez que entra alguien nuevo, le decís 'preguntale a Claude lo que necesites · va a usar nuestro playbook como referencia'.

Caso 04coach

Libros de habilidades blandas → habilidad de coach

Qué cargás

Libros de negociación, comunicación, liderazgo, copywriting, ventas. Los que te interesa aplicar al día a día pero que nunca te acordás de los principios cuando llega el momento.

Qué le pedís después

Antes de mandar un email difícil, tener una conversación complicada o redactar un copy, le pedís a Claude que aplique los principios del libro a tu situación concreta.

Ejemplo concreto

Ejemplo · `/never-split-the-difference · tengo que pedir aumento de sueldo, ¿qué tácticas del libro me recomendarías y cómo formularía la primera frase?'. Claude carga los patterns del libro y te arma un guión personalizado.

08 · los cuatro anti-patrones honestos

Cuándo NO te conviene convertir un libro en skill

No todo libro merece una skill. Hay cuatro situaciones donde te va a salir más caro (en tiempo o en budget) que el beneficio. Mejor saberlo antes de gastar la noche convirtiendo veinte PDFs.

1 · PDF escaneado · sin texto extraíble

Si tu PDF es un escaneo de páginas (foto de cada hoja, no texto), book-to-skill no lo va a poder leer · no tiene OCR adentro. Probá abriéndolo · si podés seleccionar y copiar texto, andá adelante; si no, primero pasalo por OCR (Tesseract gratis, Adobe Acrobat pago, o un servicio en la nube) y después corré book-to-skill sobre el PDF resultante.

2 · Libro que vas a tocar una sola vez

Si es un libro que vas a consultar una sola vez (un artículo, un PDF puntual de una clase, un manual de un proceso que vas a hacer y olvidar), no vale el overhead de instalarlo como skill. Para esos casos, abrís un chat suelto, pegás el contenido y listo · cuando cierres el chat, se borra solo. Las skills son para lo que vas a usar muchas veces.

3 · Contenido confidencial · sensible · regulado

Importante · book-to-skill deja la skill en `~/.claude/skills/<slug>/` en tu disco local, sin encripción, en archivos markdown legibles. Si el contenido es confidencial (información de clientes, datos legales, secretos comerciales, registros médicos), evaluá antes si tu disco está cifrado, si tu equipo tiene acceso al folder y si tu política de seguridad permite tener ese contenido en disco. La skill no se sincroniza a la nube por su cuenta, pero si tenés Dropbox/iCloud/Drive apuntando a tu home, se va a sincronizar.

4 · Libros gigantes · más de 500 páginas

Aunque los capítulos cargan on-demand, el SKILL.md mete el índice y los mental models de todo el libro · y si el libro es enorme, ese SKILL.md crece y muerde budget cada vez que mencionás el tema. Para libros muy largos, conviene dividir el contenido en dos o tres skills más chicas por sección (ej: 'libro-parte-1-fundamentos' y 'libro-parte-2-avanzado') en vez de meter todo en una sola.

Para quién no aplica esta página

Si usás solo Claude.ai web (Free o Pro sin Claude Code), esta guía no te aplica directo · las skills viven en `~/.claude/skills/` que es del CLI. Podés instalar la skill manualmente y consultarla desde Claude Cowork si tenés acceso a `/skills`, pero el flujo natural es con Claude Code.

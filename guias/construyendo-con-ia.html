01 intro

Arranque para personas sin código

llegaste al punto más importante: empezar. este proyecto no busca convertirte en ingeniero en una tarde, busca que construyas algo real y lo pongas en internet hoy mismo.

no necesitas experiencia técnica previa. necesitas una laptop, ganas de experimentar y claridad para describir lo que quieres crear.

Qué es este proyecto

un workshop práctico para construir con Codex. tú describes una idea en lenguaje natural y la IA te ayuda a implementarla en una app real.

Resultado esperado hoy

  • una app funcional en internet
  • un link público listo para compartir
  • un sistema repetible para crear más productos

Filosofía de trabajo

  • aprender construyendo, no acumulando teoría
  • avanzar rápido, publicar rápido, iterar con feedback real
  • terminar algo hoy vale más que planear perfecto una semana

Lo único que sí necesitas saber

  • usar tu compu (abrir apps, carpetas, copiar y pegar)
  • escribir comandos básicos en terminal (te guiamos abajo)
  • describir con claridad lo que quieres que la app haga

02 instalación

Instalación completa de construyeconia

la instalación está pensada para ser de una sola línea. ejecutas un script según tu sistema operativo y el entorno queda listo: dependencias, proyecto local, servidor y Codex.

Paso 1: abre terminal

macOS

presiona command + space, escribeterminal y ábrelo.

Windows

busca PowerShell, clic derecho y ejecuta como administrador.

Linux

usa Ctrl + Alt + T o buscaTerminal en aplicaciones.

Paso 2: ejecuta el script de instalación

macOS

bash <(curl -fsSL https://raw.githubusercontent.com/Hainrixz/construyeconia/main/scripts/setup-mac.sh)
Copiar comando

Windows (PowerShell)

irm https://raw.githubusercontent.com/Hainrixz/construyeconia/main/scripts/setup-windows.ps1 | iex
Copiar comando

Ubuntu / Debian

bash <(curl -fsSL https://raw.githubusercontent.com/Hainrixz/construyeconia/main/scripts/setup-ubuntu.sh)
Copiar comando

Importante: te pedirá contraseña de administrador

durante la instalación, el sistema puede pedir tu contraseña para autorizar instalación de dependencias y herramientas del entorno. esto es normal y necesario para que el proyecto funcione correctamente.

  • en macOS/Linux, al escribir la contraseña en terminal no se ven caracteres: escribe y presiona Enter.
  • en Windows, puede aparecer confirmación de permisos (UAC) o ejecución como administrador.
  • solo introduce contraseña si ejecutaste tú mismo el comando desde esta guía.

Qué hace el script por detrás

  • instala herramientas base (gestor de paquetes, Node.js, git y CLI de Codex)
  • clona el repo Hainrixz/construyeconia
  • instala dependencias del proyecto
  • levanta el servidor local y abre localhost:3000
  • inicia Codex para que arranques el flujo guiado

Mini crash course de terminal (opcional)

pwd

muestra en qué carpeta estás.

ls

lista archivos y carpetas del lugar actual.

cd carpeta

entra a una carpeta específica.

cd ..

sube un nivel en el árbol de carpetas.

al terminar setup, no tienes que configurar nada manual: Codex queda abierto y listo para el primer build.

03 primer build

Primer build guiado con Codex

cuando Codex abra, inicia con$start. ese skill arranca el flujo interactivo para definir idea, construir versión inicial e iterar.

Comandos que vas a usar

$start

inicia el curso/build guiado.

codex

si Codex se cerró, lo vuelves a abrir.

$imlost

te reencamina cuando no sabes qué pedir.

$fixit

diagnostica y corrige errores frecuentes.

El ciclo de construcción

  1. describe claramente lo que quieres construir
  2. mira el resultado en el navegador
  3. detecta qué falta o qué quieres cambiar
  4. pide ese cambio exacto a Codex
  5. repite hasta tener una versión que sí quieras mostrar

Ideas simples que sí funcionan

  • to-do list por categorías
  • journal o mood tracker
  • generador de frases o tarjetas
  • landing personal
  • contador/cuenta regresiva para un objetivo

Ejemplos de prompts buenos

"crea una app de tareas donde pueda agregar, marcar y eliminar tareas. separa por categorías y usa una interfaz minimal con fondo claro."
"haz una app de journal donde pueda escribir entradas diarias, etiquetarlas por estado de ánimo y verlas por calendario."
"quiero un generador de frases con botón de nueva frase, tipografía elegante y layout centrado."

Reglas rápidas para avanzar más rápido

  • si algo falla, no te detengas: usa $fixit
  • evita pedir "hazlo mejor"; pide cambios concretos y visibles
  • si te gusta un diseño externo, descríbelo y úsalo de referencia
  • la primera versión rara vez sale perfecta: iterar es parte del método

04 publicar

Publicar, reclamar dominio y compartir

cuando la app ya resuelve algo útil, toca publicar. ejecuta$deploydesde Codex y se genera una URL pública en Vercel.

Qué pasa después de $deploy

  • recibes una URL tipo tu-app.vercel.app
  • la URL queda activa de inmediato para pruebas y feedback
  • si haces cambios, vuelves a correr $deploy y se actualiza

Sobre el link de 24 horas

por defecto, el enlace inicial puede expirar en ~24 horas si no lo reclamas. para mantenerlo permanente, crea una cuenta gratis en Vercel desde el enlace que entrega el flujo de deploy.

Checklist de ship

  • probar flujo principal localmente antes de publicar
  • ejecutar $deploy y abrir la URL
  • reclamar el dominio en Vercel si quieres permanencia
  • compartir el link con al menos 3 personas y recoger feedback

Después de publicar

este es el cambio de juego: ya no es "un proyecto en tu máquina", es un producto vivo. vuelve a Codex, agrega mejoras y republica. cada versión te da más claridad sobre qué construir después.

05 bonus

Ir más allá del primer lanzamiento

si ya publicaste una primera versión, estás listo para subir nivel. el siguiente tramo consiste en sumar capacidades sin perder simplicidad.

Mejorar UX

pulir textos, jerarquía visual, navegación y claridad de acciones.

Agregar features

sumar capacidades como datos persistentes, paneles o flujos nuevos.

Nuevo proyecto

repetir el sistema completo con otra idea y menos fricción.

Temas de nivel intermedio para explorar

  • persistencia de datos (bases de datos) para guardar información real
  • integraciones con APIs para consumir datos de terceros
  • funciones colaborativas o multiusuario
  • automatización del flujo con más skills y prompts reutilizables

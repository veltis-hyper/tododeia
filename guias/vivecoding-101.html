Paso 1: crea tu PRD (no te lo saltes)

antes de tocar cualquier herramienta, define un PRD (documento de requerimientos de producto). ese documento separa una app funcional de una app que se ve hecha en 20 minutos.

  • qué problema resuelves y para quién.
  • qué debe hacer sí o sí tu v1 (must-have).
  • qué queda fuera para no sobrecargar el primer build.
  • cómo vas a medir que el producto realmente funciona.

Contexto de mi app:
- Nombre del proyecto: {{NOMBRE_PROYECTO}}
- Problema que resuelve: {{PROBLEMA}}
- Usuario ideal: {{USUARIO_OBJETIVO}}
- Resultado esperado por el usuario: {{RESULTADO_ESPERADO}}
- Plataformas objetivo: {{WEB_IOS_ANDROID}}
- Funciones obligatorias (must-have): {{MUST_HAVE}}
- Funciones opcionales (nice-to-have): {{NICE_TO_HAVE}}
- Restricciones o reglas del negocio: {{RESTRICCIONES}}
- Monetización (si aplica): {{MONETIZACION}}

Necesito que el PRD incluya exactamente:
1. Resumen ejecutivo (1 párrafo)
2. Problema y oportunidad
3. Perfil de usuario (ICP)
4. Objetivos del producto
5. Alcance de la v1 (in scope / out of scope)
6. Requisitos funcionales (en bullets claros)
7. Requisitos no funcionales (performance, seguridad, UX)
8. Arquitectura sugerida (frontend, backend, base de datos, IA si aplica)
9. User stories (formato: Como [tipo de usuario], quiero [acción], para [beneficio])
10. Criterios de aceptación por cada feature crítica
11. Métricas de éxito (KPIs)
12. Riesgos y supuestos
13. Plan de ejecución en fases (MVP -> v1 -> v2)

Entrega final:
- Usa markdown
- Escribe concreto, sin relleno
- Incluye checklist accionable al final
- Si falta información, haz supuestos explícitos antes de redactar

Checklist: de idea a app publicada

  1. escribe tu idea y público objetivo en una sola frase clara.
  2. genera PRD con el prompt de esta guía y revísalo.
  3. elige herramienta según nivel (no-code o más control).
  4. conecta backend (Supabase/Firebase) y define autenticación/datos.
  5. si usas IA con memoria semántica, agrega Pinecone.
  6. cierra MVP funcional y valida flujo principal extremo a extremo.
  7. publica en web (Vercel) y luego evalúa App Store/Play Store.
tip: comparte este recurso en comentarios como resumen guardable. así quien vea el video tiene todos los nombres y links en un solo lugar.

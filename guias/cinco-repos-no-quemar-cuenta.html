5 Repos Para No Quemar Tu Cuenta de Claude

Todos los que usamos Claude Code estamos quemando hasta el 80% de lo que pagamos sin darnos cuenta — respuestas larguísimas, archivos enteros que se cargan cada vez, contexto que no para de crecer. Estos 5 repos gratis de GitHub lo arreglan. Te los explico como si tuvieras cinco años — pero sirven aunque seas experto.

Lo que tienes que saber

Cada repo ataca un problema distinto. Algunos son un archivo que arrastras, otros un plugin, otros un filtro que se pone entre tu terminal y Claude. Todos suman — y son gratis.

el problema

Estás quemando el 80% de lo que pagas

Claude Code es increíble. Pero Claude no sabe que tus tokens cuestan. Cada vez que le preguntas algo, te responde como si estuviera escribiendo una novela: explicación detallada, opciones alternativas, preguntas de seguimiento, ejemplos de código que ya tenías. Todo eso se convierte en tokens de salida.

Y no para ahí. Cada vez que abres un archivo, Claude lo lee completo. Si tu proyecto tiene 500 archivos y necesitas tocar 3, lee los 500 — por si acaso. Cada comando que corre en terminal (ls, git status, npm install) le escupe a Claude 200 líneas que no necesitaba ver.

Resultado: tu sesión dura 20 minutos en vez de dos horas. Y si estás en plan Pro, ya sentiste el “has alcanzado tu límite” antes de tiempo.

Lo bueno

La comunidad ya resolvió esto. Son 5 repos open-source, todos gratis, y atacan cada punto del problema desde ángulos distintos. Puedes instalar uno, los cinco, o empezar por el más fácil — son literalmente cinco minutos.

Claude Token Efficient — el archivo mágico

Es el más fácil de los 5. Imagínate que tienes un perro que ladra de más. Si le pones un letrero en la puerta que dice “no ladres”, el perro lo lee y deja de ladrar. Eso es Claude Token Efficient — pero el letrero se llama CLAUDE.md.

Cuando Claude abre tu proyecto, lo primero que hace es buscar un archivo CLAUDE.md — y si lo encuentra, lo lee como si fueran sus instrucciones. Este repo te regala uno ya hecho que le dice a Claude: “habla corto, no me expliques lo que ya sé, dame el código y listo”.

Lo arrastras a la raíz de tu proyecto y se acabó. El autor midió respuestas 63% más cortas — sin perder información útil.

repo 2 · 39,330 ⭐

Caveman — habla como cavernícola

39 mil estrellas. No es broma. Caveman es un plugin que le pone un filtro a Claude. En vez de decirte “Would you like me to explain this step-by-step?”, te dice “Aquí está. Sigue.”.

Imagínalo como subtítulos resumidos. Claude sigue pensando igual de profundo por dentro, pero afuera te habla en frases cortas — solo las palabras que necesitas. Mismo mensaje, mitad de palabras. Y no pierde detalle técnico: si necesitas el código, el código sigue ahí.

El resultado: 65% menos tokens por cada respuesta.

repo 3 · 8,107 ⭐

Context Mode — el aplastador

¿Sabes cuando Claude empieza a repetir cosas que ya te dijo? Eso es porque el contexto se infló. Cada archivo, cada mensaje, cada comando — todo se apila. En sesiones largas, el 70% del contexto ya es basura.

Context Mode lee todo lo que se acumuló y lo comprime al 98%. Imagínate que Claude leyó un libro de 500 páginas y Context Mode lo resume en 10 frases — las 10 que importan. Claude sigue teniendo la memoria, solo sin el peso.

Efecto concreto: tu sesión dura 6 veces más antes de que te pegue el límite. Si antes te alcanzaba para 30 minutos, ahora son 3 horas.

RTK — el portero de tu terminal

Si vives en la terminal, este es el tuyo. Cada vez que Claude corre ls, git status, npm install, le rebota un muro de texto — a veces 200 líneas donde solo importaban 3. Todo ese muro entra a Claude como tokens.

RTK se pone entre tu terminal y Claude como un portero de antro. Agarra la basura, la tira, y solo le pasa a Claude lo que vale la pena ver: el error, el número de archivos que cambiaron, la línea que falló.

Medido en sesiones reales: 80% menos tokens en media hora. Sin que tú toques nada.

Code Review Graph — el que aprende tu proyecto

La cereza del pastel. Este es el más avanzado y el que más impacto tiene en proyectos grandes.

Funciona así: cuando lo instalas, escanea todo tu proyecto y arma un mapa — qué archivo llama a cuál, qué componente depende de qué servicio, qué función afecta a qué ruta. Imagínate un mapa del metro, pero de tu código.

Cuando le pides un cambio a Claude, ya no lee los 500 archivos “por si acaso”. Mira el mapa, encuentra los 3 que de verdad importan, y solo lee esos. El trabajo sale igual de bien — con una fracción del contexto.

En promedio, 6.8 veces menos tokens. En tareas grandes (refactor, feature nueva, debug complicado), hasta 49 veces menos.

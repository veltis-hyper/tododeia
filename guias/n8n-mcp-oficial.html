la promesa · de un vistazo

Describir en español, obtener un workflow que corre

La idea es simple y, esta vez, real: en lugar de abrir n8n y arrastrar nodos uno por uno, le describes a Claude la automatización que quieres, y él te devuelve el workflow listo para importar. El camino completo son cinco pasos:

  1. 1. Describes la automatización en lenguaje natural.
  2. 2. Claude genera el JSON del workflow con los nombres reales de los nodos.
  3. 3. Lo importas en n8n (o Claude lo despliega por API).
  4. 4. Conectas las credenciales a mano (este paso es tuyo, no de Claude).
  5. 5. Corres una prueba y, si pasa, lo activas.

Detrás de esa promesa hay dos capas reales y oficiales, no un truco. La primera es el MCP que n8n trae de fábrica. La segunda es un servidor de comunidad ya listado en el registro oficial de MCP de Anthropic, que le da a Claude conocimiento profundo de los nodos de n8n. Las vemos por separado.

cómo funciona de verdad

Las dos capas, sin humo

Mucha gente mezcla estas dos cosas. Aquí van separadas, porque resuelven problemas distintos y a veces se usan juntas.

A

MCP nativo oficial de n8n

Qué es: n8n 2.x trae soporte MCP de fábrica, en todos los planes (incluido Community, que es gratis). Son dos nodos: el MCP Server Trigger hace que tu n8n actúe como servidor MCP y exponga tus workflows como herramientas para Claude y otros clientes; el MCP Client Tool hace lo contrario, deja que un workflow consuma un servidor MCP externo como un paso más.

Cuándo usarla: Úsalo cuando quieras que Claude (u otro cliente MCP) dispare o use tus propios workflows como herramientas, o cuando un workflow necesite llamar a otra herramienta MCP dentro de su lógica.

  • · MCP Server Trigger: tu n8n EXPONE workflows a Claude.
  • · MCP Client Tool: tu workflow CONSUME un MCP externo como paso.
  • · Es la conexión oficial de n8n, incluida sin costo extra.
B

n8n-mcp: el cerebro de nodos (en el registro de Anthropic)

Qué es: Un servidor MCP de la comunidad (de czlonkowski) que ya está en el registro oficial de MCP de Anthropic, con más de 21 mil estrellas en GitHub, licencia MIT y escrito en TypeScript. Le da a Claude conocimiento profundo de n8n: alrededor de 1,851 nodos (822 del core y 1,029 de comunidad) con sus esquemas, unos 2,352 templates de workflow con metadata, validación de nodos, y la capacidad de crear, desplegar y actualizar workflows en TU instancia vía la API de n8n.

Cuándo usarla: Úsalo cuando quieras que Claude GENERE workflows correctos por ti: él conoce los nombres y esquemas reales de los nodos, así que el JSON que produce sí se importa sin romperse. Es el cerebro que hace posible 'describir y obtener un workflow'.

  • · ~1,851 nodos con esquema · ~2,352 templates con metadata.
  • · Valida nodos y puede desplegar a tu instancia por API.
  • · Modo solo-documentación: conocimiento de nodos sin instancia.

En corto: la capa nativa (A) sirve para que Claude use tus workflows o para que un workflow llame a otra herramienta MCP. La capa n8n-mcp (B) es la que hace que Claude genere workflows correctos. Para “describir y obtener una automatización”, la estrella es la B. La mayoría de esta guía gira alrededor de ella.

conectar Claude a n8n

Setup prompt-first: deja que Claude Code lo configure

No vas a pelear con la terminal. El setup se hace de la forma más cómoda: le pegas a Claude Code un prompt, él te pregunta tus dos datos y deja la configuración lista. Los dos datos son:

  • N8N_API_URL — la dirección de tu instancia. Si usas cloud, es tu URL de n8n.io; si autohospedas (Community Edition, gratis), suele ser algo como http://localhost:5678.
  • N8N_API_KEY — la llave que generas en n8n, en Settings > n8n API > Create an API key. Es un secreto: que no termine en git.

¿No tienes instancia todavía? No pasa nada: dile a Claude que lo configure en modo solo-documentación (sin esas dos variables). Igual conocerá los ~1,851 nodos y podrá generarte el JSON; lo único que no podrá es desplegar ni validar contra tu instancia hasta que la conectes.

de idea a automatización

El flujo completo, con el caveat honesto

Así se ve el camino de punta a punta. Cuatro de los cinco pasos los hace Claude o un clic; el cuarto, el de las credenciales, es tuyo, y es justo donde la gente tropieza. Por eso lo marcamos en grande.

1

Describes la automatización

En lenguaje natural, le cuentas a Claude qué quieres que pase y qué la dispara. Sin sintaxis, sin nodos: como se lo explicarías a un compañero.

2

Claude genera el JSON del workflow

Con n8n-mcp como cerebro, Claude usa los nombres REALES de los nodos y arma un JSON de workflow correcto, con sus disparadores, pasos y conexiones.

3

Lo importas en n8n

En el canvas de n8n, importas desde archivo o pegando desde el portapapeles. Si tienes la API conectada, Claude puede desplegarlo directo, sin que toques nada.

4

Conectas las credenciales (a mano)

Este paso es manual y no lo evita nadie: al importar, n8n NO trae tus credenciales. Claude las referencia por nombre, pero tú las conectas en cada nodo. Es, de lejos, la causa más común de que un import no funcione a la primera.

5

Corres una prueba y activas

Disparas una ejecución de prueba para ver que todo corre bien de punta a punta. Si algo falla, vuelves a Claude con el error. Cuando pasa, activas el workflow.

Para importar en n8n: abre el canvas, usa la opción de importar desde archivo o pega el JSON desde el portapapeles, y listo. Si conectaste tu instancia por API, ni siquiera tienes que hacer eso: le pides a Claude que lo despliegue directo y aparece en tu lista de workflows.

Eres un ingeniero profesional de automatización especializado en n8n. Tu trabajo es convertir lo que el usuario describe en lenguaje natural en workflows de n8n correctos, válidos e importables. REGLAS QUE NUNCA ROMPES:

1. Nombres de nodos reales. Nunca inventes un nodo. Antes de usar cualquier nodo, búscalo en el MCP y usa su nombre y su tipo exactos. Si dudas entre un nodo nativo y uno de comunidad para lo mismo, prefiere el nativo y dilo.

2. Pregunta antes de construir. Antes de generar JSON, asegúrate de tener claro: (a) qué dispara el flujo (correo, webhook, horario, formulario, etc.), (b) los pasos y las decisiones, (c) dónde termina, (d) qué servicios externos conecta. Si falta algo, haz preguntas concretas. No asumas.

3. JSON importable y válido. Entrega siempre el workflow como JSON completo, con nodos, conexiones y posiciones razonables en el canvas. Nada de placeholders ni "aquí iría tu nodo". Si el usuario tiene instancia conectada, ofrece desplegarlo por API; si no, dale instrucciones para importarlo (canvas > importar desde archivo o portapapeles).

4. Valida antes de entregar. Pasa el workflow por la validación del MCP. Si un nodo, parámetro o conexión está mal, corrígelo antes de mostrarlo. Si algo no se puede validar, dilo en claro en vez de fingir que está bien.

5. Marca SIEMPRE el paso de credenciales. Tú no puedes meter las credenciales del usuario; n8n no las trae al importar un workflow. Por eso, al final de cada entrega incluye una sección titulada "CREDENCIALES QUE DEBES CONECTAR A MANO" donde listes, por cada nodo que las necesite, el tipo de credencial y dónde se conecta en n8n. Recuérdale que esta es la causa número uno de fallos al importar.

6. Manejo de errores por defecto. En todo workflow que llame servicios externos, incluye una rama o nodo de error que avise al usuario si algo se cae, en vez de dejar el flujo muerto en silencio. Si el usuario no quiere, que lo diga; por defecto, lo pones.

7. Parte de templates cuando existan. Antes de construir desde cero, revisa si el MCP tiene un template oficial parecido y úsalo como base; ahorra tiempo y evita errores.

8. Habla en español plano. El usuario puede no programar. Explica cada flujo en palabras simples, paso por paso, antes de mostrar JSON. Nunca lo abrumes con jerga sin traducirla.

9. Seguridad. Nunca pidas, muestres ni pegues secretos (API keys, tokens, contraseñas) en el JSON ni en el chat. Refiérete a las credenciales por su nombre, no por su valor.

FORMATO DE TU RESPUESTA, en este orden:
1. Resumen en español del workflow (qué hace, paso a paso, con los nombres reales de los nodos).
2. El JSON completo e importable.
3. CREDENCIALES QUE DEBES CONECTAR A MANO (lista por nodo).
4. Cómo importarlo o desplegarlo, y cómo correr una ejecución de prueba antes de activarlo.
5. Qué podría fallar en la primera corrida y cómo prevenirlo.

Si en algún momento te piden algo que el MCP no soporta o que requiere una instancia que no está conectada, dilo con honestidad y propón la alternativa.

Buenas prácticas y caveats

Antes de soltar tus workflows al mundo, interioriza estas cinco. La primera es la que más dolores de cabeza evita.

Las credenciales son siempre manuales

Claude las nombra, pero tú las conectas en n8n. Es la causa número uno de fallos al importar. Da por hecho que después de cada import te toca abrir cada nodo con credenciales y volverlas a asignar.

Valida antes de correr

Pídele a Claude que pase el workflow por la validación del MCP antes de importarlo. Atrapa nodos inexistentes, parámetros mal puestos y conexiones rotas antes de que te exploten en producción.

Parte de templates

n8n-mcp conoce miles de templates oficiales. Pedirle a Claude que parta de uno parecido ahorra tiempo y reduce errores frente a construir desde cero.

Versiona tus workflows

Exporta el JSON de tus workflows y guárdalo en git (o donde sea). Si una edición rompe algo, vuelves a la versión que funcionaba sin rehacerlo a mano.

Nunca pegues secretos

No metas API keys, tokens ni contraseñas en el JSON ni en el chat. Las credenciales viven en n8n y se referencian por nombre. Si Claude te pide un secreto en texto, recuérdaselo.

dudas frecuentes

Preguntas que todos hacen

¿Esto es oficial o es un truco de la comunidad?+

Las dos cosas, y ambas legítimas. La capa nativa (MCP Server Trigger y MCP Client Tool) es la conexión MCP oficial que n8n trae de fábrica en la versión 2.x, en todos los planes. La capa del 'cerebro' (n8n-mcp) es un servidor de comunidad, pero ya está listado en el registro oficial de MCP de Anthropic, así que no es un experimento suelto: pasó por la validación de Anthropic.

¿Es gratis?+

Sí, puedes hacerlo todo sin pagar. n8n tiene Community Edition gratis para autohospedar. El servidor n8n-mcp es de licencia MIT (gratis y abierto). Lo único que cuesta es, si lo eliges, la versión cloud de n8n (n8n.io) en lugar de autohospedar, y tu plan de Claude.

¿Cloud o self-host?+

Cloud (n8n.io) es lo más rápido para arrancar: no instalas nada y obtienes una URL lista para tu N8N_API_URL. Self-host (Community Edition) es gratis y te da control total, pero tú mantienes el servidor. Para automatizar con Claude, cualquiera de las dos sirve: lo que importa es tener tu URL y tu API key.

¿Claude.ai, Claude Code o Claude Desktop?+

n8n-mcp se conecta a Claude Desktop, Claude Code (con claude mcp add o un .mcp.json), Cursor y Windsurf. Para crear y desplegar workflows desde tu proyecto, Claude Code es lo más cómodo porque vive en tu carpeta. El system prompt de esta guía también lo puedes pegar como instrucciones de un Proyecto de Claude en claude.ai.

¿Por qué tengo que conectar credenciales a mano si Claude hace todo lo demás?+

Por seguridad y por cómo funciona n8n: tus credenciales (las llaves de tu Gmail, tu Slack, etc.) viven dentro de tu instancia de n8n y no salen de ahí. Cuando importas un workflow, viene la estructura pero no las llaves. Claude referencia cada credencial por su nombre, pero conectarla es un paso tuyo, en n8n. Es la causa más común de que un import 'no funcione' a la primera.

¿Puedo usar n8n-mcp sin tener una instancia de n8n todavía?+

Sí. En modo solo-documentación (sin N8N_API_URL ni N8N_API_KEY), Claude igual tiene el conocimiento de los ~1,851 nodos y puede generarte el JSON. Lo único que no podrá es desplegar o validar contra tu instancia hasta que la conectes.

antes de activar

Checklist final

Si puedes marcar las diez, tienes una automatización lista para producción, no un demo que se cae al primer correo real.

  • Tengo una instancia de n8n (cloud o self-host) o decidí empezar en modo solo-documentación.
  • Generé mi N8N_API_KEY en n8n (Settings > n8n API) y tengo a mano mi N8N_API_URL.
  • Conecté el servidor n8n-mcp a Claude (Code, Desktop o como Proyecto) con el prompt de setup.
  • Confirmé que mi API key NO quedó en un archivo que se suba a git.
  • Le describí mi automatización a Claude y obtuve un JSON de workflow.
  • Le pedí a Claude que validara el workflow con el MCP antes de importarlo.
  • Importé el workflow en n8n (o Claude lo desplegó por API).
  • Conecté a mano las credenciales en cada nodo que las pedía.
  • Corrí una ejecución de prueba de punta a punta y revisé el resultado.
  • Activé el workflow solo después de que la prueba pasó.

Cierre de la guía

La parte difícil de n8n nunca fue la lógica, era arrastrar nodos y adivinar nombres. Con el MCP, esa parte se la quitas a Claude: tú describes, él arma, tú conectas las credenciales y activas. Empieza por una automatización pequeña de tu día a día, valida antes de importar y ve sumando flujos. Esta guía vive en la bóveda de tododeia.

    Este apéndice es tu diccionario de settings. Aquí encontrarás TODOS los ajustes que
    puedes cambiar en Claude Code, organizados por categoría. Cada setting tiene su tipo,
    su valor por defecto y dónde puedes usarlo. Úsalo como referencia rápida cuando
    necesites configurar algo específico.




Cómo Funciona la Configuración

Claude Code guarda sus ajustes en archivos JSON. Piensa en estos archivos como capas de ropa. Cada
capa puede agregar o cambiar algo. Las capas de arriba tienen más poder que las de abajo.

El orden de poder (de más fuerte a más débil) es:

  1. Managed Settings — Las reglas del jefe. Nadie puede cambiarlas. Son políticas de empresa.
  2. Argumentos de línea de comandos — Flags como --model sonnet . Solo duran esa sesión.
  3. Settings locales del proyecto — El archivo .claude/settings.local.json . Tus preferencias
    personales para este proyecto.
  4. Settings compartidos del proyecto — El archivo .claude/settings.json . Los comparte todo
    el equipo.
  5. Settings de usuario — El archivo ~/.claude/settings.json . Tus preferencias globales.

Dato clave: Los settings que son listas (arrays) se fusionan entre niveles. No se reemplazan. Si agregas
un permiso en el nivel de usuario y otro en el de proyecto, Claude Code usa ambos.

Archivos de Configuración
Estos son todos los archivos donde Claude Code busca configuración:

   • ~/.claude/settings.json — Tus settings globales. Aplican a todos tus proyectos.
   • .claude/settings.json — Settings del proyecto. Se commitean al repo. Todo el equipo los ve.
   • .claude/settings.local.json — Tus overrides personales para este proyecto. Están en
     .gitignore .

   • managed-settings.json — Políticas enterprise. Ubicación según SO: macOS en /Library/
    Application Support/ClaudeCode/ , Linux en /etc/claude-code/ , Windows en C:
    \Program Files\ClaudeCode\ .

   • managed-settings.d/*.json — Directorio drop-in para fragmentos de política. Se fusionan
    alfabéticamente con el archivo base. Archivos ocultos (con punto) se ignoran. Usa prefijos
    numéricos (10-telemetry.json, 20-security.json) para controlar el orden.

   • ~/.claude.json — Preferencias, OAuth, servidores MCP, caches.
   • .mcp.json — Servidores MCP del proyecto.

Ver Tus Settings Activos
Para ver qué settings están activos y de dónde vienen, usa estos comandos dentro de Claude Code:

   • /status — Muestra cada capa de configuración con su origen.
   • /config — Abre una interfaz con pestañas para ver y modificar settings.

Sintaxis de Reglas de Permisos
Las reglas de permisos usan patrones. Aquí tienes los más comunes:

   • Bash o Bash(*) — Coincide con todos los comandos Bash.
   • Bash(npm run *) — Coincide con comandos que empiezan con npm run . El * es un comodín.
   • Read(./.env) — Controla lectura de archivos. Sigue la sintaxis de gitignore.
   • Edit(/docs/**) — Controla edición de archivos. ** coincide recursivamente.
   • WebFetch(domain:example.com) — Controla solicitudes web a un dominio.
   • mcp__servidor__herramienta — Controla herramientas MCP específicas.
   • Agent(nombre) — Controla qué subagentes puede usar Claude.
   • Write(ruta) — Controla escritura de archivos nuevos. Sigue la misma sintaxis de rutas que
    Edit.
   • NotebookEdit(ruta) — Controla edición de notebooks Jupyter.
   • Task(nombre) — Controla qué tareas en background puede crear Claude.
   • Skill(nombre) — Controla qué skills puede ejecutar Claude.
   • MCP(servidor:herramienta) — Controla herramientas MCP. Alternativa a
    mcp__servidor__herramienta .

Prefijos de ruta para Read/Edit:

   • //ruta — Ruta absoluta desde la raíz del sistema.
   • ~/ruta — Relativa a tu home.
   • /ruta — Relativa a la raíz del proyecto.
   • ./ruta — Relativa al directorio actual.

    Resumen

    Claude Code usa un sistema de configuración por capas donde los managed settings tienen
    máxima prioridad y los de usuario la mínima. Hay más de 100 settings y 60 variables de entorno
    organizados en categorías: modelo, permisos, sandbox, hooks, MCP, channels, worktree, skills, UI
    y más. Los arrays se fusionan entre niveles (no se reemplazan) y las reglas deny siempre ganan.
    Los settings de ~/.claude.json (interfaz local) no deben mezclarse con settings.json.

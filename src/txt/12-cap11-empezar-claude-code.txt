¿Qué es Claude Code?

Imagina que tienes un compañero programador sentado a tu lado. Le dices "arregla este bug" y él lo
arregla. Le dices "explícame esta función" y te la explica. Eso es Claude Code.

Claude Code es una herramienta de programación agentiva. Eso significa que no solo responde
preguntas. También puede actuar: leer tus archivos, editarlos, ejecutar comandos en la terminal y
trabajar con tus herramientas de desarrollo.

Funciona directo en tu terminal. No necesitas abrir un navegador ni copiar y pegar código. Tú escribes
lo que necesitas en lenguaje natural y Claude Code se encarga.

¿Dónde puedes usar Claude Code?
Claude Code funciona en varios lugares:

   • Terminal (CLI) — La forma principal. Abres tu terminal y escribes claude .
   • VS Code — Como extensión dentro del editor. Busca "Claude Code" en Extensions.
   • JetBrains — Plugin para IntelliJ IDEA, PyCharm, WebStorm y otros.
   • App de escritorio — Una aplicación para macOS y Windows. Sin terminal.
   • Navegador web — En claude.ai/code directamente desde tu navegador.
   • App iOS — Desde tu teléfono.

Todas estas "superficies" usan el mismo motor por debajo. Lo que configures en una, funciona en las
demás.

Superficies adicionales para integrar Claude Code en flujos automatizados o de equipo:

   • GitHub Actions — Ejecuta Claude Code dentro de tus workflows de CI. Útil para revisar PRs o
    automatizar tareas.
   • GitLab CI/CD — Equivalente para proyectos en GitLab.
   • Slack via @Claude — Mencionas a Claude en un canal y responde directamente.
   • Chrome — Extensión para debug de webapps. Claude inspecciona la página y te ayuda.

Requisitos del sistema

Antes de instalar, revisa que tu computadora cumpla con lo mínimo. Piensa en esto como los
ingredientes de una receta: si te falta uno, el plato no sale.

Sistemas operativos soportados
Claude Code funciona en estos sistemas:

   • macOS 13.0 o superior — Si tienes una Mac del 2017 en adelante, probablemente funciona.
    Revisa en el menú Apple → About This Mac.
   • Windows 10 (versión 1809+) o Windows Server 2019+ — La mayoría de computadoras Windows
    modernas sirven.
   • Linux — Ubuntu 20.04+, Debian 10+, Alpine Linux 3.19+.


Hardware y conexión
RAM mínima: 4 GB (8 GB recomendado para codebases grandes). Claude Code procesa cosas en la
nube, pero necesita algo de memoria local. Si tu servidor Linux tiene menos de 4 GB, la instalación
puede morir con el mensaje "Killed". Más adelante te mostramos cómo solucionarlo.

Internet: Obligatorio. Claude Code se conecta a los servidores de Anthropic para funcionar. Sin
internet, no arranca.

Ubicación: Debes estar en un país soportado por Anthropic. Si no lo estás, el instalador te devolverá
una página HTML en vez del script.


Shells compatibles
Un shell es el programa que interpreta tus comandos en la terminal. Es como el idioma que habla tu
terminal.

Claude Code entiende estos shells:

   • Bash — El más común en Linux.
   • Zsh — El predeterminado en macOS desde Catalina.
   • PowerShell — El shell moderno de Windows.
   • CMD — El clásico "Command Prompt" de Windows.

En Windows, Claude Code necesita además Git for Windows. Este incluye "Git Bash", que Claude Code
usa internamente para ejecutar comandos.

Notas por plataforma

Cada sistema operativo tiene sus detalles. Aquí van los más importantes.

macOS
macOS es la plataforma más sencilla para Claude Code. Pocas sorpresas.

   • El shell predeterminado es Zsh.
   • El binario está firmado por Anthropic y notarizado por Apple. Tu Mac lo reconoce como software
    confiable.
   • Las credenciales se guardan en el Keychain encriptado de macOS. Es el mismo lugar donde se
    guardan tus contraseñas de Wi-Fi.

Si después de instalar el comando claude no se encuentra, agrega la ruta al PATH:



   echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
   source ~/.zshrc




Linux
En la mayoría de distribuciones Linux (Ubuntu, Debian), la instalación funciona sin problemas.

Caso especial: Alpine Linux — Alpine usa musl en vez de glibc (dos formas diferentes de conectar
programas con el sistema operativo). Necesitas instalar dependencias extra:




                                                 212                                    @soyenriquerocha

   apk add libgcc libstdc++ ripgrep



Y en tu configuración, decirle a Claude Code que use el ripgrep del sistema:



   {"env": {"USE_BUILTIN_RIPGREP": "0"}}



Servidores con poca RAM: Si la instalación muere con "Killed", tu servidor no tiene suficiente
memoria. Agrega swap (memoria virtual en disco):



   sudo fallocate -l 2G /swapfile
   sudo chmod 600 /swapfile
   sudo mkswap /swapfile
   sudo swapon /swapfile



Luego vuelve a intentar la instalación.

Si claude no se encuentra tras instalar:



   echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
   source ~/.bashrc




Windows nativo
Windows funciona bien, pero tiene un requisito extra: Git for Windows.

¿Por qué? Claude Code usa Git Bash internamente para ejecutar comandos. Sin él, no arranca.
Descárgalo gratis en git-scm.com/downloads/win .

Si Claude Code no encuentra Git Bash automáticamente, indícale la ruta en tu archivo de
configuración settings.json :

   {
        "env": {
            "CLAUDE_CODE_GIT_BASH_PATH": "C:\\Program Files\\Git\\bin\\bash.exe"
        }
   }



No necesitas ejecutar PowerShell como Administrador. La instalación funciona con permisos
normales de usuario.

Herramienta PowerShell nativa: Cuando tienes Git Bash instalado, Claude Code lo usa por defecto
para ejecutar comandos. Pero hay un rollout progresivo de la herramienta PowerShell nativa que
puedes activar (o desactivar) manualmente con la variable CLAUDE_CODE_USE_POWERSHELL_TOOL :



   # Forzar uso de PowerShell aunque tengas Git Bash
   CLAUDE_CODE_USE_POWERSHELL_TOOL=1


   # O forzar Git Bash explícitamente
   CLAUDE_CODE_USE_POWERSHELL_TOOL=0



Si no tienes Git Bash instalado, Claude Code usa PowerShell por defecto sin que tengas que setear
nada.

Si el comando claude no se reconoce, agrega la ruta al PATH de Windows:



   $currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
   [Environment]::SetEnvironmentVariable('PATH', "$currentPath;
   $env:USERPROFILE\.local\bin", 'User')



Después, cierra y abre la terminal.


Windows con WSL (Subsistema de Linux)
WSL (Windows Subsystem for Linux) te permite correr Linux dentro de Windows. Claude Code funciona
en WSL, pero con detalles importantes.

WSL 1 vs WSL 2:

   • WSL 1 funciona, pero no soporta sandboxing (una capa de seguridad que aísla lo que Claude
    Code puede hacer).
   • WSL 2 soporta sandboxing, pero necesitas instalar dos paquetes extra:

   sudo apt-get install bubblewrap socat



Problema común: el login no abre el navegador. WSL no siempre puede abrir el navegador de
Windows. Dos soluciones:

  1. Configura la variable BROWSER apuntando al Chrome de Windows:



   export BROWSER="/mnt/c/Program Files/Google/Chrome/Application/chrome.exe"



  1. O cuando Claude Code te pida login, presiona c para copiar la URL y pégala manualmente en tu
    navegador.

Consejo de rendimiento: Trabaja en /home/ (el filesystem de Linux), no en /mnt/c/ (el filesystem
de Windows). La diferencia de velocidad es enorme.


Docker
Si instalas Claude Code en un contenedor Docker, hay un truco importante. No instales desde el
directorio raíz / . El instalador escanea el directorio actual y puede colgarse.

En tu Dockerfile, haz esto:



   WORKDIR /tmp
   RUN curl -fsSL https://claude.ai/install.sh | bash



También es buena idea darle suficiente memoria al build:



   docker build --memory=4g .

Paso 2: Iniciar sesión
La primera vez que ejecutas claude , se abre tu navegador automáticamente. Ahí inicias sesión con

Si el navegador no se abre:

   • Presiona c para copiar la URL de login.
   • Pégala manualmente en tu navegador.

Para terminales remotas: Si estás por SSH, en una VM o en un contenedor donde el paste interactivo

   claude auth login



Lee el código de OAuth desde stdin en vez del prompt interactivo. Pegas el código, presionas Enter y
listo. Es la versión más amigable para terminales que se portan raro con el clipboard.

Tipos de cuenta soportados:

   • Claude Pro / Max — Login con tu cuenta de claude.ai
   • Teams / Enterprise — Login con la cuenta que tu admin te invitó
   • Console — Login con credenciales de Console. La primera vez se crea un workspace "Claude
    Code" automáticamente.
   • Bedrock / Vertex / Foundry — No usan login web. Se configuran con variables de entorno.

políticas estrictas. Esta sección cubre esos casos.

Tokens de larga duración para CI y scripts
El login OAuth normal abre un navegador. Eso no funciona en GitHub Actions, GitLab CI o un cron job.
Para esos casos, Claude Code tiene un subcomando que genera un token de larga duración (vale
aproximadamente un año):



   claude setup-token



El comando imprime el token en la terminal, pero no lo guarda en ningún lado. Tienes que copiarlo
tú mismo y meterlo donde lo necesites, generalmente como variable de entorno:



   export CLAUDE_CODE_OAUTH_TOKEN=cco_...



Para CI lo más común es guardarlo como secret del repositorio (en GitHub: Settings → Secrets) y
exponerlo en el workflow.

Requisitos importantes:

   • Solo funciona con planes Pro, Max, Teams o Enterprise. Las cuentas de Console no generan este
    tipo de token.
   • El scope es sólo de inferencia (ejecutar tareas con Claude). No incluye Remote Control.
   • No funciona en bare mode; para esos casos usa ANTHROPIC_API_KEY o apiKeyHelper .


Precedencia de autenticación (quién gana)
Claude Code puede recibir credenciales por varios caminos a la vez. Cuando hay más de uno, hay un
orden de prioridad fijo. De mayor a menor:

  1. Cloud providers — Si CLAUDE_CODE_USE_BEDROCK , CLAUDE_CODE_USE_VERTEX o
    CLAUDE_CODE_USE_FOUNDRY están activos, ganan sobre todo lo demás.

  2. ANTHROPIC_AUTH_TOKEN — Bearer token, típicamente para enrutar por un gateway LLM.
  3. ANTHROPIC_API_KEY — API key de Console, enviada como header X-Api-Key .
  4. apiKeyHelper — Script externo que retorna una API key (con refresh cada 5 minutos o en HTTP
    401).
  5. CLAUDE_CODE_OAUTH_TOKEN — Token de larga duración generado por claude setup-token .
  6. OAuth de suscripción — El login que haces con /login (Pro, Max, Teams, Enterprise). Es la
    opción por defecto si no hay nada más.

Atención muy común: Si tu suscripción Pro/Max deja de funcionar sin razón aparente, casi siempre la
causa es un ANTHROPIC_API_KEY exportado en tu shell que apunta a una organización desactivada.
El API key tiene precedencia y rompe el login OAuth. El típico mensaje es API Error: 400 — organization
has been disabled.

Para volver a la suscripción:



   unset ANTHROPIC_API_KEY



Y borra cualquier export ANTHROPIC_API_KEY=... de ~/.zshrc , ~/.bashrc o ~/.profile . En
Windows, revisa tu $PROFILE de PowerShell y las variables de usuario. Confirma con /status que
estás usando OAuth de nuevo.


Cloud providers (Bedrock, Vertex, Foundry)
Si tu empresa ya tiene crédito o contrato con AWS, Google Cloud o Microsoft Azure, puedes apuntar
Claude Code a esos proveedores en vez de Anthropic directamente. Cada uno se activa con su propia
env var:

   • Amazon Bedrock: CLAUDE_CODE_USE_BEDROCK=1 . Requiere credenciales AWS válidas (por aws
    configure , IAM role o variables como AWS_ACCESS_KEY_ID ).

   • Google Vertex AI: CLAUDE_CODE_USE_VERTEX=1 . Requiere ANTHROPIC_VERTEX_PROJECT_ID y
     CLOUD_ML_REGION . Autenticación con gcloud auth application-default login .

   • Microsoft Foundry: CLAUDE_CODE_USE_FOUNDRY=1 . Requiere ANTHROPIC_FOUNDRY_API_KEY o
    login previo con az login .

Como vimos en la precedencia, los cloud providers ganan sobre todas las demás formas de auth. Una
vez activos, ignoran cualquier OAuth o API key que tengas configurado.

Nota sobre Claude Code on the Web: El editor en navegador ( claude.ai/code ) siempre usa las
credenciales de tu suscripción. Aunque exportes ANTHROPIC_API_KEY o ANTHROPIC_AUTH_TOKEN
dentro del sandbox web, esas variables no sobreescriben al OAuth de tu cuenta. Es algo a tener en
cuenta si esperabas el mismo comportamiento que en la CLI.

Latest vs Stable
Latest (predeterminado) — Recibes las novedades apenas salen. Es el carril rápido. Puede incluir
algún bug nuevo de vez en cuando.

Stable — Recibes las actualizaciones con una semana de retraso. Si una versión tiene errores graves,
se la saltan. Es el carril seguro.

Para instalar directamente en el canal stable:



    curl -fsSL https://claude.ai/install.sh | bash -s stable



Para cambiar de canal después de instalar tienes dos caminos. Desde una sesión de Claude Code
abres /config y eliges "Auto-update channel". O editas directo tu settings.json con la setting
autoUpdatesChannel :



    {
        "autoUpdatesChannel": "stable"
    }



Los valores válidos son "latest" y "stable" . Cualquier flujo de auto-update y el subcomando
claude update respetan esta setting.

Si necesitas control total, puedes instalar una versión específica:



    curl -fsSL https://claude.ai/install.sh | bash -s 2.1.89



Y si quieres evitar que Claude Code baje a una versión más vieja al cambiar de canal (típico al pasar de
latest a stable), pon un piso con minimumVersion :



    {
        "autoUpdatesChannel": "stable",
        "minimumVersion": "2.1.100"
    }



Con esto el auto-update solo aplica releases iguales o más nuevas que 2.1.100 . Útil para evitar
downgrades accidentales.

Si necesitas actualizar manualmente en cualquier momento, ejecuta:



   claude update



Desactivar updates — dos niveles distintos:

   • DISABLE_AUTOUPDATER=1 apaga sólo el check automático en background. El subcomando
       claude update sigue funcionando si tú lo lanzas a mano.

   • DISABLE_UPDATES=1 bloquea todos los caminos de update, incluido el manual. Es la opción de
    entornos empresariales donde la versión está pinneada por política.

Para desactivar el auto-update (pero permitir manual), agrega en tu settings.json :



   {
        "env": {
            "DISABLE_AUTOUPDATER": "1"
        }
   }

package manager por ti cuando hay versión nueva, activa:



   CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE=1



(No aplica a apt, dnf o apk porque ésos necesitan privilegios elevados.)

Archivos de configuración importantes

Claude Code guarda su configuración en varios archivos. No necesitas tocarlos ahora, pero es bueno
saber dónde están.

   • ~/.claude/settings.json — Tu configuración personal. Permisos, hooks, preferencias.
   • .claude/settings.json — Configuración del proyecto. Se comparte con tu equipo vía Git.
   • .claude/settings.local.json — Configuración local del proyecto. NO se sube a Git.
   • ~/.claude.json — Estado global: tema visual, OAuth, servidores MCP.
   • CLAUDE.md — Instrucciones para Claude Code. Aquí pones estándares de código, decisiones
    arquitectónicas y reglas del proyecto.
   • .mcp.json — Servidores MCP del proyecto (herramientas externas).

Reubicar ~/.claude: En Linux y Windows, si necesitas que la configuración y las credenciales vivan en
otra carpeta (por ejemplo en un disco montado o en un volumen compartido del equipo), puedes
setear:



   export CLAUDE_CONFIG_DIR=/opt/claude-config



Claude Code usará esa ruta como base. El archivo .credentials.json también se mueve ahí. En
macOS esta variable no aplica porque las credenciales viven en el Keychain.

Errores comunes y cómo resolverlos

Aquí van los problemas más frecuentes durante la instalación y sus soluciones.

"command not found: claude"
Causa: El directorio de instalación no está en tu PATH. Tu terminal no sabe dónde buscar el comando
claude .

Solución para Zsh (macOS):



   echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
   source ~/.zshrc



Solución para Bash (Linux):



   echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
   source ~/.bashrc



Solución para Windows PowerShell:



   $currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
   [Environment]::SetEnvironmentVariable('PATH', "$currentPath;
   $env:USERPROFILE\.local\bin", 'User')



Cierra y abre tu terminal después.


"syntax error near unexpected token"
Causa: El script de instalación devolvió HTML en vez del script real. Esto pasa si estás en un país no
soportado o hay un problema de red.

Solución: Verifica que estás en un país soportado. Intenta un método alternativo como Homebrew o
WinGet. O espera unos minutos y reintenta.

                                                                          EMPEZAR CON CLAUDE CODE




"Killed" durante la instalación en Linux
Causa: Tu servidor no tiene suficiente memoria. El sistema operativo mató el proceso para protegerse.

Solución: Agrega 2 GB de swap (memoria virtual en disco):



   sudo fallocate -l 2G /swapfile
   sudo chmod 600 /swapfile
   sudo mkswap /swapfile
   sudo swapon /swapfile



Luego reintenta la instalación.


Errores de TLS o SSL
Causa: Certificados desactualizados, proxy corporativo o TLS 1.2 no habilitado.

Solución en Linux:



   sudo apt-get install ca-certificates



Solución en Windows PowerShell:



   [Net.ServicePointManager]::SecurityProtocol =
   [Net.SecurityProtocolType]::Tls12



Si hay proxy corporativo:



   export NODE_EXTRA_CA_CERTS=/ruta/al/certificado-corporativo.pem




"Claude Code on Windows requires git-bash"
Causa: No tienes Git for Windows instalado, o Claude Code no lo encuentra.

Solución: Instala Git for Windows desde git-scm.com/downloads/win . Si ya lo tienes, dile a Claude
Code dónde está:

EMPEZAR CON CLAUDE CODE




   {
       "env": {
           "CLAUDE_CODE_GIT_BASH_PATH": "C:\\Program Files\\Git\\bin\\bash.exe"
       }
   }




"OAuth error: Invalid code" o login fallido
Causa: El código de login expiró o se copió incompleto.

Solución: Presiona Enter para reintentar. Completa el login rápido. Si estás en SSH o WSL, presiona c
para copiar la URL completa y pégala en tu navegador local.


"Illegal instruction"
Causa: Tu CPU no soporta las instrucciones AVX que el binario necesita. Pasa con procesadores Intel/
AMD anteriores a 2013 (Sandy Bridge y más viejos) y con algunas máquinas virtuales que no exponen
AVX al guest.

Solución: No hay workaround. El binario requiere AVX y no existe build sin él. Necesitas correr Claude
Code en otra máquina o, si es una VM, habilitar AVX passthrough en el host.

Para verificar si tu CPU tiene AVX en Linux:



   grep -m1 -ow avx /proc/cpuinfo



Si no devuelve nada, no hay AVX disponible.


"Exec format error" en WSL
Causa: Estás en WSL 1, que tiene una regresión conocida con el binario nativo de Claude Code (issue
#38788). El loader de Linux dentro de WSL 1 no procesa bien el formato del ejecutable.

Solución: Migrar a WSL 2. Desde PowerShell:



   wsl --set-version <NombreDistro> 2



Reemplaza <NombreDistro> por el nombre de tu distro (por ejemplo Ubuntu-22.04 ). Lista las
distros con wsl --list --verbose .

WSL 2 además habilita el sandbox, así que ganas seguridad encima de arreglar el error.


"dyld" / "built for Mac OS X 13.0" (macOS viejo)
Causa: Tu macOS es anterior a 13.0 (Ventura). Claude Code requiere macOS 13 o superior. macOS 12
(Monterey) y anteriores no son compatibles.

Solución: Actualizar el sistema operativo desde System Settings → General → Software Update. Probar
otros métodos de instalación (Homebrew, npm) no resuelve nada porque todos descargan el mismo
binario.


"The process cannot access the file" en Windows
Causa: Una instalación previa todavía está corriendo, o tu antivirus está escaneando los binarios
descargados en %USERPROFILE%\.claude\downloads y bloquea el acceso.

Solución:

  1. Cierra cualquier ventana de PowerShell que haya quedado abierta con el installer.
  2. Espera unos segundos a que el antivirus termine de escanear.
  3. Borra la carpeta de descargas y vuelve a intentar:



   Remove-Item -Recurse -Force "$env:USERPROFILE\.claude\downloads"




"libstdc++.so.6" o "libgcc_s.so.1" no encontrado
Causa: Mismatch entre el binario y tu libc. Pasa en Alpine Linux (que usa musl) si no tienes las librerías
de compatibilidad.

Solución en Alpine:



   apk add libgcc libstdc++ ripgrep



Y en tu settings.json agrega:



   {"env": {"USE_BUILTIN_RIPGREP": "0"}}

"Could not find native binary package" (npm)
Causa: npm se instaló sin optional dependencies. El paquete @anthropic-ai/claude-code jala el
binario nativo a través de optional deps por plataforma, y si las desactivaste no llega.

Solución: Quita los flags --omit=optional , --no-optional o --ignore-optional de tu
comando o de tu .npmrc :



   npm install -g @anthropic-ai/claude-code



Si estás detrás de un mirror npm corporativo, asegúrate de que el mirror tenga los 8 paquetes por
plataforma ( @anthropic-ai/claude-code-darwin-arm64 , ...-linux-x64 , etc.).


"API Error: 400 organization has been disabled"
Causa: Tienes un ANTHROPIC_API_KEY exportado en tu shell que apunta a una organización de
Console desactivada. Por la regla de precedencia, el API key gana sobre tu OAuth de suscripción.

Solución:



   unset ANTHROPIC_API_KEY



Y borra cualquier export ANTHROPIC_API_KEY=... de ~/.zshrc , ~/.bashrc o ~/.profile . En
Windows, revisa tu $PROFILE de PowerShell y las variables de usuario en Settings. Reabre la terminal
y confirma con /status que ya usas OAuth.


"Does not support 32-bit Windows"
Causa: Abriste Windows PowerShell (x86) desde el menú Inicio, que corre como proceso de 32 bits
aunque tu sistema sea de 64 bits. Claude Code no tiene build para 32-bit Windows.

Solución: Abre Windows PowerShell (sin el sufijo (x86) ) o PowerShell 7. Verifica que estás en proceso
de 64 bits con:

   [Environment]::Is64BitProcess



Debería responder True .


"The token '&&' is not a valid statement separator"
Causa: Pegaste el comando de instalación de CMD dentro de PowerShell. PowerShell no usa &&
como separador de comandos, así que se queja apenas lo ve. Es un error de confusión de shell: dos
terminales distintas, dos comandos distintos.

Cómo saber en qué shell estás: En PowerShell, el prompt empieza con PS C:\ (la PS al inicio es la
pista). En CMD, el prompt es solo C:\ sin ese prefijo.

Solución: Como estás en PowerShell, usa el comando de PowerShell:



   irm https://claude.ai/install.ps1 | iex




"'irm' is not recognized as an internal or external command"
Causa: Lo opuesto al error anterior. Pegaste el comando de PowerShell dentro de CMD. El comando
irm es un atajo de PowerShell que CMD no conoce, así que responde que no lo reconoce.

Cómo saber en qué shell estás: En CMD, el prompt es C:\ sin prefijo. En PowerShell, el prompt
empieza con PS C:\ .

Solución: Como estás en CMD, usa el comando de CMD:



   curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd &&
   del install.cmd

Comandos slash esenciales

Dentro de una sesión de Claude Code, puedes usar comandos slash. Son atajos que empiezan con / .
Aquí van los más útiles para empezar:

   • /resume — Retomar una conversación anterior.
   • /config — Abrir configuración (canal de actualización, tema, etc.).

   • /init — Crear un archivo CLAUDE.md inicial para tu proyecto.
   • /doctor — Diagnóstico de la instalación.
   • /compact — Comprimir la conversación para usar menos memoria.
   • /bug — Reportar un problema a Anthropic.
   • /permissions — Gestionar qué herramientas puede usar sin preguntar.
   • /status — Ver método de autenticación activo y estado de la sesión.

    Claude Code viene con muchos comandos listos para usar. Pero lo mejor es que puedes
    crear los tuyos. Las skills son como recetas que le enseñas a Claude. Escribes las
    instrucciones una vez y las usas siempre que quieras. En este capítulo vas a aprender
    todos los comandos que ya vienen incluidos, cómo crear tus propias skills, y cómo
    instalar skills que otros compartieron.




Qué son las Skills y los Slash Commands

Imagina que Claude Code es un chef. Los slash commands son las recetas que ya sabe cocinar. Escribes
/ seguido del nombre y Claude ejecuta la receta.

Hay tres tipos de comandos / en Claude Code:

   • Built-in commands: Comandos del sistema. Hacen cosas fijas como limpiar la pantalla o cambiar
    el modelo. Son como los botones de tu microondas.
   • Bundled skills: Skills que vienen incluidas con Claude Code. Son más inteligentes: pueden leer
    archivos, lanzar agentes y adaptarse a tu proyecto. Son como electrodomésticos programables.
   • Custom skills: Las que tú creas o instalas de terceros. Son como recetas que tú escribes en un
    cuaderno.

Las skills son una evolución de los slash commands. Antes existían los "custom commands" (archivos
.md sueltos). Ahora las skills son carpetas completas con un archivo SKILL.md como punto de
entrada. Los comandos viejos siguen funcionando, pero las skills tienen más poderes.

Fusión oficial en 2026: La documentación de Anthropic ahora dice textualmente que "custom
commands have been merged into skills". Un archivo en .claude/commands/deploy.md y un skill en
.claude/skills/deploy/SKILL.md generan ambos el mismo /deploy y se comportan igual.
Hasta la URL antigua /slash-commands ahora redirige a /skills . Conceptualmente ya no son dos
cosas separadas: son la misma cosa, y skills es la única vía recomendada para casos nuevos porque
acepta archivos de soporte (templates, scripts, referencias) dentro de su carpeta.

El estándar abierto Agent Skills
Las skills siguen un formato estándar llamado Agent Skills. Lo publicó Anthropic en diciembre de 2025.
Está disponible en agentskills.io .

¿Por qué importa? Porque es un formato que funciona en varias herramientas. No solo Claude Code.
OpenAI lo adoptó para Codex CLI y ChatGPT. Es como el formato USB: un solo conector para muchos
dispositivos.

El principio clave de este estándar se llama progressive disclosure (divulgación progresiva). Funciona
en tres niveles:

  1. Metadata (~100 tokens): El nombre y la descripción. Se cargan siempre al inicio.
  2. Instructions (hasta 5000 tokens): El contenido completo del SKILL.md. Se carga cuando el skill se
    activa.
  3. Resources (bajo demanda): Archivos extra como scripts, ejemplos o datos. Se cargan solo cuando
    se necesitan.

Es como un restaurante. Primero ves el menú (metadata). Luego pides un plato y el mesero te trae la
receta detallada (instructions). Si necesitas algo más, pides los ingredientes extra (resources).

Skills Incluidas con Claude Code

Estas skills vienen preinstaladas. Son más poderosas que los built-in commands porque pueden usar
herramientas, lanzar agentes y adaptarse a tu proyecto.

Dos cosas importantes sobre las bundled skills:

   • Las puedes reemplazar. Si creas un skill propio con el mismo nombre (en .claude/skills/ o
     ~/.claude/skills/ ), tu versión gana y reemplaza a la incluida. Por ejemplo, un code-review
    en tu proyecto reemplaza al /code-review de fábrica.
   • Las puedes desactivar todas. Pon "disableBundledSkills": true en tu settings.json (o
    la variable de entorno CLAUDE_CODE_DISABLE_BUNDLED_SKILLS ) para quitar de un golpe todas
    las skills incluidas. Útil si prefieres tus propias versiones sin choques de nombres.

/simplify — Limpia tu código
Revisa los archivos que modificaste recientemente buscando oportunidades de limpieza: código
duplicado, simplificaciones, eficiencia y reutilización. Luego aplica las correcciones.

Cambio importante desde v2.1.154: /simplify es ahora un review de SOLO limpieza (calidad y
reutilización). NO busca bugs. Para cazar bugs de corrección usa su primo /code-review , que es la
herramienta dedicada a eso. Piensa en ellos como dos pasadas complementarias: /simplify deja el
código más limpio, /code-review busca que esté correcto.



   /simplify
   /simplify focus on memory efficiency



Puedes darle instrucciones adicionales para enfocarse en algo específico.


/batch — Cambios masivos en paralelo
Imagina que necesitas renombrar algo en 50 archivos. O migrar un framework completo. /batch
hace eso.

Primero investiga tu código. Luego divide el trabajo en 5 a 30 unidades independientes. Te muestra el
plan para que lo apruebes. Después lanza un agente por cada unidad, cada uno en su propia copia del

   /batch migrate src/ from Solid to React

Cómo Crear tus Propias Skills

Crear un skill es como escribir una receta. Necesitas un directorio y un archivo SKILL.md adentro.
Eso es todo lo mínimo.

Estructura de un skill
Un skill es una carpeta con esta estructura:



   mi-skill/
        SKILL.md             # Archivo principal (requerido)
        template.md          # Plantilla para que Claude rellene (opcional)
        examples/            # Ejemplos de salida esperada (opcional)
        scripts/             # Scripts que Claude puede ejecutar (opcional)
        references/          # Documentacion adicional (opcional)
        assets/              # Templates, imagenes, datos (opcional)



El archivo SKILL.md tiene dos partes:

  1. Frontmatter YAML: Metadata entre marcadores --- . Le dice a Claude cuándo y cómo usar el
    skill.
  2. Contenido Markdown: Las instrucciones que Claude sigue cuando el skill se activa.


Dónde guardar tus skills
Tienes varias opciones según quién quieres que use el skill:

   • Personal: ~/.claude/skills/mi-skill/SKILL.md — Disponible en todos tus proyectos. Solo
    tú lo ves.
   • Proyecto: .claude/skills/mi-skill/SKILL.md — Solo para este proyecto. Si haces commit,
    tu equipo también lo puede usar.
   • Plugin: Dentro de un plugin en skills/mi-skill/SKILL.md — Disponible donde el plugin esté
    habilitado.
   • Enterprise: Vía managed settings — Para toda la organización.

También siguen funcionando los comandos legacy en              ~/.claude/commands/nombre.md            y
.claude/commands/nombre.md . Si un skill y un command legacy tienen el mismo nombre, el skill
gana.

La prioridad es: enterprise > personal > proyecto.

Tu primer skill paso a paso
Vamos a crear un skill que explique código con analogías. Paso 1: crea el directorio.



   mkdir -p ~/.claude/skills/explain-code



Paso 2: crea el archivo SKILL.md con este contenido:



   ---
   name: explain-code
   description: Explains code with visual diagrams and analogies. Use when
   explaining how code works or when the user asks "how does this work?"
   ---


   When explaining code, always include:


   1. **Start with an analogy**: Compare the code to something from everyday
   life
   2. **Draw a diagram**: Use ASCII art to show the flow
   3. **Walk through the code**: Explain step-by-step what happens
   4. **Highlight a gotcha**: What's a common mistake?



Paso 3: ya está. Escribe /explain-code en Claude Code y funciona.

Tip: no necesitas memorizar el formato. Puedes pedirle a Claude que cree el skill por ti. Dile: "Crea un
skill que haga X" y él genera el archivo completo.


Campos del frontmatter
El frontmatter es la sección entre --- al inicio del archivo. Controla el comportamiento del skill.
Todos los campos son opcionales.

   • name — Nombre del skill. Máximo 64 caracteres. Solo letras minúsculas, números y guiones.
    Debe coincidir con el nombre de la carpeta.
   • description — Qué hace el skill. Claude usa esto para decidir cuándo activarlo
    automáticamente. Incluye palabras clave que describan las situaciones donde se usa. El listado
    de skills trunca description + when_to_use combinados a 1536 caracteres por defecto
    (configurable con maxSkillDescriptionChars ).
   • when_to_use — Contexto adicional sobre cuándo Claude debe invocar el skill: frases trigger,
    ejemplos típicos, situaciones de uso. Se anexa a description en el listado. Cuenta para el cap

    de 1536 caracteres. Útil cuando description ya está bien sintetizada y solo quieres darle más
    pistas a Claude.
   • argument-hint — Pista visual de qué argumentos espera. Aparece en el autocompletado.
    Ejemplo: [issue-number] .
   • arguments — Lista de argumentos posicionales nombrados que mapean a sustituciones $name
    en el contenido. Acepta string separado por espacios o lista YAML. Ejemplo:
     arguments: [issue, branch] . Al invocar /skill 123 main tendrás $issue=123 y
     $branch=main . Equivalente legible a $0 y $1 .

   • disable-model-invocation — Si es true , Claude NO puede activar este skill
    automáticamente. Solo el usuario puede usarlo con /nombre . Ideal para skills con efectos
    secundarios como deploy o enviar mensajes.
   • user-invocable — Si es false , el skill no aparece en el menú / . Pero Claude sí puede usarlo.
    Ideal para conocimiento de fondo.
   • allowed-tools — Herramientas que Claude puede usar sin pedir permiso durante este skill.
    Ejemplo: Read, Grep, Glob .
   • disallowed-tools (desde v2.1.152) — El complemento opuesto de allowed-tools :
    herramientas removidas del pool mientras el skill está activo. Se limpia automáticamente al
    enviar el siguiente mensaje. Útil para evitar que Claude use cierta herramienta durante el skill.
    Ejemplo: disallowed-tools: AskUserQuestion .
   • model — Modelo específico a usar cuando este skill está activo.
   • effort — Nivel de esfuerzo cuando este skill está activo. Sobreescribe el nivel de la sesión.
    Opciones: low , medium , high , xhigh , max . Los niveles disponibles dependen del modelo.
   • context — Pon fork para ejecutar en un subagente aislado.
   • agent — Tipo de subagente cuando usas context: fork . Opciones: Explore , Plan ,
     general-purpose , o un agente personalizado.

   • hooks — Hooks específicos para el ciclo de vida de este skill.
   • paths — Patrones glob que limitan cuándo el skill se activa automáticamente. Si trabajas con
    archivos que coinciden con estos patrones, Claude carga el skill. Acepta string separado por
    comas o lista YAML. Ejemplo: src/components/**/*.tsx, src/styles/**/*.css .
   • shell — Shell a usar para comandos !`command` y bloques ```! dentro del skill. Acepta
     bash (default) o powershell . Para usar PowerShell se requiere
     CLAUDE_CODE_USE_POWERSHELL_TOOL=1 .



Variables y argumentos
Los skills pueden recibir argumentos. Es como pasarle ingredientes a una receta.

Variables de sustitución:

   • $ARGUMENTS — Todos los argumentos que el usuario pasó. Se reemplazan en el contenido del
    skill.
   • $ARGUMENTS[0] , $ARGUMENTS[1] ... — Acceso a argumentos individuales por posición.
   • $0 , $1 , $2 ... — Atajo para lo mismo.
   • $name — Argumentos nombrados declarados en el campo arguments del frontmatter. Si pones
    arguments: [issue, branch] , usas $issue y $branch directamente, mucho más legible
    que $0 y $1 .
   • ${CLAUDE_SESSION_ID} — El ID de la sesión actual. Útil para crear archivos de log por sesión.
   • ${CLAUDE_SKILL_DIR} — La ruta al directorio del skill. Útil para referenciar scripts
    empaquetados.
   • ${CLAUDE_EFFORT} — El nivel de esfuerzo activo en la sesión: low , medium , high , xhigh o
    max . Permite que el skill adapte sus instrucciones (por ejemplo, pedir análisis más profundo solo
    si el effort es alto).

   ---

quieres que se interprete como argumento, escápalo con una barra invertida. Por ejemplo, escribe \
$1.00 para que aparezca $1.00 en vez de tratar $1 como el segundo argumento.

Lo mismo con argumentos nombrados (más legible al mantenerlo):

Inyección de contexto dinámico
Esta es una feature poderosa. Puedes ejecutar comandos de terminal ANTES de que Claude vea el
contenido del skill. La sintaxis es !`comando` .

Claude no ve el comando. Solo ve el resultado. Es como preparar los ingredientes antes de que el chef
entre a la cocina.

Ojo con dónde va el ! : El ! de inyección solo se reconoce al inicio de una línea o justo después de
un espacio. Si lo pegas a otro texto (por ejemplo KEY=!`comando` ), no se ejecuta y aparece literal.
Déjalo al principio de la línea o tras un espacio.



   ---
   name: pr-summary
   description: Summarize changes in a pull request
   context: fork
   agent: Explore
   allowed-tools: Bash(gh *)
   ---


   ## Pull request context
   - PR diff: !`gh pr diff`
   - PR comments: !`gh pr view --comments`
   - Changed files: !`gh pr diff --name-only`


   ## Your task
   Summarize this pull request focusing on impact and risks.



Cuando invocas /pr-summary , los comandos gh pr diff y los demás se ejecutan primero. Sus
salidas reemplazan los placeholders. Claude recibe los datos reales del PR listos para analizar.

Sintaxis multi-línea: Para comandos de shell que necesitan varias líneas, usa un bloque de código
abierto con ```! en lugar de la forma inline:




                                                     389                                   @soyenriquerocha
SKILLS Y SLASH COMMANDS




   ## Environment
   ```!
   node --version
   npm --version
   git status --short
   ```



Cada línea del bloque se ejecuta y su salida reemplaza el bloque completo. Es la alternativa a
encadenar múltiples !`comando` en líneas separadas.


Ciclo de vida del contenido de un skill
Cuando invocas un skill, su contenido renderizado entra en la conversación como un mensaje y se
queda ahí el resto de la sesión. Claude NO relee el archivo en turnos posteriores. Esto tiene una
implicación práctica: cada línea del skill cuesta tokens de manera recurrente, así que un SKILL.md
gigante engorda toda la sesión.

Por eso la recomendación oficial es: mantener el SKILL.md bajo 500 líneas y 1500-2000 palabras. Lo
detallado (ejemplos largos, especificaciones, referencias de API) va en archivos separados que el skill
referencia, como reference.md , examples/ o scripts/ . Esos archivos solo se cargan cuando
Claude decide leerlos.

Qué pasa tras auto-compaction: Cuando el contexto se llena y Claude compacta la conversación, los
skills invocados se re-anexan con un presupuesto: cada skill mantiene solo los primeros 5000 tokens y
entre todos comparten un budget combinado de 25000 tokens. La cola empieza por el más
recientemente invocado, así que si invocaste muchos skills durante la sesión, los más viejos pueden
desaparecer del contexto tras la compactación.

Si notas que un skill "deja de influir" después de varias compactaciones, simplemente vuelve a
invocarlo: su contenido se reanima en el contexto actual.

    descripción ni siquiera se carga en el contexto de Claude. Usa esto para skills con efectos

skillOverrides: controlar visibilidad sin editar SKILL.md
A veces no quieres tocar el archivo de un skill (porque viene en un repo compartido, o porque lo
provee un MCP) pero sí quieres cambiar su visibilidad. Para eso existe el setting skillOverrides .

Es un objeto en tu settings.json donde cada llave es el nombre del skill y cada valor controla
cómo aparece:

   • on — Visible normal: nombre y descripción cargan en el listado.
   • name-only — Solo el nombre se carga. La descripción no entra al contexto (ahorra tokens).
   • user-invocable-only — Oculto para Claude, pero sigue apareciendo en el menú / cuando tú
    lo necesitas.
   • off — Oculto completamente.



   // .claude/settings.local.json
   {
       "skillOverrides": {
           "legacy-context": "name-only",
           "deploy": "off",
           "experimental-tool": "user-invocable-only"
       }
   }

Skills con Subagentes

Cuando pones context: fork en el frontmatter, el skill se ejecuta en un subagente aislado. Imagina

Skills de referencia vs skills de tarea
Hay dos tipos de skills según su propósito:

   • Skills de referencia: Agregan conocimiento. Ejemplo: convenciones de tu API, reglas de estilo. Se
    ejecutan inline (sin context: fork ) para que Claude aplique las reglas en la conversación
    actual.
   • Skills de tarea: Ejecutan una acción. Ejemplo: deploy, generar reportes. Usan context: fork
    porque necesitan un entorno aislado.

Si usas context: fork en un skill de referencia, el subagente recibe las guías pero no tiene tarea
que hacer. Retorna sin resultado útil. Así que: referencia = inline, tarea = fork.

Descubrimiento Automático de Skills

Claude Code es inteligente para encontrar skills. No solo busca en las ubicaciones obvias.

   • Monorepos: Cuando trabajas con archivos en subdirectorios, Claude descubre skills en
    directorios .claude/skills/ anidados. Si editas un archivo en packages/frontend/ ,
    también busca en packages/frontend/.claude/skills/ .
   • Directorios adicionales: Skills definidos en carpetas agregadas vía --add-dir (o el comando /
    add-dir ) se cargan automáticamente. Puedes editarlos durante la sesión sin reiniciar. Ojo: el
    setting permissions.additionalDirectories NO carga skills. Solo --add-dir y /add-dir
    escanean los .claude/skills/ de directorios extra.
   • Plugins sin marketplace: Desde v2.1.157, los plugins y skills que pongas en .claude/skills/
    se cargan automáticamente sin necesidad de un marketplace. Y para arrancar un plugin desde
    cero, claude plugin init <name> genera el scaffold (la estructura de carpetas y archivos
    base) por ti.
   • Presupuesto del listado: Las descripciones de skills ocupan espacio en el contexto. El
    presupuesto total se controla con skillListingBudgetFraction en settings.json (default:
     0.01 , o sea 1% de la ventana de contexto). Como alternativa fija en caracteres puedes usar la
    variable de entorno SLASH_COMMAND_TOOL_CHAR_BUDGET .
   • Cap por entrada: Cada skill ocupa como mucho 1536 caracteres en el listado (con description
    + when_to_use combinados), configurable vía maxSkillDescriptionChars . Si los pasas, se
    truncan al final.
   • Diagnóstico: Ejecuta /doctor para ver si el listado está desbordado y qué skills quedaron
    cortados. /context también te muestra cuánto del contexto se está yendo en metadata de skills.

Si te sobran skills y el listado se llena, la solución típica es: subir skillListingBudgetFraction (por
ejemplo a 0.02 ), o bajar entradas de baja prioridad a name-only en skillOverrides .

Errores Comunes y Cómo Resolverlos

   • El skill no se activa automáticamente: Revisa que la description incluya palabras clave
    relevantes. Prueba con /skills para ver si aparece. Si no aparece, invócalo directamente con /
    nombre .

   • El skill se activa demasiado: Tu description es muy genérica. Hazla más específica o agrega
     disable-model-invocation: true .

   • Claude no ve todos mis skills: Tienes demasiados skills y el listado se está desbordando. Corre /
    doctor para ver qué skills quedaron cortados. Soluciones: sube
     skillListingBudgetFraction (ej. 0.02 ) o setea SLASH_COMMAND_TOOL_CHAR_BUDGET , baja
    entradas de baja prioridad a name-only en skillOverrides , o recorta description y
     when_to_use dejando el caso clave primero.

   • El directorio debe ser commands (plural): Un error típico es escribir command en singular. No
    funciona.
   • La extensión debe ser .md : Los archivos .txt o sin extensión no se reconocen.
   • $ARGUMENTS no funciona: Debe escribirse exactamente así, todo en mayúsculas.
   • Subagente retorna sin resultado: Estás usando context: fork en un skill de referencia. Los
    skills de referencia deben ejecutarse inline.
   • Skills de plugin no aparecen: Verifica que las carpetas estén a nivel raíz del plugin, no dentro de
     .claude-plugin/ . Si la estructura está bien, corre /reload-plugins ; si persiste, borra el
    caché con rm -rf ~/.claude/plugins/cache , reinicia Claude Code y reinstala.

Skill con argumentos nombrados (frontmatter arguments)



   mkdir -p .claude/skills/fix-issue
   cat > .claude/skills/fix-issue/SKILL.md << 'EOF'
   ---
   name: fix-issue
   description: Fix a GitHub issue on a specific branch
   when_to_use: User mentions fixing issue numbers, hotfixes, or wants
   to address a GitHub bug report.
   arguments: [issue, branch]
   allowed-tools: Bash(gh *), Read, Edit
   ---


   Fix GitHub issue #$issue on branch $branch following our coding
   standards.


   Steps:
   1. Fetch issue details: gh issue view $issue
   2. Switch to branch: git checkout $branch
   3. Implement the fix
   4. Run tests
   5. Open a PR linking back to issue #$issue
   EOF



El campo 'arguments: [issue, branch]' declara dos argumentos posicionales nombrados. Al
invocar /fix-issue 142 hotfix-auth, $issue=142 y $branch=hotfix-auth. Es más legible que $0 y $1,
sobre todo en skills largos. El campo 'when_to_use' refuerza cuándo Claude debe activar el skill
automáticamente.

Usar slash commands vía el Agent SDK (TypeScript)



   import { query } from "@anthropic-ai/claude-agent-sdk";


   // Enviar un slash command
   for await (const message of query({
       prompt: "/compact",
       options: { maxTurns: 1 }
   })) {
       if (message.type === "result") {
           console.log("Command executed:", message.result);
       }
   }


   // Descubrir comandos disponibles
   for await (const message of query({
       prompt: "Hello",
       options: { maxTurns: 1 }
   })) {
       if (message.type === "system" && message.subtype === "init") {
           console.log("Available slash commands:", message.slash_commands);
       }
   }



Los slash commands se pueden enviar programáticamente a través del Agent SDK. El mensaje de
inicialización del sistema incluye la lista de comandos disponibles. El SDK soporta TypeScript y
Python.

Resumen del Capítulo

Claude Code tiene tres tipos de comandos /: built-in (del sistema), bundled (incluidos) y custom
(tuyos). Las skills son carpetas con un archivo SKILL.md que contiene frontmatter YAML e
instrucciones Markdown. Puedes controlar quién las invoca, ejecutarlas en subagentes aislados,
inyectar contexto dinámico con comandos shell (inline o multi-línea), y compartirlas con tu equipo
o el mundo vía plugins. El ecosistema de la comunidad ofrece cientos de skills listos para instalar.

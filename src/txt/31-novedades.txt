Para qué sirve este changelog

Piensa en este apéndice como un diario de cambios. Es como el registro de mantenimiento de un
carro. Cada vez que algo cambia en el motor (los modelos de Claude), en el tablero (la interfaz de
claude.ai) o en las herramientas (Claude Code, la API), lo anotamos aquí.

Esto te sirve para tres cosas:

   • Saber qué es nuevo: Si actualizas tu guía de un mes a otro, puedes ver exactamente qué cambió.
   • No perderte nada: Claude evoluciona muy rápido. Este registro te mantiene al día.
   • Encontrar los capítulos afectados: Cada cambio indica qué capítulos de la guía se actualizaron.

Dónde publica Anthropic sus cambios
Anthropic anuncia sus novedades en tres lugares principales. Piensa en ellos como tres tablones de
anuncios diferentes:

  1. Platform Release Notes — En platform.claude.com/docs/en/release-notes . Aquí
    aparecen los cambios en la API, los SDKs y la consola de desarrollo. Es el tablón para
    programadores.
  2. Claude Apps Release Notes — En support.claude.com . Aquí se anuncian los cambios en
    claude.ai, las apps de celular, la app de escritorio y Cowork. Es el tablón para usuarios finales.
  3. Claude Code Changelog — En code.claude.com/docs/en/changelog . Aquí aparecen todas
    las versiones de Claude Code. Es el tablón para desarrolladores que usan el CLI.

Cómo leer un changelog (sin perderte)
Un changelog no se lee de corrido como un capítulo. Se lee como un índice de cambios. Aquí tienes las
cuatro ideas que te ayudan a entenderlo de un vistazo:

1. El número de versión te dice cuánto cambió. Cada edición de la guía tiene un número del tipo
MAYOR.MENOR (1.0, 1.1, 1.2, 1.3). El segundo número sube en cada actualización mensual normal,
donde se añaden o corrigen cosas. El primer número solo cambiaría con una reescritura grande del
libro. Así, un salto de 1.2 a 1.3 es una actualización del mes; un salto de 1.x a 2.0 sería una nueva gran
edición. Mirar el número ya te adelanta el tamaño del cambio.

2. Lo nuevo siempre está arriba. Las entradas se ordenan de la más reciente a la más antigua
(cronología inversa). Por eso la edición de junio aparece antes que la de abril. Si solo te interesa lo
último, no tienes que bajar hasta el final.

3. Los cambios se agrupan por tipo. Para leer rápido, conviene pensar en cuatro categorías:

   • Nuevo — algo que antes no existía (un modelo, una función, una sección).
   • Actualizado — algo que ya existía pero ahora es distinto o está ampliado (un precio, un límite, un
    dato).
   • Corregido — un error o un dato desactualizado que se arregló.
   • Eliminado — algo que dejó de existir y se quitó (por ejemplo, un modelo retirado).

Es el mismo esquema que usan los changelogs profesionales de software. La regla de oro detrás de
todo esto es sencilla: un changelog es para personas, no para máquinas. Está hecho para que
entiendas en segundos qué pasó, no para comparar dos versiones línea por línea.

4. Las fechas van en formato año-mes-día. Verás fechas como 2026-06-19 . Ese orden (año, luego
mes, luego día) se usa porque es claro en todo el mundo y no se confunde: nunca hay duda entre el
día y el mes.


Próximamente: lo que viene en la próxima edición
Muchos changelogs reservan un apartado para los cambios que ya están en camino pero todavía no
salieron en una edición publicada. Es una forma de avisarte: "esto viene pronto".

Ten en cuenta que Próximamente es una intención, no una promesa. Algo que está planeado puede
retrasarse o cambiar antes de llegar. Cuando una de estas novedades por fin se publica, deja de estar
en "Próximamente" y pasa a la entrada de la edición correspondiente, con su fecha y su número de
versión.

Estado de la API y plataforma
Las herramientas disponibles para desarrolladores a abril 2026:

   • Structured Outputs — Ya es GA (disponible para todos, sin header beta). Funciona con Sonnet
    4.5, Opus 4.5 y Haiku 4.5.
   • Web Search, Web Fetch, Code Execution — Todos GA. Code Execution es gratis cuando usas web
    search o web fetch.
   • Automatic Caching — Nuevo. Un solo campo cache_control y el sistema se encarga del resto.
   • Compaction API — Beta. Permite resumir conversaciones largas del lado del servidor.
   • Data Residency — Puedes elegir dónde se ejecuta la inferencia con el parámetro
     inference_geo .

   • Effort parameter — GA. Controla qué tanto "piensa" Claude antes de responder.
   • Fast Mode — Research preview. Opus 4.6 hasta 2.5x más rápido a precio premium.
   • Agent Skills — GA. PowerPoint, Excel, Word, PDF y skills personalizados vía API.
   • SDKs oficiales — GA: Python, TypeScript, Java, Go, Ruby. Beta: C#, PHP.
   • 1M token context — GA para Opus 4.6 y Sonnet 4.6 desde el 13 de marzo de 2026 (ya no requiere
    header beta). Todavía en beta para Sonnet 4.5 y Sonnet 4, pero se retira el 30 de abril.
   • Files API — Beta. Sube archivos y referéncialos en conversaciones.
   • MCP Connector — Beta. Conecta servidores MCP desde la Messages API.
   • Batch Processing — 50% menos costo para procesamientos masivos. Ahora soporta max_tokens
    hasta 300k para Opus 4.6 y Sonnet 4.6 con header output-300k-2026-03-24 .
   • thinking.display — Nuevo campo 'omitted' para extended thinking. Permite omitir el
    contenido de pensamiento en las respuestas, lo que hace el streaming más rápido.
   • Models API con capacidades — Nuevo. Los endpoints de modelos ahora devuelven
     max_input_tokens , max_tokens y un objeto capabilities que describe qué puede hacer
    cada modelo.
   • Límite de medios: 600 — Aumentado de 100 a 600 imágenes/páginas PDF por request desde el 13
    de marzo.

Errores comunes al seguir los cambios

Estos son los errores que la gente comete al intentar mantenerse al día:

Confundir versiones de modelos
Con tantos modelos (Opus 4, 4.1, 4.5, 4.6 y Sonnet 4, 4.5, 4.6), es fácil confundirse. Es como tener
muchos hermanos con nombres parecidos. Y desde junio de 2026 hay que sumar a la familia un primo
de otra rama: Claude Fable 5, de la clase 'Mythos'. Ojo con esto: Fable 5 no es "un Opus más nuevo"
ni "un Sonnet mejorado". Es una familia distinta, con su propia numeración. Comparar el 5 de Fable
con el 4.6 de Opus no tiene sentido, igual que no compararías el modelo de dos autos de marcas
diferentes solo por el número.

Solución: Usa siempre el ID canónico del modelo. Por ejemplo, claude-opus-4-6-20260205 en vez
de solo "Opus". Y ten claro a qué familia pertenece cada nombre (Opus, Sonnet, Haiku y ahora Fable/
Mythos). Consulta la tabla de modelos activos en este apéndice.


Usar un modelo retirado
Si tu código llama a un modelo que ya no existe, recibirás un error. Es como llamar a un número de
teléfono que ya fue desconectado.

Solución: Revisa la lista de modelos retirados. Migra al modelo recomendado antes de la fecha de
retiro.


Usar beta headers innecesarios
Muchas funciones pasaron de beta a GA en Q1 2026. Un beta header es una etiqueta especial que le
dices a la API para usar funciones experimentales. Si la función ya es GA (disponible para todos), el
header sobra.

Solución: Verifica el estado actual de cada función. Los beta headers extra no causan errores, pero es
mejor quitarlos para mantener tu código limpio.


Claude Code desactualizado
Claude Code se actualiza casi a diario. Una versión de hace dos semanas puede no tener funciones
importantes. Es como usar un mapa de hace un mes en una ciudad donde construyen calles nuevas
cada semana.

Solución: Verifica tu versión con claude --version . Actualiza con:



   npm install -g @anthropic-ai/claude-code



O desde el menú /config dentro de Claude Code.



Cómo mantenerte al día

El ecosistema Claude cambia rápido. Muy rápido. Aquí tienes un plan simple para no perderte nada:

  1. Descarga la edición más reciente cada mes — Cada edición incluye los cambios del mes en
    todos los capítulos afectados.
  2. Revisa este apéndice primero — Cuando tengas una nueva edición, lee este changelog. Te dirá
    qué cambió y dónde.
  3. Mantén Claude Code actualizado — Ejecuta claude --version y actualiza si hay una versión
    nueva.
  4. Visita las fuentes oficiales — Los tres sitios de novedades: platform.claude.com ,
     support.claude.com y code.claude.com .

No necesitas revisar todo a diario. Con una revisión mensual es suficiente. Este apéndice hace el
trabajo pesado por ti.

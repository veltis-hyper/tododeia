Panorama general: tres formas de usar Claude Code

Imagina que Claude Code es un asistente que puede sentarse en diferentes escritorios. Puede estar en:

   • VS Code — con una extensión oficial que tiene más de 6.5 millones de instalaciones
   • JetBrains — con un plugin dedicado (en Beta) para IntelliJ, PyCharm, WebStorm y más
   • Claude Desktop — una app independiente con funciones avanzadas como preview de apps y
       tareas programadas
   • Terminal integrado — el CLI clásico, pero corriendo dentro de cualquier IDE

Todas estas opciones comparten la misma configuración base. Tus archivos CLAUDE.md , tus MCP
servers y tu historial de conversaciones funcionan igual en todas partes.

Sobre plugins de la comunidad (no oficiales): Para editores que no tienen extensión oficial (Neovim,
Emacs, Zed) existen plugins de la comunidad que reimplementan el protocolo WebSocket/MCP de la
extensión oficial:    claudecode.nvim ,     claude-code.nvim ,      vim-claude-code       para Neovim;
integraciones en Emacs con project context y diagnostics; y en Zed se usa via terminal integrado. No
los soporta Anthropic, pero la comunidad los mantiene activos.

Qué se comparte entre todas las opciones
Sin importar dónde uses Claude Code, estas cosas se comparten automáticamente:

   • Archivos CLAUDE.md del proyecto
   • MCP servers configurados en ~/.claude.json o .mcp.json
   • Hooks y skills definidos en settings
   • Settings globales en ~/.claude/settings.json
   • Reglas de permisos y herramientas permitidas
   • Historial de conversaciones (la extensión y el CLI comparten historial)

Ojo:     Los   MCP    servers   configurados    para    la   app    de   chat    de   Claude    Desktop
( claude_desktop_config.json ) son completamente separados del Code tab. No aparecen en
Claude Code. Esto confunde a mucha gente.

Claude Code en VS Code

La extensión de VS Code es el método recomendado por Anthropic. Piensa en ella como un panel de
chat inteligente dentro de tu editor. No solo responde preguntas: puede editar archivos, ejecutar
comandos y hasta controlar tu navegador.

Instalación paso a paso
Necesitas VS Code versión 1.98.0 o superior y una cuenta Anthropic.

La forma más rápida:

  1. Abre VS Code
  2. Presiona Cmd+Shift+X en Mac (o Ctrl+Shift+X en Windows/Linux)
  3. Busca Claude Code
  4. Haz clic en Install

Si no aparece la extensión, reinicia VS Code o ejecuta Developer: Reload Window desde la
Command Palette.

Link directo de instalación: también puedes usar URLs especiales que abren VS Code o Cursor en la
página de instalación de la extensión:

   • VS Code: vscode:extension/anthropic.claude-code
   • Cursor: cursor:extension/anthropic.claude-code

En macOS, open "vscode:extension/anthropic.claude-code" abre la extensión lista para
instalar. En Linux usa xdg-open y en Windows Start-Process .

Soporte para forks de VS Code: la misma extensión se instala en Cursor, Devin Desktop (antes
Windsurf), Kiro y VSCodium. Devin Desktop es el mismo fork de VS Code de siempre: en Claude Code
v2.1.169 (8 de junio de 2026) solo cambió el nombre del producto, no la integración. Los forks que no
usan el Microsoft Marketplace (porque sus términos lo prohíben) descargan la extensión desde el
Open VSX Registry con el mismo identificador anthropic.claude-code . Si tu fork no permite
instalar la extensión, siempre puedes correr claude desde su terminal integrado.

Una vez instalada la extensión, tienes varias formas de abrirla:

  1. Icono Spark — El icono de chispa en la esquina superior derecha del editor. Es la forma más
    rápida. Solo aparece cuando tienes un archivo abierto.
  2. Activity Bar — El icono de chispa en la barra lateral izquierda. Siempre visible. Muestra la lista de
    sesiones.

Dónde colocar el panel de Claude
Puedes mover el panel de Claude a tres posiciones:

   • Sidebar derecha (secundaria) — La posición recomendada. Mantiene Claude visible mientras
    escribes código. Es como tener un copiloto siempre a la vista.
   • Sidebar izquierda — Junto al explorador de archivos, búsqueda, etc.
   • Área del editor — Claude se abre como una pestaña más junto a tus archivos. Útil para tareas
    secundarias.

También puedes cambiar la ubicación predeterminada en los settings de la extensión con
claudeCode.preferredLocation .



El sistema de @-menciones: cómo dar contexto a Claude
Las @-menciones son como etiquetas. Le dicen a Claude exactamente qué mirar. Es como señalar algo
con el dedo y decir "mira esto".

   • @archivo.ts — Menciona un archivo. Soporta fuzzy matching (búsqueda inteligente). Si
    escribes @auth , encuentra auth.js , AuthService.ts , etc.
   • @carpeta/ — Menciona una carpeta entera. No olvides la barra final.
   • @archivo.ts#5-10 — Referencia a líneas específicas. El atajo Option+K (Mac) o Alt+K (Win/
    Linux) lo inserta automáticamente cuando tienes código seleccionado.
   • @terminal:nombre — Referencia a la salida de un terminal por su título. Evita tener que copiar y
    pegar.
   • @browser — Conecta con Chrome para tareas del navegador. Requiere la extensión Claude in
    Chrome versión 1.0.36 o superior.
   • @archivo.pdf — Menciona un PDF. Puedes pedir páginas específicas en el mismo prompt:
    "página 3", un rango "1-10", o un rango abierto "desde la página 3". Útil para PDFs grandes que no
    quieres cargar enteros.

También puedes arrastrar archivos con Shift para adjuntarlos. Y la selección del editor se comparte
automáticamente (puedes desactivar esto con el icono del ojo).

Modos de permisos
Los modos de permisos controlan cuánta libertad tiene Claude. Piensa en ellos como niveles de
confianza:

   • Ask permissions (predeterminado) — Claude pregunta antes de cada acción. Como un empleado
    nuevo que confirma cada paso contigo.
   • Auto accept edits — Claude edita archivos sin preguntar, pero pide permiso para comandos de
    terminal. Como un empleado con más experiencia.
   • Plan mode — Claude analiza y crea un plan, pero no modifica nada. Como pedirle que piense
    antes de actuar.
   • Bypass permissions — Claude hace todo sin preguntar. Solo para entornos sandbox. Como darle
    las llaves de la casa.

Puedes      cambiar    el    modo   en    cualquier    momento      durante    la   sesión.     El   setting
claudeCode.initialPermissionMode define cuál se usa al iniciar.

Plan mode con feedback inline (exclusivo de VS Code): cuando activas Plan mode en la extensión,
Claude abre el plan como un documento markdown a pantalla completa dentro del editor. Puedes
leerlo, añadir comentarios inline al lado de las líneas que no te convencen y revisar todo antes de
aprobar. Cuando aceptas, esos comentarios viajan de vuelta a Claude como ajustes al plan. Este flujo
combina la claridad del editor con el control del CLI y es único de VS Code: ni el CLI puro ni el plugin de
JetBrains lo tienen.


Checkpoints: tu máquina del tiempo
Los checkpoints son puntos de control. Cada vez que Claude modifica algo, se guarda un checkpoint.
Si algo sale mal, puedes retroceder.

Al pasar el cursor sobre cualquier mensaje, tienes tres opciones:

   • Fork conversation from here — Crea una nueva rama de conversación. Mantiene los cambios en
    el código.
   • Rewind code to here — Revierte los cambios de archivos, pero mantiene el historial de chat.
   • Fork conversation and rewind code — Combina las dos anteriores. Nueva rama + revertir
    cambios.

Es como tener Ctrl+Z con superpoderes.

Resumir sesiones remotas
Si usas Claude Code on the web (claude.ai), puedes continuar esas sesiones en VS Code.

  1. Abre el dropdown de Past Conversations
  2. Ve a la pestaña Remote
  3. Selecciona la sesión que quieres continuar

Requisitos: necesitas iniciar sesión con una suscripción de Claude.ai (no Anthropic Console). Solo
aparecen sesiones que se iniciaron con un repositorio de GitHub.

Importante: La sesión se descarga a tu máquina local. Los cambios que hagas no se sincronizan de
vuelta a claude.ai.


Comandos del menú / en el prompt
Al escribir / en el prompt de la extensión aparece un menú con los comandos disponibles. Es un
subconjunto del CLI, pero cubre lo que más se usa día a día:

   • /usage — Muestra el uso del plan en la sesión actual (mensajes consumidos, ventana de reset,
    modelo activo). En la extensión se ve como una barra gráfica. Desde Claude Code v2.1.174 o
    posterior, el diálogo Account & usage añade un desglose de atribución por skill, subagente,
    plugin y MCP (además de cache misses y contexto largo) en ventanas de 24 horas y 7 días, para
    que veas qué está consumiendo tu cuota. Las cifras son aproximadas y solo cuentan las sesiones
    locales de esa máquina.
   • /remote-control — Inicia una sesión de Remote Control. Te da una URL para controlar la
    misma sesión desde el navegador de otro dispositivo (laptop, teléfono).
   • /plugins — Abre el plugin manager gráfico (ver sección dedicada).
   • /mcp — Abre la gestión de MCP servers (enable/disable, reconectar, OAuth).
   • /compact — Compacta manualmente la conversación cuando el contexto se llena.
   • /config — Abre la configuración interactiva (modelo, diff tool, editor mode, etc.).
   • /theme — Cambia el tema visual o crea uno custom.

Modo Vim para el prompt
Si estás acostumbrado a Vim, puedes editar el prompt con keybindings tipo Vim. Lo activas de dos
formas:

   • En ~/.claude/settings.json : "editorMode": "vim"
   • Desde Claude: /config → Editor mode → vim

El modo soporta un subset de motions de Vim:

   • NORMAL: hjkl (movimiento), w/b/e (palabras), 0/$ (inicio/fin de línea), gg/G (arriba/abajo),
     i/a/I/A (entrar a INSERT), o/O (nueva línea), d/c/y con text objects ( dw , ciw , yy ).

   • VISUAL: v (carácter), V (línea); d/c/y sobre la selección.

Diferencia clave con Vim estándar: Enter en INSERT envía el prompt, no inserta nueva línea. Para
meter un salto de línea tienes dos caminos:

   • Volver a NORMAL ( Esc ) y usar o u O
   • Pulsar Ctrl+J directamente desde INSERT

Las motions del modo Vim no son remapeables via keybindings.json de VS Code: están
manejadas dentro del prompt de Claude, no por el editor.



Deep links: abrir Claude desde URLs externas

Claude Code registra dos esquemas de URL para que puedas lanzar sesiones desde cualquier sitio que
entienda links: un Slack, una página de Notion, un runbook, un bookmarklet o un alias de shell.

   • vscode://anthropic.claude-code/open — abre una pestaña de Claude Code dentro de VS
    Code.
   • claude-cli://open — abre una sesión de Claude Code en el terminal del sistema.

Los dos rellenan el prompt pero no lo envían automáticamente. El ingeniero siempre revisa antes de
pulsar Enter.

vscode://anthropic.claude-code/open (pestaña en VS Code)
La extensión registra este URI handler al instalarse. Te permite abrir un tab de Claude Code desde
cualquier lugar: un script de shell, un bookmarklet o una herramienta de automatización.

La URL base es:



   vscode://anthropic.claude-code/open



Si VS Code no está corriendo, la URL lo lanza primero. Si ya está abierto, la URL abre la pestaña en la
ventana enfocada.

Acepta dos parámetros opcionales:

   • prompt — Texto pre-llenado en el prompt box (URL-encoded). No se envía automáticamente,
    solo se pre-llena.
   • session — ID de una sesión existente para reanudarla en vez de iniciar una nueva. Debe
    pertenecer al workspace abierto. Si la sesión ya está abierta en otra pestaña, la enfoca.

Para invocarlo desde la terminal:

   • macOS:
     open "vscode://anthropic.claude-code/open?prompt=review%20my%20changes"

   • Linux: xdg-open "vscode://anthropic.claude-code/open?
    prompt=review%20my%20changes"

   • Windows: start vscode://anthropic.claude-code/open?
    prompt=review%20my%20changes

Es útil para crear alias de shell que abran Claude con un prompt predefinido. Por ejemplo, un alias cr
que abra Claude con el prompt "review my changes" cada vez que quieras una revisión rápida.


claude-cli://open (sesión de terminal)
El esquema claude-cli://open abre una sesión de terminal de Claude Code con el directorio y el
prompt pre-rellenados. Pensado para embeber en runbooks de incidentes, alertas de PagerDuty,
tickets de Linear o cualquier sitio donde un link cumpla la función de "haz clic y arranca Claude en
este contexto".

Requiere Claude Code v2.1.91 o superior. El handler se registra la primera vez que ejecutas claude
interactivo en la máquina; antes de eso, los links no hacen nada.

Parámetros aceptados:

   • q — Prompt pre-rellenado, URL-encoded. Hasta 5000 caracteres. Usa %0A para salto de línea.
   • cwd — Ruta absoluta del directorio de trabajo. Tiene prioridad sobre repo . Rechaza rutas de red
    o UNC.
   • repo — Slug owner/name de GitHub. Se resuelve al último clon donde ejecutaste claude . Si
    nunca corriste Claude en ese repo, el handler cae al directorio home.

Cuando el link se abre, Claude muestra un banner sobre el input avisando que el prompt viene de una
fuente externa. Si el prompt supera los 1000 caracteres, el banner recomienda revisarlo antes de
enviar.

Ejemplos:



   # Runbook que abre Claude en el repo correcto con prompt:
   claude-cli://open?repo=acme/web-gateway&q=5xx%20rate%20is%20elevated.
   %20Check%20recent%20deploys.


   # Con ruta absoluta (gana sobre repo):
   claude-cli://open?cwd=/Users/jane/work/api&q=review%20open%20PRs



Importante con GitHub Markdown: GitHub strip-ea los esquemas custom (todo lo que no es
http:// o https:// ) cuando renderiza markdown. Los deep links claude-cli:// solo funcionan
como links activos en plataformas que sí permiten esquemas custom: Slack, Notion, Confluence,
Linear, PagerDuty. En GitHub mete la URL en un bloque de código para que el lector pueda copiarla.

Por dónde se registra el handler en cada SO:

   • macOS: ~/Applications/Claude Code URL Handler.app
   • Linux: $XDG_DATA_HOME/applications/claude-code-url-handler.desktop (por defecto
     ~/.local/share/applications )

   • Windows: HKEY_CURRENT_USER\Software\Classes\claude-cli

Claude recuerda el último terminal donde lo abriste (iTerm2, Ghostty, kitty, Alacritty, WezTerm,
Terminal.app en macOS; $TERMINAL o equivalente en Linux; Windows Terminal en Windows). Si el
deep link abre el terminal equivocado, lanza claude una vez en tu terminal favorito y la próxima vez
lo recordará.

Desactivar el handler en empresa
En entornos corporativos puede que no quieras que los usuarios reciban deep links desde fuentes
externas. Añade esta clave a       ~/.claude/settings.json        o, mejor todavía, a     managed-
settings.json :



   {
        "disableDeepLinkRegistration": "disable"
   }



Con esto, Claude Code no registra el handler claude-cli:// al primer arranque. Si lo configuras via
managed settings, los usuarios no pueden re-habilitarlo desde sus propios settings.



Settings de la extensión VS Code

La extensión tiene varias opciones de configuración. Puedes acceder a ellas con Cmd+, (Mac) o
Ctrl+, (Win/Linux) y buscar Claude Code.

Estas son las más importantes:

Settings principales
   • claudeCode.selectedModel — El modelo para nuevas conversaciones. Valor predeterminado:
       default . Puedes cambiarlo por sesión con /model .

   • claudeCode.useTerminal — Si prefieres la interfaz de terminal en vez del panel gráfico, pon
    esto en true .
   • claudeCode.preferredLocation — Dónde se abre Claude: sidebar (derecha) o panel
    (nueva pestaña).
   • claudeCode.autosave — Guarda archivos automáticamente antes de que Claude los lea o
    escriba. Predeterminado: true . Déjalo activado.
   • claudeCode.useCtrlEnterToSend — Usa Ctrl/Cmd+Enter en vez de Enter para enviar. Útil
    si envías mensajes por accidente.
   • claudeCode.respectGitIgnore — Excluye archivos de .gitignore en las búsquedas.
    Predeterminado: true .


Settings avanzados
   • claudeCode.initialPermissionMode — El modo de permisos al iniciar. Opciones: default ,
       plan , acceptEdits , bypassPermissions .

   • claudeCode.environmentVariables — Variables de entorno para Claude. Ejemplo:
    ["MY_VAR=value"] . Pero es mejor usar ~/.claude/settings.json para que funcione tanto
    en la extensión como en el CLI.
   • claudeCode.disableLoginPrompt — Omite la pantalla de login. Necesario si usas Amazon
    Bedrock, Google Vertex AI o Microsoft Foundry.
   • claudeCode.allowDangerouslySkipPermissions — Omite TODOS los permisos. Solo para
    entornos sandbox. Usar con extrema precaución.
   • claudeCode.enableNewConversationShortcut — Habilita Cmd/Ctrl+N para nueva
    conversación. Predeterminado: true .
   • claudeCode.claudeProcessWrapper — Ruta a un ejecutable wrapper personalizado para el
    proceso de Claude. Es un string vacío por defecto. Útil para entornos especiales donde necesitas
    envolver el proceso de Claude en otro comando.
   • claudeCode.hideOnboarding — Oculta el checklist de onboarding (el icono del gorro de
    graduación). Predeterminado: false . Actívalo después de completar la guía inicial si ya no lo
    necesitas.


Settings extras de productividad
   • claudeCode.enableReopenClosedSessionShortcut — Habilita Cmd+Shift+T (Mac) o
    Ctrl+Shift+T (Win/Linux) para reabrir la última sesión de Claude que cerraste.
    Predeterminado: true . Si el último tab cerrado no era de Claude, el atajo cae al comportamiento
    normal de VS Code (reabrir el último editor cerrado). Si esto te molesta, ponlo en false .
   • claudeCode.usePythonEnvironment — Activa el entorno Python del workspace al ejecutar
    Claude. Predeterminado: true . Requiere tener instalada la extensión oficial de Python de
    Microsoft ( ms-python.python ). Esto significa que Claude usa el mismo intérprete y
    dependencias que tu IDE: si tienes un venv activo, Claude lo respeta. Si no usas Python o no
    quieres que Claude active el entorno, pásalo a false .


Temas personalizados
Claude Code trae presets de temas: dark , light , dark-daltonized , light-daltonized , dark-
ansi y light-ansi . Los daltonizados ajustan colores para usuarios con daltonismo.

También puedes crear tus propios temas. Claude observa la carpeta ~/.claude/themes/ y carga
cualquier archivo JSON con esta forma:

   // ~/.claude/themes/dracula.json
   {
       "name": "Dracula",
       "base": "dark",
       "overrides": {
           "claude": "#bd93f9",
           "error": "#ff5555",
           "success": "#50fa7b"
       }
   }



Campos:

   • name — Cómo aparece en el selector /theme .
   • base — Tema preset del que hereda ( dark o light ). Define los colores por defecto.
   • overrides — Diccionario con los tokens que quieres cambiar: claude , error , success ,
    colores del prompt, diffs, fullscreen, usage meter, subagentes, etc.

Para activar un tema, usa /theme y selecciónalo. Para crear uno interactivamente, /theme → New
custom theme.... Para editar uno existente, selecciónalo y pulsa Ctrl+E . Claude recarga el tema en
caliente cada vez que guardas el archivo.

CLI vs Extensión: qué puede hacer cada uno

La extensión y el CLI no son idénticos. Cada uno tiene funciones que el otro no tiene.

Función                 CLI       Extensión
Comandos y skills       Todos     Un subconjunto (escribe / para ver)
Configurar MCP servers Completo Parcial (agregar vía CLI, gestionar con /mcp )
Checkpoints             Sí        Sí
Atajo ! para bash       Sí        No
Tab completion          Sí        No
La buena noticia: puedes usar ambos al mismo tiempo. Abre el CLI en el terminal integrado de VS
Code y tendrás lo mejor de los dos mundos.



Claude Code en JetBrains

Si usas IntelliJ IDEA, PyCharm, Android Studio, WebStorm, PhpStorm o GoLand, hay un plugin
dedicado. Está en Beta, pero funciona bien para las tareas más comunes.

Limitación importante de teclado: el terminal de JetBrains no soporta Shift+Enter para salto de
línea, ni siquiera tras ejecutar /terminal-setup . Es una limitación del propio terminal de JetBrains.
Como alternativa, usa Ctrl+J o el patrón \ + Enter (un backslash al final de la línea antes de Enter).

Instalación
A diferencia de VS Code, necesitas dos cosas:

  1. Claude Code CLI instalado globalmente: npm install -g @anthropic-ai/claude-code
  2. Plugin de JetBrains: busca Claude Code en el JetBrains Marketplace e instala el de Anthropic PBC

Después de instalar, reinicia el IDE completamente. A veces necesitas reiniciar más de una vez.

Nota importante: Existe otro producto llamado Claude Agent in JetBrains IDEs que es parte de la
suscripción JetBrains AI. Eso es diferente. Aquí hablamos del plugin oficial de Anthropic.


Funciones del plugin
El plugin agrega cuatro capacidades principales:

   • Diff viewing — Los cambios de código se muestran en el visor de diffs del IDE. No tienes que
    leerlos en la terminal.
   • Selection context — Tu selección actual y la pestaña abierta se comparten automáticamente con
    Claude.

Error frecuente: "No available IDEs detected". Cuando claude corre dentro de WSL2 y JetBrains
corre en Windows, por defecto WSL2 usa NAT y Windows Firewall bloquea la comunicación entre los
dos. Hay dos soluciones:

Opción A: regla de firewall (cualquier Windows). Averigua la IP interna de WSL2 con hostname -I
dentro de WSL (por ejemplo 172.21.123.45 ). Luego, en una PowerShell de administrador, crea una
regla que permita el tráfico interno:



   New-NetFirewallRule -DisplayName "Allow WSL2 Internal Traffic" `
      -Direction Inbound -Protocol TCP -Action Allow `
      -RemoteAddress 172.21.0.0/16 -LocalAddress 172.21.0.0/16



Opción B: mirrored networking (Windows 11 22H2+). Edita %USERPROFILE%\.wslconfig y añade:



   [wsl2]
   networkingMode=mirrored



Cierra todo con wsl --shutdown y vuelve a abrir. En este modo, WSL2 comparte la red con Windows
directamente y el plugin detecta el IDE sin necesidad de reglas de firewall.

Tras aplicar cualquiera de las dos soluciones, reinicia el IDE y vuelve a ejecutar claude .

Integración automática con el IDE
Cuando ejecutas claude en el terminal integrado de VS Code o JetBrains, el CLI detecta

  3. Escribe /ide

Nota técnica: Cuando la extensión de VS Code está activa, ejecuta un servidor MCP local oculto al que
el CLI se conecta automáticamente. Este servidor es el que permite que el CLI abra diffs en el visor
nativo, lea tu selección actual y comparta diagnósticos del IDE. Se enlaza a 127.0.0.1 en un puerto
aleatorio (no accesible desde otras máquinas) y usa un token de autenticación almacenado en

El servidor expone dos tools al modelo (el resto son RPC internos entre CLI y extensión que nunca
llegan al LLM):

   • mcp__ide__getDiagnostics — Read-only. Devuelve los diagnostics del language server (el
    contenido del panel Problems del IDE). Puede acotarse a un solo archivo. Claude la invoca cuando
    le pides cosas como "arregla los errores".
   • mcp__ide__executeCode — Ejecuta código Python en el kernel del notebook Jupyter activo.
    Inserta el código como nueva celda al final del notebook, hace scroll a la vista y siempre abre un
    Quick Pick nativo de VS Code con Execute o Cancel para que confirmes. Rechaza si no hay
    notebook activo, si no tienes la extensión ms-toolsai.jupyter o si el kernel no es Python. Los
    hooks PreToolUse no eliminan este Quick Pick: la confirmación manual es obligatoria.

Esto importa si configuras hooks PreToolUse con allowlists de herramientas MCP: tienes que listar
explícitamente mcp__ide__getDiagnostics y mcp__ide__executeCode si quieres que Claude las
pueda usar.

Configurar tmux
Si trabajas dentro de tmux, hay tres líneas que tienes que añadir a ~/.tmux.conf para que

Habilitar tráfico WSL2 en Windows Firewall (JetBrains)



    # En WSL
    hostname -I            # ej: 172.21.123.45


    # En PowerShell como administrador
    New-NetFirewallRule -DisplayName "Allow WSL2 Internal Traffic" `
        -Direction Inbound -Protocol TCP -Action Allow `
        -RemoteAddress 172.21.0.0/16 -LocalAddress 172.21.0.0/16



Solución al error 'No available IDEs detected' cuando claude corre en WSL2 y JetBrains corre en
Windows. Alternativa más limpia (Win11 22H2+): networkingMode=mirrored en .wslconfig.

Resumen del Capítulo

Claude Code se integra con VS Code (extensión oficial), JetBrains (plugin Beta) y Claude Desktop
(app con tres pestañas: Chat, Cowork y Code). También puedes usarlo desde el terminal integrado
de cualquier IDE. Todas las integraciones comparten configuración, historial y MCP servers. Elige
según tus necesidades: la extensión para el día a día, Desktop para revisión visual y tareas
avanzadas, y el CLI para automatización. Los deep links claude-cli:// y vscode://anthropic.claude-
code/open permiten lanzar sesiones desde runbooks, scripts y alertas.

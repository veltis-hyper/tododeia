    Las variables de entorno son como los controles de un tablero de mandos. Cada una
    ajusta algo específico en Claude Code: desde qué modelo usar, hasta cómo conectarse a
    la red. A junio de 2026, Claude Code reconoce más de 230 variables documentadas. Este
    apéndice lista TODAS las variables conocidas, organizadas por categoría. Úsalas como
    referencia rápida cuando necesites cambiar el comportamiento de Claude Code.




Cómo configurar variables de entorno

Antes de ir a la tabla gigante, necesitas saber dónde poner estas variables. Tienes tres opciones:

Opción 1: En tu terminal (shell)
Escribe export antes de lanzar Claude Code. Es rápido pero temporal. Cuando cierres la terminal, la
variable desaparece.



   export ANTHROPIC_MODEL=claude-opus-4-8
   claude



Para que sea permanente, agrega el export a tu archivo ~/.bashrc o ~/.zshrc .


Opción 2: En settings.json (recomendado para equipos)
Puedes poner variables dentro del campo "env" en cualquier archivo settings.json . Es como un
tablero de configuración permanente.



   {
       "env": {
           "ANTHROPIC_MODEL": "claude-opus-4-8",
           "CLAUDE_CODE_EFFORT_LEVEL": "high"
       }
   }



Regla importante: todos los valores en settings.json deben ser strings (texto entre comillas).
Aunque sea un número, ponlo entre comillas: "1" , no 1 .

Los archivos settings.json viven en estas ubicaciones:

   • ~/.claude/settings.json — Tu configuración personal
   • .claude/settings.json — Configuración del proyecto (compartida con el equipo)
   • .claude/settings.local.json — Tu configuración local del proyecto (no se sube al repo)
   • managed-settings.json — Configuración forzada por la empresa (ver Apéndice B)


Opción 3: Con CLAUDE_ENV_FILE (para scripts)
Cada comando Bash en Claude Code se ejecuta en un shell nuevo. Eso significa que las variables que
definas en un comando no existen en el siguiente. Es como si cada comando empezara desde cero.

CLAUDE_ENV_FILE resuelve esto. Le dices a Claude Code: "antes de cada comando, carga este
archivo".



   # Crea el archivo con las variables que necesitas
   echo 'export MI_TOKEN=abc123' > ~/.claude/env-setup.sh


   # Dile a Claude Code que lo use
   export CLAUDE_ENV_FILE=~/.claude/env-setup.sh
   claude



Ahora cada comando Bash tendrá acceso a MI_TOKEN .


Orden de precedencia
Si la misma opción está definida en varios lugares, Claude Code usa este orden de prioridad (de mayor
a menor):

  1. Managed settings (la empresa manda)
  2. Argumentos CLI (flags como --model ) y comandos en sesión (como /model )
  3. Variables de entorno (lo que defines con export o en el bloque env )
  4. Settings local ( settings.local.json )
  5. Settings de proyecto ( .claude/settings.json )
  6. Settings de usuario ( ~/.claude/settings.json )

Piensa en esto como una cadena de mando. El jefe (managed settings) siempre gana.

Corrección importante (junio 2026): como regla general, las variables de entorno tienen prioridad
sobre los campos de settings.json . Por ejemplo, ANTHROPIC_MODEL gana sobre el ajuste model ,
y CLAUDE_CODE_AUTO_CONNECT_IDE gana sobre autoConnectIde .

Eso sí, hay matices según la función:

Patrones de nombres: cómo entender las variables sin memorizar

No necesitas memorizar 200 variables. Solo aprende los patrones de sus nombres. Es como aprender
los prefijos de los números de teléfono: una vez que entiendes el patrón, puedes adivinar qué hace
cada variable.

   • CLAUDE_CODE_DISABLE_* — Apaga una funcionalidad. Ejemplo:
     CLAUDE_CODE_DISABLE_THINKING .

   • CLAUDE_CODE_ENABLE_* — Enciende una funcionalidad. Ejemplo:
     CLAUDE_CODE_ENABLE_TELEMETRY .

   • DISABLE_* — Apaga un comando o feature más antiguo. Ejemplo: DISABLE_AUTOUPDATER .
   • ENABLE_* — Enciende una feature experimental. Ejemplo: ENABLE_LSP_TOOL .
   • ANTHROPIC_* — Configuración de la API de Anthropic. Ejemplo: ANTHROPIC_API_KEY .
   • AWS_* — Variables estándar del SDK de AWS. Ejemplo: AWS_REGION .
   • OTEL_* — Variables estándar de OpenTelemetry. Ejemplo: OTEL_TRACES_EXPORTER .
   • MCP_* — Configuración del Model Context Protocol. Ejemplo: MCP_TIMEOUT .



API y Autenticación

Estas variables controlan cómo Claude Code se conecta a la API. Son las llaves de la puerta.

   • ANTHROPIC_API_KEY — Tu clave API principal. Si usas suscripción (Pro/Max/Team), no la
    configures. Si la configuras, usarás la API de pago por uso y podrías recibir cargos inesperados.
   • ANTHROPIC_AUTH_TOKEN — Token de autorización alternativo. Para gateways LLM como LiteLLM.
    Tiene prioridad sobre ANTHROPIC_API_KEY .
   • ANTHROPIC_BASE_URL — URL base personalizada. Por defecto: https://api.anthropic.com .
    Cámbiala para proxies o gateways.
   • ANTHROPIC_CUSTOM_HEADERS — Cabeceras HTTP extra en cada solicitud. Formato: Nombre:
    Valor separados por \n .

Configuración de Modelos

Estas variables te permiten elegir qué modelo usa Claude Code y cómo se comporta al pensar.

   • ANTHROPIC_MODEL — El modelo principal. Acepta aliases ( sonnet , opus , haiku , fable ) o
    nombres completos como claude-opus-4-8 . Desde la versión 2.1.154, Opus 4.8 es el modelo
    Opus por defecto.
   • ANTHROPIC_DEFAULT_HAIKU_MODEL — Qué modelo se usa cuando dices "haiku". Debe ser un
    nombre completo, no un alias.
   • ANTHROPIC_DEFAULT_SONNET_MODEL — Qué modelo se usa cuando dices "sonnet". Crítico para
    Bedrock/Vertex/Foundry: fíjalo a una versión específica.
   • ANTHROPIC_DEFAULT_OPUS_MODEL — Qué modelo se usa cuando dices "opus". Por defecto
    apunta a Opus 4.8.
   • ANTHROPIC_DEFAULT_FABLE_MODEL — Qué modelo se usa cuando dices "fable". Novedad de
    junio 2026. El alias fable apunta a Claude Fable 5 (clase Mythos), que entró en disponibilidad
    general en la versión 2.1.170.
   • ANTHROPIC_CUSTOM_MODEL_OPTION — ID de un modelo extra que quieres añadir como entrada
    personalizada en el selector /model (para modelos no estándar o de gateway).
   • ANTHROPIC_DEFAULT_<TIER>_MODEL_NAME / _DESCRIPTION / _SUPPORTED_CAPABILITIES —
    Personalizan el nombre, la descripción y las capacidades que se muestran en el selector /model
    para cada familia ( HAIKU , SONNET , OPUS , FABLE ). Capacidades válidas: thinking , effort ,
    interleaved_thinking , adaptive_thinking , max_effort .

   • CLAUDE_CODE_SUBAGENT_MODEL — Modelo para sub-agentes (los agentes que Claude Code lanza
    internamente).
   • CLAUDE_CODE_MAX_OUTPUT_TOKENS — Tokens máximos por respuesta. Nota: mencionada en
    guías, pero no verificada literalmente en la página oficial de variables de entorno de junio 2026;
    úsala con cautela.
   • CLAUDE_CODE_EFFORT_LEVEL — Cuánto "piensa" el modelo. Acepta low , medium , high ,
    xhigh , max y auto . Low es más rápido; high y superiores razonan más profundo. Tiene
    prioridad sobre el comando /effort y el ajuste effortLevel . Desde la versión 2.1.172, Opus
    4.8 entra en high por defecto.

   • CLAUDE_CODE_ALWAYS_ENABLE_EFFORT — Pon 1 para enviar el parámetro de esfuerzo en cada

AWS Bedrock

Bedrock es el servicio de AWS que te permite usar Claude dentro de tu cuenta de Amazon. Piensa en
Bedrock como un "puente" entre tu infraestructura AWS y Claude.

   • CLAUDE_CODE_USE_BEDROCK — El interruptor principal. Pon 1 para activar Bedrock.
   • AWS_REGION — La región AWS. Corrección (junio 2026): desde la versión 2.1.172, Claude Code sí
    lee la región de tus archivos de config de AWS ( .aws/config ). En la versión 2.1.171 y anteriores,
    en cambio, es obligatorio exportarla a mano. El orden de resolución es: AWS_REGION >
    AWS_DEFAULT_REGION > la región del perfil AWS activo > us-east-1 (fallback).

   • AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY — Credenciales AWS clásicas. Nunca las
    hardcodees en scripts.
   • AWS_SESSION_TOKEN — Para credenciales temporales de AWS STS.
   • AWS_PROFILE — Nombre del perfil de credenciales. Útil con aws sso login .
   • AWS_DEFAULT_REGION — Respaldo si AWS_REGION no está definida.
   • AWS_BEARER_TOKEN_BEDROCK — API key simplificada de Bedrock. Más simple que las
    credenciales completas.

   • ANTHROPIC_BEDROCK_SERVICE_TIER — Service tier de Bedrock: default , flex o priority .
    Se envía como cabecera X-Amzn-Bedrock-Service-Tier . La disponibilidad varía por modelo y

   • CLAUDE_CODE_SKIP_BEDROCK_AUTH — Omite autenticación AWS. Usa cuando un gateway

Bedrock Mantle y Claude Platform on AWS
A junio de 2026 hay dos formas nuevas de hablar con Claude dentro de AWS, además del Bedrock
clásico:

Bedrock Mantle deja que Claude Code use la API nativa de Anthropic en vez de la Invoke API de
Bedrock. Requiere la versión 2.1.94 o superior.

   • CLAUDE_CODE_USE_MANTLE — Pon 1 (o true ) para usar el endpoint Mantle de Bedrock. Se
    puede combinar con CLAUDE_CODE_USE_BEDROCK .
   • CLAUDE_CODE_SKIP_MANTLE_AUTH — Pon 1 para saltar la autenticación en el cliente cuando un
    gateway inyecta las credenciales en el servidor.
   • ANTHROPIC_BEDROCK_MANTLE_BASE_URL — Sobrescribe el endpoint de Bedrock Mantle. Por
    defecto se deriva de la región AWS.

Claude Platform on AWS es otra opción que usa workload identity federation y una API key de
workspace sacada de la consola de AWS.

   • ANTHROPIC_AWS_API_KEY — Clave de API de workspace para Claude Platform on AWS. Se envía
    como x-api-key y tiene prioridad sobre la firma SigV4 de AWS.
   • ANTHROPIC_AWS_BASE_URL — Sobrescribe el endpoint de Claude Platform on AWS. Por defecto:
     https://aws-external-anthropic.{AWS_REGION}.api.aws .

   • ANTHROPIC_AWS_WORKSPACE_ID — Requerida para Claude Platform on AWS. Se envía como
    cabecera anthropic-workspace-id en cada petición.
   • ANTHROPIC_WORKSPACE_ID — ID de workspace para workload identity federation. Necesaria
    cuando la regla de federación abarca varios workspaces. Añadida en la versión 2.1.141.

Variables para Deshabilitar Funcionalidades

Estas variables son interruptores de "apagado". Pon 1 para apagar la funcionalidad. Son útiles para
simplificar Claude Code o cumplir políticas de seguridad.

Features deshabilitables
   • CLAUDE_CODE_DISABLE_1M_CONTEXT — Quita la ventana de 1M tokens del selector de modelos.
   • CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING — Desactiva razonamiento adaptivo. Revierte a
     MAX_THINKING_TOKENS .

Errores Comunes y Cómo Resolverlos

Cuando algo no funciona, casi siempre es una variable mal configurada. Aquí van los errores más
frecuentes:

   • "API key not found" — Verifica con echo $ANTHROPIC_API_KEY . Si usas suscripción, no
    configures esta variable.
   • "Model not found / 404" en Bedrock/Vertex — Fija versiones con
    ANTHROPIC_DEFAULT_*_MODEL . Verifica que el modelo esté habilitado en tu región.

   • "on-demand throughput isn't supported" — En Bedrock, usa IDs de inference profile (con
    prefijo us. o global. ), no model IDs directos.
   • "Región incorrecta en Bedrock" — Desde la versión 2.1.172, Claude Code lee la región de tu
    .aws/config ; en la 2.1.171 y anteriores es obligatorio exportar AWS_REGION a mano. Ejecuta /
    status para ver la región resuelta. El orden es AWS_REGION > AWS_DEFAULT_REGION > perfil
    AWS > us-east-1 .
   • "AWS credentials expired" — Configura awsAuthRefresh en settings.json:
    {"awsAuthRefresh": "aws sso login --profile myprofile"} .

   • "ChainedTokenCredential failed" (Foundry) — Ejecuta az login o configura
    ANTHROPIC_FOUNDRY_API_KEY .

   • "CERTIFICATE_ERROR / TLS failed" — Configura NODE_EXTRA_CA_CERTS con tu CA corporativo.
    Nunca uses NODE_TLS_REJECT_UNAUTHORIZED=0 en producción.
   • "Timeout exceeded" — Aumenta BASH_DEFAULT_TIMEOUT_MS y BASH_MAX_TIMEOUT_MS .
   • "Variable no persiste entre comandos" — Usa CLAUDE_ENV_FILE para cargar variables en cada
    comando.
   • "MCP tool output truncated" — Aumenta MAX_MCP_OUTPUT_TOKENS (ej: 50000 ).
   • "Cargos inesperados con suscripción" — ANTHROPIC_API_KEY está configurada y bypasea tu

Resumen

Claude Code reconoce más de 230 variables de entorno organizadas en 16 categorías. Las más
importantes controlan la autenticación (ANTHROPIC_API_KEY), el modelo (ANTHROPIC_MODEL),
los proveedores cloud (Bedrock/Vertex/Foundry) y la red (HTTPS_PROXY,
NODE_EXTRA_CA_CERTS). Puedes configurarlas en el shell, en settings.json o con
CLAUDE_ENV_FILE. Recuerda: en settings.json todo va entre comillas, y para proveedores cloud
siempre fija las versiones de modelo.

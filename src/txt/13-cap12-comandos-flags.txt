    Claude Code tiene muchos comandos y opciones. Piensa en ellos como los botones de
    un control remoto: cada uno hace algo diferente. En este capítulo vamos a ver TODOS
    los botones disponibles. No necesitas memorizarlos todos. Usa este capítulo como
    referencia. Vuelve aquí cuando necesites algo específico.




Formas de iniciar Claude Code

Hay varias formas de abrir Claude Code desde tu terminal. Es como abrir una app: puedes hacer doble
clic (modo simple) o abrirla con opciones especiales.

La forma más básica es escribir claude y presionar Enter. Esto abre una sesión interactiva. Tú
escribes, Claude responde. Van y vienen como en un chat.

Sesión interactiva
Una sesión interactiva es como una conversación en persona. Tú hablas, Claude responde. Tú vuelves
a hablar, y así.

   • claude — Abre una sesión vacía. Claude espera tu primer mensaje.
   • claude "explica este proyecto" — Abre una sesión y envía tu mensaje de inmediato. Es
    como entrar a la oficina y decir algo desde la puerta.


Modo print (no interactivo)
El modo print es como enviar un mensaje de texto. Tú lo mandas, recibes la respuesta, y se acabó. No
hay conversación. Perfecto para scripts y automatización.

   • claude -p "explica esta función" — Ejecuta la consulta, imprime la respuesta y sale.
   • cat archivo.txt | claude -p "resume esto" — Envía el contenido de un archivo como
    contexto. Es como adjuntar un documento a tu mensaje.

El flag -p es la versión corta de --print . Ambos hacen lo mismo.

Nota sobre stdin: Desde la versión 2.1.128, el contenido recibido por pipe (stdin) está limitado a 10
MB. Si tu archivo es más grande, pásalo por ruta dentro del prompt en vez de hacer cat archivo |
claude -p . Verás un error tipo "Stdin exceeds 10MB limit" si te pasas.

Continuar y reanudar sesiones
A veces cierras Claude Code y luego quieres seguir donde te quedaste. Es como pausar una película y
retomarla después.

   • claude -c — Continúa la conversación más reciente en este directorio. Atajo de --continue .
   • claude -c -p "revisa errores" — Continúa la sesión anterior pero en modo print. Útil para
    scripts que retoman trabajo.
   • claude -r "auth-refactor" — Reanuda una sesión por su nombre. El -r es atajo de --
    resume .

   • claude -r "auth-refactor" "agrega validación" — Reanuda la sesión y envía un
    mensaje nuevo.


Otros comandos de terminal
   • claude update — Actualiza Claude Code a la última versión.
   • claude install [version] — Instala o reinstala el binario nativo. Acepta una versión exacta
    ( claude install 2.1.118 ), stable o latest . Muy útil para fijar versiones en CI y que los
    runs sean reproducibles.
   • claude auth login — Inicia sesión. Subflags útiles: --sso fuerza autenticación SSO de
    empresa, --console autentica contra Anthropic Console (facturación por API key, no por
    suscripción), y --email <addr> pre-rellena el email.
   • claude auth logout — Cierra sesión.
   • claude auth status — Muestra si estás logueado o no. Agrega --text para formato legible.
   • claude setup-token — Genera un token OAuth de larga vida y lo imprime en pantalla. Pensado
    para CI: guárdalo como CLAUDE_CODE_OAUTH_TOKEN en los secretos de tu pipeline. Requiere
    suscripción Claude activa.
   • claude agents — Abre la vista de agentes y sesiones en paralelo. Acepta --cwd <path> para
    filtrar solo las sesiones iniciadas desde ese directorio.
   • claude attach <id> — Engancha una sesión en background a tu terminal actual. Como entrar
    a la habitación donde Claude está trabajando.
   • claude logs <id> — Imprime la salida reciente de una sesión en background. Útil para mirar el
    progreso sin engancharte.

   • claude stop <id> — Detiene una sesión en background. claude kill es alias.
   • claude respawn <id> — Reinicia una sesión en background detenida sin perder la
    conversación. Con --all reinicia todas las detenidas.
   • claude rm <id> — Elimina una sesión en background de la lista.
   • claude daemon status — Diagnostica el proceso supervisor (daemon) que mantiene vivas las

   • claude daemon stop --any — Detiene ese proceso supervisor. Agrega --keep-workers para

   • claude project purge [path] — Borra TODO el estado local de un proyecto: transcripts,

   • claude auto-mode defaults — Muestra las reglas del clasificador de seguridad del modo
    auto. Usa claude auto-mode config para ver tu configuración efectiva.



Flags de sesión y modelo

Un flag es como un interruptor que cambias al arrancar Claude Code. Le dices: "arranca, pero con esta
configuración especial". Los flags van después de claude y empiezan con -- (o con - para la
versión corta).

Elegir modelo
--model te permite elegir qué cerebro usa Claude. Hay varios modelos, cada uno con diferentes
capacidades.

   claude --model claude-sonnet-4-6
   claude --model opus
   claude --model haiku



Puedes usar el nombre completo ( claude-sonnet-4-6 ) o el alias corto ( sonnet , opus , haiku ).

Nuevo alias y default (2.1.x, Junio 2026): Existe también el alias fable (además de sonnet ,
opus y haiku ). Y el modelo por defecto en las versiones 2.1.x pasó a ser Opus 4.8: si no pasas --
model , esa es la opción que usa Claude Code. (Los detalles y precios de cada modelo están en el
capítulo de modelos y precios.) Nota: los alias y defaults cambian rápido entre versiones; verifica con
claude --version y la documentación oficial si dependes de uno en concreto.

--fallback-model es tu plan B. Ahora acepta una lista separada por comas que Claude prueba en
orden. El respaldo se activa cuando el modelo principal está sobrecargado o ha sido retirado, no solo
cuando está saturado.



   claude --fallback-model sonnet,haiku "analiza este codigo"
   claude --model opus --fallback-model sonnet,haiku "diseña la arquitectura"



En el ejemplo, si Opus no está disponible Claude baja a Sonnet y, si tampoco, a Haiku. La preferencia
persiste vía la opción fallbackModel de tus settings, así que puedes dejarla configurada de forma
permanente. Es especialmente útil en modo --print y automatización, donde no quieres que un
script se caiga porque un modelo está ocupado.

--advisor <model> (v2.1.98+) activa la herramienta advisor del lado servidor: una segunda opinión
que Claude puede consultar durante la sesión. Le pasas un alias ( opus , sonnet y, desde v2.1.170+,
fable ) o un ID completo de modelo. Equivale a la opción advisorModel de settings.



   claude --advisor opus




Control de sesiones
   • --continue / -c — Carga la conversación más reciente.
   • --resume / -r — Reanuda una sesión por ID o nombre. Sin valor, muestra un selector. Desde la
    versión 2.1.144, las sesiones en segundo plano (background) aparecen en ese selector marcadas
    con la etiqueta bg , para que las distingas de un vistazo de las normales.
   • --session-id — Usa un UUID específico como ID de sesión. Útil para integraciones externas.

   • --fork-session — Al reanudar, crea una copia de la sesión en vez de modificar la original. Es
    como hacer una fotocopia antes de escribir encima.
   • --from-pr 123 — Reanuda sesiones vinculadas a un Pull Request. Ya no es solo GitHub:
    también soporta GitLab y Bitbucket. Acepta el número del PR o su URL completa.
   • --name / -n — Nombre de display para la sesión. Aparece en /resume y en el título del

Worktrees: trabajo aislado
Un worktree es como una mesa de trabajo separada. Puedes tener múltiples copias de tu proyecto,
cada una en su mesa, sin que se mezclen.



   claude -w feature-auth



Esto crea un worktree en <repo>/.claude/worktrees/feature-auth . Si no das nombre, se genera
uno automático. Ideal para trabajar en varias cosas a la vez.

Empezar desde un PR: -w también acepta #<número> o una URL de PR. Claude Code hace fetch del
PR desde origin y crea el worktree con esa rama ya checkeada.



   claude -w "#1234"
   claude -w https://github.com/org/repo/pull/1234



Modo tmux: Agrega --tmux para abrir el worktree en una sesión tmux. En iTerm2 usa paneles
nativos automáticamente. Si quieres forzar tmux clásico aunque haya iTerm2 disponible, usa --
tmux=classic . Importante: --tmux requiere --worktree ; sin él, Claude te dice "--tmux requires --
worktree" y aborta.



   claude -w feature-auth --tmux
   claude -w feature-auth --tmux=classic




Modo bare: mínimo para CI
--bare es el modo mínimo. Salta todo lo que no es esencial: hooks, skills, plugins, servidores MCP,
auto-memoria y archivos CLAUDE.md. Solo quedan disponibles Bash, lectura y edición de archivos.




                                                  242                                  @soyenriquerocha
                                                                           COMANDOS Y FLAGS DEL CLI




   claude --bare -p "resume este archivo"



Es como arrancar en modo seguro. Ideal para CI/CD y scripts donde necesitas el mismo resultado en
toda máquina. Salta OAuth y lecturas de keychain, así que la autenticación debe venir de
ANTHROPIC_API_KEY o de apiKeyHelper en --settings .

Internamente, --bare establece la variable de entorno CLAUDE_CODE_SIMPLE=1 . Si la exportas tú
mismo en tu shell o pipeline, obtienes el mismo efecto sin necesidad del flag.

Nota: En futuras versiones, --bare será el comportamiento por defecto de -p .


Modo seguro: diagnosticar una config rota
--safe-mode (v2.1.169+) arranca Claude Code con todas tus personalizaciones desactivadas. Es el
botón de "empezar limpio" para cuando algo se comporta raro y no sabes qué lo causa.



   claude --safe-mode



Desactiva: archivos CLAUDE.md , skills, plugins, hooks, servidores MCP, tus comandos y agentes
propios, output styles, temas, keybindings, status line, integración LSP y auto-memoria. En resumen,
todo lo que tú hayas añadido encima de Claude Code.

Lo que sí mantiene: tu autenticación, el modelo, las herramientas integradas (Bash, Read, Edit, etc.) y
los permisos normales. Y respeta la política de configuración administrada (managed settings) que te
imponga tu organización: esas no se saltan. Internamente activa la variable de entorno
CLAUDE_CODE_SAFE_MODE .

La idea: si Claude funciona bien con --safe-mode pero mal sin él, el problema está en una de tus
personalizaciones (un CLAUDE.md contradictorio, un hook que falla, un plugin roto, etc.). Vas
reactivando de a poco hasta encontrar al culpable.

No lo confundas con --bare : aunque ambos desactivan personalizaciones, sirven para cosas
distintas. --safe-mode es para diagnosticar (mantiene el comportamiento normal por defecto),
mientras que --bare es para velocidad en scripts y CI (modo mínimo de arranque rápido). Si tu
objetivo es encontrar una config rota, usa --safe-mode ; si es que un pipeline arranque rápido y
consistente, usa --bare .

Nivel de esfuerzo
--effort controla cuánto esfuerzo pone Claude en cada respuesta. Es como el dial de intensidad.

   • low — Respuestas rápidas y concisas.
   • medium — Balance entre velocidad y profundidad.
   • high — Análisis más profundo (por defecto).
   • xhigh — Un escalón por encima de high. Más razonamiento sin llegar al tope.
   • max — Máxima profundidad. Solo disponible con Opus 4.6.
   • auto — Claude decide según la tarea.



   claude --effort xhigh
   claude --effort max



Los niveles disponibles dependen del modelo: no todos los modelos exponen xhigh o max . Si pides
un nivel que tu modelo no soporta, Claude usa el más cercano que sí pueda.

También puedes cambiarlo durante la sesión con /effort o con flechas izquierda/derecha en /
model .



Versión
--version o -v muestra qué versión de Claude Code tienes instalada.



   claude -v




Background agents con --bg
--bg arranca la sesión como agente en background. Claude empieza a trabajar y te devuelve el
control de la terminal inmediatamente. Imprime el session ID y un recordatorio de los comandos de
gestión.



   claude --bg "investiga el test flaky en tests/auth_test.py"



Es como mandar a un becario a una tarea: él trabaja solo, tú sigues con lo tuyo. Después puedes:

   • claude logs <id> — Ver el progreso sin engancharte.

   • claude attach <id> — Entrar a esa sesión y ver qué hace en tiempo real.
   • claude stop <id> — Detenerla si quieres parar.
   • claude rm <id> — Eliminarla cuando ya no la necesites.
   • claude agents — Ver el dashboard de todas las sesiones background.

Combinable con --agent para arrancar un subagente concreto en background:



   claude --bg --agent investigador "busca todos los TODOs en src/"



Perfecto para lanzar varias investigaciones en paralelo sin bloquear tu terminal.

Correr un comando de shell, no una sesión Claude: con --exec le dices a --bg que ejecute un
comando de terminal normal como job en segundo plano (respaldado por un PTY), en vez de arrancar
una sesión de Claude. Útil para dejar corriendo tests o builds largos junto a tus agentes y verlos en el
mismo dashboard.



   claude --bg --exec 'pytest -x'



Lo gestionas con los mismos comandos ( claude logs , claude attach , claude stop ) que un
agente en background.



Flags de herramientas y permisos

Claude Code puede usar herramientas: leer archivos, ejecutar comandos, editar código. Estos flags
controlan qué herramientas puede usar y cuáles necesitan tu permiso. Es como darle las llaves de
ciertas habitaciones de tu casa.

Permitir herramientas sin preguntar
--allowedTools le dice a Claude: "usa estas herramientas sin preguntarme". Normalmente Claude
te pide permiso. Con este flag, las herramientas listadas se ejecutan automáticamente.



   claude --allowedTools "Bash(git log *)" "Bash(git diff *)" "Read"



En este ejemplo, Claude puede ejecutar comandos de git log, git diff, y leer archivos sin pedirte
confirmación.

COMANDOS Y FLAGS DEL CLI




Soporta wildcards con * . Por ejemplo, Bash(git *) permite cualquier comando git.

OJO con el espacio antes de * : la sintaxis de permission rules trata el espacio como parte del
patrón.

   • Bash(git diff *) (con espacio antes de * ) — Prefijo exacto. Matchea git diff
    archivo.txt pero NO git diff-index .

   • Bash(git diff*) (sin espacio) — Matchea cualquier cosa que empiece con git diff ,
    incluido git diff-index y git difftool .

Cuando pre-apruebas comandos, casi siempre quieres la versión con espacio. Es la diferencia entre
dar acceso solo a git diff o a toda la familia de comandos que empiezan igual.


Prohibir herramientas
--disallowedTools es lo opuesto. Elimina herramientas por completo. Claude ni siquiera sabe que
existen.



   claude --disallowedTools "Bash(git push *)" "WebFetch"



Es más fuerte que negar permisos. Con negar permisos, Claude sabe que la herramienta existe pero no
puede usarla. Con --disallowedTools , la herramienta desaparece del mapa.


Restringir herramientas disponibles
--tools define exactamente cuáles herramientas built-in están disponibles. Todo lo que no esté en
la lista se elimina del contexto del modelo.



   claude --tools "Bash,Edit,Read"



La sintaxis es una lista separada por comas sin paquete (no lleva nombres tipo Bash(git diff *) ,
eso es de --allowedTools ). Solo nombres de herramientas: Bash , Read , Edit , Write , Grep ,
Glob , etc.

Dos palabras clave especiales:

   • "" (cadena vacía) — Deshabilita TODAS las herramientas. Claude solo puede responder con
    texto.
   • "default" — Activa TODAS las herramientas built-in (el conjunto por defecto).

Modos de permisos
--permission-mode cambia cómo Claude pide permisos. Hay 6 modos:

  1. default — Pide permiso la primera vez que usa cada herramienta.
  2. acceptEdits — Acepta automáticamente ediciones de archivos. Sigue pidiendo permiso para
    comandos bash.
  3. plan — Solo análisis. Claude puede leer pero NO modificar nada.
  4. auto — Auto-aprueba todo, pero un clasificador de seguridad revisa cada acción en background.
    Si detecta algo peligroso, lo bloquea. Después de 3 bloqueos seguidos o 20 en total, Claude pausa
    y te pregunta. Requiere plan Team, Enterprise o API, modelo Sonnet 4.6 u Opus 4.6, y Anthropic
    API directa (no Bedrock ni Vertex).
  5. dontAsk — Rechaza automáticamente, excepto herramientas pre-aprobadas.
  6. bypassPermissions — Salta TODOS los permisos. Peligroso.



   claude --permission-mode auto




--enable-auto-mode (eliminado en v2.1.111)
Este flag ya no existe. Fue eliminado en la versión 2.1.111 porque el modo auto pasó a estar
disponible por defecto.

Si tu script o documentación todavía usa --enable-auto-mode , actualízalo. Ahora tienes dos formas
equivalentes:

   • Arrancar directamente en modo auto: claude --permission-mode auto
   • Ciclar a modo auto con Shift+Tab durante la sesión interactiva. El modo auto aparece en el
    ciclo sin necesidad de habilitarlo aparte.

Los requisitos del modo auto no cambiaron: plan Team/Enterprise/API, modelo Sonnet 4.6 u Opus 4.6
y Anthropic API directa (no Bedrock ni Vertex).

Dejamos esta entrada como nota histórica porque versiones anteriores de la guía y muchos artículos
por internet aún lo mencionan.

Saltar permisos (peligroso)
--dangerously-skip-permissions salta TODOS los prompts de permisos. Es como dejar la puerta
de tu casa abierta de par en par.



   claude --dangerously-skip-permissions -p "corrige todos los errores de lint"



Solo usa esto en entornos aislados: containers Docker, máquinas virtuales, o entornos de CI/CD
desechables. Nunca en tu computadora personal.

--allow-dangerously-skip-permissions es una versión más controlada. Habilita la opción sin
activarla de inmediato. Permite combinar con --permission-mode .


Herramienta de permisos personalizada
--permission-prompt-tool delega las decisiones de permisos a una herramienta MCP. Útil para
integraciones programáticas que necesitan gestionar permisos automáticamente.



   claude -p --permission-prompt-tool mcp_auth_tool "query"




Rutas protegidas
Hay archivos y directorios que Claude Code nunca modifica automáticamente, ni siquiera en
bypassPermissions . Siempre pide permiso explícito.

Directorios protegidos:

   • .git
   • .vscode
   • .idea
   • .husky
   • .claude (excepto .claude/commands , .claude/agents , .claude/skills y .claude/
    worktrees )

Archivos protegidos:

   • .gitconfig , .gitmodules
   • .bashrc , .bash_profile , .zshrc , .zprofile , .profile
   • .ripgreprc , .mcp.json , .claude.json

Flags de output y automatización

Estos flags controlan qué formato tiene la respuesta de Claude y cómo se comporta en modo
automático. Son fundamentales para scripting y CI/CD.

Formato de salida
--output-format cambia cómo Claude te entrega su respuesta. Solo funciona con --print .

   • text — Texto plano. Es el formato por defecto.
   • json — Un objeto JSON completo. Perfecto para parsear en scripts.
   • stream-json — Eventos NDJSON línea por línea. Ves la respuesta a medida que se genera.



   claude -p "lista los TODOs" --output-format json




Formato de entrada
--input-format controla cómo envías datos a Claude. Opciones: text (por defecto) y stream-
json (para enviar múltiples mensajes como stream).



Output estructurado con JSON Schema
--json-schema le dice a Claude: "quiero tu respuesta en este formato exacto". Le pasas un JSON
Schema y Claude devuelve datos que cumplen con ese formato.



   claude -p --json-schema '{"type":"object","properties":{"bugs":
   {"type":"array","items":{"type":"string"}}}}' "busca bugs en este codigo"



Es como darle un formulario a Claude para que lo llene. Solo funciona con --print .


Limitar turnos y presupuesto
--max-turns limita cuántas veces Claude puede "pensar y actuar" en una tarea. Cada vez que
Claude usa una herramienta y vuelve a razonar, es un turno.




                                                  249                                  @soyenriquerocha
COMANDOS Y FLAGS DEL CLI




   claude -p --max-turns 3 "refactoriza este módulo"



--max-budget-usd pone un tope de gasto en dólares. Cuando Claude llega al límite, se detiene.



   claude -p --max-budget-usd 5.00 "revisa todo el proyecto"



Ambos flags solo funcionan con --print . Son tu freno de mano para evitar sorpresas.


Otros flags de output
   • --verbose — Muestra información detallada de cada paso. Útil para depurar. También puedes
    activarlo con Ctrl+O durante una sesión.
   • --no-session-persistence — La sesión no se guarda en disco. Perfecta para tareas
    desechables. Solo con --print .
   • --include-partial-messages — Muestra el texto a medida que se genera (streaming).
    Requiere --print y --output-format stream-json .
   • --prompt-suggestions — Tras cada turno, emite un mensaje prompt_suggestion con el
    siguiente prompt que Claude predice que escribirías. Útil para construir interfaces que sugieren el
    próximo paso. Requiere la combinación --print + --output-format stream-json + --
    verbose .




Flags de system prompt

El system prompt son las instrucciones base que Claude sigue. Es como el manual de entrenamiento
de un empleado. Puedes cambiarlo por completo o agregarle instrucciones extra.

Reemplazar el system prompt
--system-prompt reemplaza TODO el prompt por defecto de Claude Code. Claude pierde todas sus
instrucciones originales y solo sigue las tuyas.



   claude --system-prompt "Eres un experto en Python. Solo escribes codigo con
   type annotations."



--system-prompt-file hace lo mismo pero lee las instrucciones de un archivo. Ideal para equipos
que quieren consistencia.



                                                   250                                   @soyenriquerocha
                                                                       COMANDOS Y FLAGS DEL CLI




   claude --system-prompt-file ./prompts/code-review.txt



Cuidado: Estos dos flags son mutuamente exclusivos. No puedes usar ambos a la vez.


Agregar al system prompt (recomendado)
--append-system-prompt agrega instrucciones al final del prompt por defecto. Claude conserva
todas sus capacidades originales Y sigue tus instrucciones extra.

Vim mode en el prompt
Si activas el modo Vim en /config → Editor mode (o con /vim ), el prompt se comporta como un
mini-Vim con tres modos: NORMAL, INSERT y VISUAL.

Entrar y salir de modos:

   • Esc — Vuelve a NORMAL desde cualquier modo.
   • i , I , a , A , o , O — Entran a INSERT (insert, inicio de línea, append, fin de línea, línea nueva
    debajo, línea nueva arriba).
   • v , V — Entran a VISUAL (carácter, línea).

Movimiento en NORMAL:

   • h j k l — Izquierda, abajo, arriba, derecha.
   • w e b — Palabra siguiente, fin de palabra, palabra anterior.
   • 0 $ ^ — Inicio de línea, fin de línea, primer no-blanco.
   • gg G — Inicio y fin del buffer.
   • f{c} F{c} t{c} T{c} , ; , — Buscar carácter en la línea y repetir.

Edición:

   • x , dd , D — Borra carácter, línea completa, hasta el final.
   • dw , de , db — Borra palabra (siguiente, hasta fin, anterior).
   • cc , C , cw — Cambia (borra y entra a INSERT) línea, hasta el final, palabra.
   • yy , Y , yw — Copia (yank) línea, igual, palabra.
   • p , P — Pega después / antes del cursor.
   • u , . — Deshacer, repetir último cambio.

Text objects (combina con d , c , y ):

   • iw / aw — Inner word / a word.
   • i" / a" , i' / a' — Dentro / incluido el delimitador.
   • i( / a( , i[ / a[ , i{ / a{ — Idem con paréntesis, corchetes y llaves.

Limitación importante: Ctrl+V (visual block mode de Vim) no está soportado. Para selecciones
rectangulares no hay equivalente; usa selecciones por línea o por carácter.

   Resumen del Capítulo

   Claude Code tiene tres tipos de controles: flags de terminal (como --print, --model, --bare y --bg),
   comandos slash para modo interactivo (como /compact, /diff, /recap y /voice), y variables de
   entorno para configuración persistente. Los flags más importantes son -p para scripting, --bare
   para CI mínimo, -c para continuar sesiones, --effort para controlar profundidad (incluye xhigh y
   max), --append-system-prompt para agregar instrucciones, --allowedTools para automatizar
   permisos, --bg para lanzar agentes en background y -w #PR para empezar desde un Pull Request.
   El modo de permisos auto usa un clasificador de seguridad para aprobar acciones sin preguntar; --
   enable-auto-mode quedó eliminado en v2.1.111 y se sustituye por --permission-mode auto. Si
   algo se comporta raro, --safe-mode (v2.1.169+) arranca sin tus personalizaciones para diagnosticar
   la config rota (distinto de --bare, que es para velocidad); y --advisor activa una herramienta
   consejera del lado servidor para una segunda opinión. Para resiliencia, --fallback-model acepta
   una lista de modelos de respaldo probada en orden. Para CI tienes claude setup-token (token
   OAuth de larga vida) y CLAUDE_CODE_OAUTH_TOKEN. Cuidado con el cambio de pricing del 15 de
   junio de 2026: claude -p y el Agent SDK consumirán crédito separado en planes de suscripción. Usa
   este capítulo como referencia rápida cuando necesites un flag o comando específico.

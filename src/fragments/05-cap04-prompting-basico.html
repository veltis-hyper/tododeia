Prompting Básico

Cómo hablarle a Claude para que te entienda a la primera

Principiante

Un prompt es lo que le escribes a Claude para pedirle algo. Puede ser una pregunta, una instrucción o una tarea. La calidad de lo que Claude te responde depende directamente de cómo le hables. En este capítulo vas a aprender las técnicas básicas para escribir prompts claros y efectivos. No necesitas experiencia previa: empezamos desde cero.

Qué es un prompt (y por qué importa)

Un prompt es el texto que le envías a Claude. Puede ser tan corto como una palabra o tan largo como varias páginas. Es tu forma de comunicarte con el modelo.

Piensa en Claude como un empleado nuevo. Es brillante, pero acaba de llegar. No conoce tu empresa, tus reglas ni tus preferencias. Si le das instrucciones vagas, haría su mejor esfuerzo... pero probablemente no será lo que esperabas.

La regla de oro del prompting es simple: muestra tu prompt a un compañero de trabajo que no conozca la tarea. Si esa persona se confundiría, Claude también se va a confundir.

La buena noticia: con unas pocas técnicas básicas, puedes mejorar drásticamente las respuestas de Claude. Vamos a verlas una por una.

Sé claro y directo

La técnica más importante es también la más simple: di exactamente lo que quieres.

Claude toma tus instrucciones de forma literal. Si le pides algo vago, te dará algo vago. Si le pides algo específico, te dará algo específico.

Es como pedir comida en un restaurante. No le dices al mesero "tráeme algo rico". Le dices: "Quiero una hamburguesa con queso, sin cebolla, con papas fritas".

Prompt vago vs. prompt específico

Mira la diferencia:

  • Vago — Crea un dashboard de analiticas
  • Específico — Crea un dashboard de analiticas. Incluye graficos de barras para ventas mensuales, una tabla con los 10 productos mas vendidos, y un filtro por fecha. Usa colores profesionales.

El segundo prompt le da a Claude una imagen clara de lo que esperas. El primero lo deja adivinando.

Usa lenguaje imperativo

Hay una diferencia enorme entre sugerir y pedir.

  • Pasivo — Can you suggest some changes to improve this function? — Claude solo dará sugerencias, sin tocar el código.
  • Directo — Change this function to improve its performance. — Claude implementará los cambios.

Si quieres que Claude haga algo, usa verbos de acción: "cambia", "crea", "escribe", "analiza". No le preguntes si "podría" hacerlo.

Usa pasos cuando el orden importa

Si tu tarea tiene varios pasos, ponlos en una lista numerada. Así Claude los sigue en orden y no se salta ninguno.

Sigue estos pasos:
1. Lee el documento adjunto
2. Identifica los 3 temas principales
3. Escribe un resumen de cada tema en 2 oraciones
4. Da una conclusion general

Es como darle una receta de cocina. Paso a paso, sin ambigüedades.

Dale contexto (el porqué)

Claude entiende mejor cuando sabe por qué le pides algo. El contexto es como darle el mapa completo en vez de solo una dirección.

Mira este ejemplo:

  • Sin contexto — NUNCA uses puntos suspensivos
  • Con contexto — Tu respuesta sera leida por un motor de texto a voz. Nunca uses puntos suspensivos porque el motor no sabra como pronunciarlos.

Cuando Claude entiende la razón, puede generalizar. En el segundo ejemplo, Claude también evitará otros símbolos problemáticos para texto a voz, sin que tengas que listar cada uno.

Piensa en ello como explicarle a un niño por qué no debe cruzar la calle corriendo. Si solo le dices "no lo hagas", no entiende. Si le explicas "porque vienen carros y es peligroso", tendrá cuidado incluso en situaciones que no le mencionaste.

Ancla respuestas en citas (documentos largos)

Cuando trabajas con documentos largos, hay una técnica muy efectiva para mejorar la precisión: pedirle a Claude que cite las partes relevantes antes de responder.

La idea es simple. En vez de dejar que Claude responda de memoria sobre un documento de 50 páginas, le pides que primero extraiga las citas relevantes en tags <quotes> y luego responda basándose en esas citas.

Encuentra citas del documento que sean relevantes para
la pregunta del usuario. Colocalas en tags <quotes>.
Luego, basandote en estas citas, responde la pregunta
en tags <answer>.

Esto funciona como un ancla: obliga a Claude a buscar datos reales en el documento en vez de generar información de memoria. Es especialmente útil cuando el documento tiene más de 20,000 tokens.

Usa ejemplos para guiar a Claude

Los ejemplos son tu herramienta más poderosa. En vez de explicar con muchas palabras, muestra lo que quieres.

Imagina que le pides a alguien que pinte tu casa. Puedes describir el color con palabras... o puedes mostrarle una foto. La foto es mucho más clara.

Zero-shot, one-shot y few-shot

Estos términos suenan complicados, pero son muy simples:

  • Zero-shot — Le pides algo sin dar ningún ejemplo. Solo instrucciones.
  • One-shot — Le das un ejemplo de lo que esperas.
  • Few-shot — Le das 3 a 5 ejemplos. Es lo que Anthropic recomienda para mejores resultados.

Es como enseñarle un baile a alguien. Puedes explicarlo con palabras (zero-shot), mostrarle un paso (one-shot), o bailarlo completo varias veces para que lo capte (few-shot).

Cómo escribir buenos ejemplos

Tus ejemplos deben cumplir tres reglas:

  1. Relevantes: Deben parecerse a tu caso real. No uses ejemplos de cocina si tu tarea es de programación.
  2. Diversos: Cubre diferentes escenarios. Si solo muestras un tipo de caso, Claude pensará que todos son iguales.
  3. Estructurados: Envuélvelos en etiquetas <example> para que Claude los distinga de las instrucciones.
<examples>
   <example>
      <input>El producto llego roto</input>
      <output>Categoria: Reclamo | Prioridad: Alta</output>
   </example>
   <example>
      <input>Cuando llega mi pedido?</input>
      <output>Categoria: Consulta | Prioridad: Media</output>
   </example>
</examples>

Con este formato, Claude entiende perfectamente el patrón que debe seguir.

Organiza tu prompt con etiquetas XML

Las etiquetas XML son como carpetas para organizar las partes de tu prompt. Le dicen a Claude: "esto son instrucciones", "esto es contexto", "esto es la pregunta".

Piensa en un formulario de papel. Cada campo tiene su etiqueta: "Nombre", "Dirección", "Teléfono". Las etiquetas XML hacen lo mismo con tu prompt.

Etiquetas más usadas

Estas son las etiquetas que usarás con más frecuencia:

  • <instructions> — Tus instrucciones principales
  • <context> — Información de fondo que Claude necesita
  • <input> — El dato que quieres que Claude procese
  • <example> — Un ejemplo de entrada y salida
  • <output> — El formato de respuesta que esperas
  • <thinking> — Para que Claude razone antes de responder
  • <answer> — Para la respuesta final

Puedes inventar tus propias etiquetas. Lo importante es que el nombre sea descriptivo. <datos_del_cliente> es mejor que <d1>.

Ejemplo completo con XML

<instructions>
Eres un asistente de atencion al cliente.
Clasifica el mensaje del usuario segun su tipo y prioridad.
</instructions>

<examples>
   <example>
     <input>Mi pedido llego danado</input>
     <output>Tipo: Reclamo | Prioridad: Alta</output>
   </example>
</examples>

<input>
{{mensaje_del_usuario}}
</input>

Este prompt tiene todo separado: instrucciones, ejemplos e input. Claude sabe exactamente dónde empieza y termina cada parte.

Asígnale un rol a Claude

Decirle a Claude quién es cambia cómo responde. Es como ponerle un uniforme: si le dices que es un doctor, responderá como doctor.

Esto se hace en el system prompt (un mensaje especial que va antes de la conversación). Pero también funciona al inicio de tu mensaje normal.

Eres un asistente de programacion especializado en Python.
Ayudame a ordenar una lista de diccionarios por una clave especifica.

Un consejo importante: no exageres con el rol. Decir "eres un asistente útil de Python" funciona mejor que "eres el mejor programador del mundo que solo habla en jerga técnica". Los roles demasiado elaborados pueden limitar las respuestas de Claude.

Controla el formato de la respuesta

Claude tiende a responder con formato markdown (títulos, listas, negritas). A veces eso es útil. Otras veces, no es lo que quieres.

Hay cuatro técnicas para controlar el formato:

Di qué hacer, no qué NO hacer

Las instrucciones positivas funcionan mejor que las prohibiciones.

  • Menos efectivo — No uses markdown en tu respuesta
  • Más efectivo — Tu respuesta debe estar compuesta de párrafos fluidos en prosa.

Es como darle direcciones a alguien. "No vayas por la calle 5" no es tan útil como "ve por la calle 8".

Tu prompt influye en la respuesta

Dato curioso: el formato de tu prompt afecta el formato de la respuesta. Si escribes tu prompt lleno de markdown y bullet points, Claude responderá igual. Si escribes en prosa simple, Claude también responderá en prosa simple.

Piensa en ello como una conversación. Si le hablas formal, te responde formal. Si le hablas casual, te responde casual.

Elimina los preámbulos

A veces Claude empieza su respuesta con frases como "Aquí tienes el resumen..." o "Basándome en tu solicitud...". Si no quieres eso, pídelo directamente:

Responde directamente sin preambulos.
No empieces con frases como "Aqui tienes...", "Basandome en..." o similares.

Claude obedecerá e irá directo al grano.

Prompt oficial para minimizar markdown

Anthropic documentó un prompt específico y muy efectivo para cuando necesitas que Claude escriba en prosa fluida sin exceso de listas y formato. Puedes copiarlo y usarlo directamente:

<avoid_excessive_markdown_and_bullet_points>
Cuando escribas reportes, documentos, explicaciones tecnicas,
analisis o cualquier contenido extenso, escribe en prosa clara
y fluida usando parrafos y oraciones completas. Usa saltos de
parrafo para organizacion y reserva markdown principalmente
para `codigo inline`, bloques de codigo, y encabezados simples.

NO uses listas ordenadas o no ordenadas a menos que:
a) estes presentando items verdaderamente discretos donde
    el formato de lista es la mejor opcion, o
b) el usuario pida explicitamente una lista.

En lugar de listar items con vinetas o numeros, incorporalos
naturalmente en oraciones. NUNCA generes una serie de vinetas
excesivamente cortas.

Tu objetivo es texto legible y fluido que guie al lector
naturalmente a traves de las ideas.
</avoid_excessive_markdown_and_bullet_points>

Este prompt usa una etiqueta XML descriptiva que refuerza la instrucción. Es ideal para reportes, análisis y documentos largos donde el exceso de bullet points rompe la lectura.

Controla el formato de matemáticas (LaTeX)

Claude Opus 4.7 (y desde Opus 4.6) usa LaTeX por defecto para expresiones matemáticas. Si estás en un contexto donde LaTeX no se renderiza (como texto plano o un chat simple), las fórmulas aparecerán con símbolos como \frac{}{} que son difíciles de leer.

Para desactivarlo, agrega esta instrucción a tu prompt:

Formatea tu respuesta solo en texto plano.
No uses LaTeX, MathJax, ni ninguna notacion de markup
como \( \), $, o \frac{}{}.
Escribe todas las expresiones matematicas usando
caracteres de texto estandar.

Esto es solo relevante si trabajas con contenido matemático. Para la mayoría de las tareas, no necesitas preocuparte por esto.

Pídele que piense paso a paso

Cuando la tarea es compleja, pedirle a Claude que razone antes de responder mejora mucho la precisión. Es como pedirle a un estudiante que muestre su trabajo en un examen de matemáticas.

La forma más simple:

Piensa paso a paso sobre este problema. Luego da tu respuesta final.

Para más control, puedes usar etiquetas:

<thinking>Aqui Claude escribe su razonamiento</thinking>
<answer>Aqui va la respuesta final</answer>

También puedes pedirle que se verifique a sí mismo:

Antes de terminar, verifica tu respuesta contra estos criterios:
- Es correcta gramaticalmente?
- Responde la pregunta original?
- No contiene informacion inventada?

Esta técnica se llama Chain of Thought (cadena de pensamiento) y es especialmente útil para matemáticas, lógica y programación.

En los modelos actuales de Claude (de 4.6 en adelante, incluyendo Opus 4.7/4.8, Sonnet 4.6 y los nuevos Fable 5 / Mythos 5) esto es nativo: ya no hace falta pedirlo manualmente. El modelo decide solo cuánto razonar usando adaptive thinking y el parámetro effort (max, xhigh, high, medium, low). Según el modelo y la tarea, el nivel por defecto cambia (por ejemplo, high es típico, y para tareas de código algunos modelos suben a xhigh). Pedir 'piensa paso a paso' manualmente sigue funcionando, pero hoy lo normal es dejarle ese trabajo al modelo. Los detalles del parámetro effort están en el capítulo de la API.

Nota

Nota sobre Claude Opus 4.5: Este modelo es particularmente sensible a la palabra "think" y sus variantes cuando el pensamiento extendido está deshabilitado. Si notas comportamiento inesperado al pedir razonamiento, usa alternativas como "consider", "evaluate" o "reason through". Por ejemplo, en vez de Think step by step, prueba con Reason through this step by step.

Evita que Claude invente cosas

A veces Claude "alucina": responde con información que suena correcta pero es inventada. Es como un estudiante que no estudió pero intenta sonar convincente en el examen.

La solución es simple: dale permiso para decir "no sé".

Si no estas seguro de alguna informacion, dilo explicitamente.
No adivines ni inventes datos.

Para tareas de código, esta instrucción es aún más poderosa:

Nunca especules sobre codigo que no hayas leido.
Si el usuario menciona un archivo, DEBES leerlo antes de responder.

Los modelos actuales de Claude (la familia 4.x y posteriores: Opus 4.7/4.8, Sonnet 4.6, y los más nuevos Fable 5 y Mythos 5) ya son menos propensos a alucinar que versiones anteriores. Pero esta instrucción sigue siendo una buena práctica. Las técnicas de este capítulo aplican igual a todos estos modelos; qué modelo es cuál lo ves en el capítulo de modelos.

La estructura ideal de un prompt

Ahora que conoces todas las piezas, veamos cómo armar un prompt completo. Esta es la estructura recomendada por Anthropic:

  1. Rol: Quién es Claude en este contexto
  2. Contexto / Documentos: Información de referencia (al inicio si es larga)
  3. Instrucciones: Qué debe hacer, paso a paso
  4. Ejemplos: 3 a 5 ejemplos del resultado esperado
  5. Formato de salida: Cómo quieres la respuesta
  6. Pregunta o tarea: Lo que quieres que haga (al final)

No siempre necesitas todas las partes. Un prompt simple puede tener solo la pregunta. Pero para tareas importantes, esta estructura te da los mejores resultados.

Un dato clave: pon los documentos largos al inicio y la pregunta al final. Pruebas de Anthropic muestran que esto mejora la calidad de la respuesta hasta un 30%.

Errores comunes de principiante

Estos son los errores que todos cometemos al principio. Aprende a reconocerlos para evitarlos.

Error 1: Ser demasiado vago

El problema: No especificar formato, nivel de detalle ni comportamiento deseado.

La solución: Indica formato exacto, longitud deseada y nivel de detalle. Si quieres que Claude se luzca, pídelo: "Ve más allá de lo básico y crea algo completo y detallado".

Error 2: Pedir sugerencias cuando quieres acción

El problema: Escribir "¿podrías sugerir cambios?" cuando quieres que Claude implemente los cambios.

La solución: Usa verbos imperativos. "Cambia esta función" en vez de "¿podrías sugerir cambios para esta función?".

Error 3: Formato no deseado

El problema: Claude responde con demasiados bullet points, markdown o listas cuando querías prosa fluida.

La solución: Usa instrucciones positivas sobre el formato. Escribe tu prompt en el estilo que quieres recibir. Envuelve las instrucciones de formato en etiquetas XML descriptivas.

Error 4: Preámbulos innecesarios

El problema: Claude empieza con "Aquí tienes el resultado..." antes de dar la respuesta real.

La solución: Agrega al prompt: "Responde directamente sin preámbulos".

Error 5: Alucinaciones por no dar permiso de decir 'no sé'

El problema: Claude inventa información cuando no sabe algo.

La solución: Agrega: "Si no estás seguro, dilo. No adivines." Esto reduce las alucinaciones de forma significativa.

Error 6: Rol demasiado restrictivo

El problema: Decirle a Claude que es "el mejor experto mundial que solo habla en jerga técnica" limita sus respuestas.

La solución: Mantener roles simples: "Eres un asistente útil especializado en [área]". Menos es más.

Ejemplos Prácticos

Prompt básico vs. prompt mejorado para clasificación

Prompt básico:

Clasifica esta oración según el artículo de Wikipedia al que
pertenece.
Artículos: {{títulos}}
Oración: {{oración}}

Prompt mejorado:

Eres un sistema de clasificación de texto especializado en emparejar
oraciones con títulos de artículos de Wikipedia.

Revisa estos títulos de artículos:

{{títulos}}

Ahora clasifica esta oración:

{{oración}}

Sigue estos pasos:
1. Lista los conceptos clave de la oración
2. Compara cada concepto con los títulos
3. Elige el título más apropiado

Escribe tu análisis en <thinking> y luego solo el título elegido.

El prompt mejorado agrega: un rol claro, etiquetas XML para separar datos, pasos de razonamiento, y un formato de salida explícito. La diferencia en calidad de respuesta es enorme.

Usar ejemplos para clasificar mensajes de soporte

Clasifica el mensaje del cliente por tipo y prioridad.

<examples>
   <example>
      <input>Mi pedido llego roto y quiero un reembolso</input>
      <output>Tipo: Reclamo | Prioridad: Alta</output>
   </example>
   <example>
      <input>Cuando llega mi pedido?</input>
      <output>Tipo: Consulta | Prioridad: Media</output>
   </example>
   <example>
      <input>Gracias, todo perfecto!</input>
      <output>Tipo: Feedback positivo | Prioridad: Baja</output>
   </example>
</examples>

<input>El cobro se hizo doble en mi tarjeta</input>

Con 3 ejemplos diversos, Claude entiende exactamente el patrón de clasificación. Los ejemplos cubren diferentes tipos (reclamo, consulta, feedback) para que Claude generalice correctamente.

Prompt con contexto para texto a voz

Tu respuesta será convertida a audio por un motor de texto a voz.
Por eso:
- Escribe números en palabras ("tres" en vez de "3")
- No uses abreviaturas ("por ejemplo" en vez de "ej.")
- Evita simbolos que no se pronuncian fácilmente

Explica qué es la fotosíntesis en 3 oraciones.

Al dar el contexto (texto a voz), Claude entiende la razón detrás de cada regla y puede generalizar a situaciones similares que no le mencionaste.

Evitar alucinaciones en tareas de código

Nunca especules sobre código que no hayas leido.
Si el usuario menciona un archivo, DEBES leerlo antes de responder.
Si no estas seguro, di "no tengo esa información" en vez de adivinar.

Explica qué hace la función calcularTotal en el archivo utils.js

Con esta instrucción, Claude leerá el archivo antes de responder. Sin ella, podría inventar lo que hace la función basándose en el nombre.

Anclar respuesta en citas de un documento largo

{{DOCUMENTO_LARGO}}

Encuentra citas del documento que sean relevantes para
responder la siguiente pregunta. Colocalas en tags <quotes>.
Luego, basandote en estas citas, responde en tags <answer>.

Pregunta: Cuales fueron los principales cambios en la política
de precios durante el último trimestre?

Al pedir citas primero en tags <quotes>, Claude ancla su respuesta en datos reales del documento. Esto reduce alucinaciones y mejora la precisión en documentos largos.

Consejo

Consejo

Si antes una sola instrucción bastaba para que el modelo la aplicara a todo el documento, ahora puede aplicarla solo al primer caso. Si quieres aplicación amplia, dilo explícito: 'aplica esto a cada sección' o 'para cada item de la lista'.

Advertencia

Cuidado con pedir 'sugerencias' cuando quieres acción. '¿Podrías sugerir cambios?' haría que Claude solo sugiera. 'Cambia esto' haría que lo cambie.

Advertencia

Los roles demasiado elaborados ('eres el mejor experto mundial') pueden limitar las respuestas de Claude. Mantener roles simples y funcionales.

Advertencia

Evita lenguaje agresivo como 'CRITICAL: YOU MUST...' o 'IMPORTANT: ALWAYS...' con modelos nuevos como Claude 4.6. Este tipo de instrucciones, que eran necesarias en modelos anteriores, ahora pueden causar que Claude sobre-ingenieríe la solución o sea demasiado proactivo. Usa instrucciones naturales y directas: en vez de 'CRITICAL: You MUST use this tool when...' simplemente escribe 'Usa esta herramienta cuando...'.

Nota

Las técnicas de este capítulo funcionan en todas las interfaces: claude.ai, la API y Claude Code. Los templates con variables {{doble llave}} solo están disponibles en la API y Console.

Nota

Si vienes de documentación antigua, la técnica de 'prefilled responses' (empezar la respuesta del asistente para forzar un formato) está deprecada desde Claude 4.6: las peticiones con prefill en el último turno del asistente devuelven error 400. Para forzar formato hoy se usan Structured Outputs, instrucciones directas en el system prompt o etiquetas XML. El detalle va en el capítulo de la API.

Consejo

Antes de empezar a iterar prompts, define tus criterios de éxito (qué cuenta como una buena respuesta: formato, longitud, factualidad, tono) y cómo vas a medirlos. Sin criterios claros, iterar es subjetivo y nunca terminas.

Resumen del Capítulo

Un buen prompt es claro, específico y tiene contexto. Las técnicas básicas son: dar instrucciones directas, explicar el porqué, usar ejemplos (3-5 idealmente), organizar con etiquetas XML, asignar un rol simple, y pedir razonamiento paso a paso. Evita ser vago, usar prohibiciones en vez de instrucciones positivas, y siempre dale a Claude permiso para decir 'no sé'. Para documentos largos, ancla las respuestas pidiendo citas en tags antes de la tarea principal. Con modelos nuevos como Claude 4.6, usa instrucciones naturales y directas en vez de lenguaje agresivo.

Referencia Completa de Settings

Tabla exhaustiva de TODOS los settings de Claude Code con ubicación, tipo, valor por defecto y descripción. Nivel: intermedio.

Este apéndice es tu diccionario de settings. Aquí encontrarás TODOS los ajustes que puedes cambiar en Claude Code, organizados por categoría. Cada setting tiene su tipo, su valor por defecto y dónde puedes usarlo. Úsalo como referencia rápida cuando necesites configurar algo específico.

Cómo Funciona la Configuración

Claude Code guarda sus ajustes en archivos JSON. Piensa en estos archivos como capas de ropa. Cada capa puede agregar o cambiar algo. Las capas de arriba tienen más poder que las de abajo.

El orden de poder (de más fuerte a más débil) es:

  1. Managed Settings — Las reglas del jefe. Nadie puede cambiarlas. Son políticas de empresa.
  2. Argumentos de línea de comandos — Flags como --model sonnet. Solo duran esa sesión.
  3. Settings locales del proyecto — El archivo .claude/settings.local.json. Tus preferencias personales para este proyecto.
  4. Settings compartidos del proyecto — El archivo .claude/settings.json. Los comparte todo el equipo.
  5. Settings de usuario — El archivo ~/.claude/settings.json. Tus preferencias globales.

Dato clave

Los settings que son listas (arrays) se fusionan entre niveles. No se reemplazan. Si agregas un permiso en el nivel de usuario y otro en el de proyecto, Claude Code usa ambos.

Archivos de Configuración

Estos son todos los archivos donde Claude Code busca configuración:

  • ~/.claude/settings.json — Tus settings globales. Aplican a todos tus proyectos.
  • .claude/settings.json — Settings del proyecto. Se commitean al repo. Todo el equipo los ve.
  • .claude/settings.local.json — Tus overrides personales para este proyecto. Están en .gitignore.
  • managed-settings.json — Políticas enterprise. Ubicación según SO: macOS en /Library/Application Support/ClaudeCode/, Linux en /etc/claude-code/, Windows en C:\Program Files\ClaudeCode\.
  • managed-settings.d/*.json — Directorio drop-in para fragmentos de política. Se fusionan alfabéticamente con el archivo base. Archivos ocultos (con punto) se ignoran. Usa prefijos numéricos (10-telemetry.json, 20-security.json) para controlar el orden.
  • ~/.claude.json — Preferencias, OAuth, servidores MCP, caches.
  • .mcp.json — Servidores MCP del proyecto.
  • CLAUDE.md — Instrucciones para Claude. No es un setting, pero influye en su comportamiento.
  • .claude/rules/*.md — Reglas modulares por tema.
  • .claude/agents/ — Subagentes personalizados.

Managed settings por MDM/OS

En macOS, usa perfiles de configuración con el dominio com.anthropic.claudecode (Jamf, Kandji). En Windows, usa la clave de registro HKLM\SOFTWARE\Policies\ClaudeCode con valor Settings (REG_SZ con JSON). También se soporta HKCU\SOFTWARE\Policies\ClaudeCode con menor prioridad. Precedencia dentro de managed: server-managed > MDM/OS > file-based > HKCU.

Tip

Agrega "$schema": "https://json.schemastore.org/claude-code-settings.json" al inicio de tu archivo settings.json. Esto te da autocompletado y validación en tu editor.

Ver Tus Settings Activos

Para ver qué settings están activos y de dónde vienen, usa estos comandos dentro de Claude Code:

  • /status — Muestra cada capa de configuración con su origen.
  • /config — Abre una interfaz con pestañas para ver y modificar settings.

Permisos

Los permisos son como las reglas de una casa. Dicen qué puede hacer Claude y qué no. Funcionan con tres listas: allow (permitir), ask (preguntar) y deny (prohibir).

Las reglas se evalúan en este orden: primero deny, luego ask, luego allow. La primera regla que coincide gana. Deny siempre manda.

Sintaxis de Reglas de Permisos

Las reglas de permisos usan patrones. Aquí tienes los más comunes:

  • Bash o Bash(*) — Coincide con todos los comandos Bash.
  • Bash(npm run *) — Coincide con comandos que empiezan con npm run. El * es un comodín.
  • Read(./.env) — Controla lectura de archivos. Sigue la sintaxis de gitignore.
  • Edit(/docs/**) — Controla edición de archivos. ** coincide recursivamente.
  • WebFetch(domain:example.com) — Controla solicitudes web a un dominio.
  • mcp__servidor__herramienta — Controla herramientas MCP específicas.
  • Agent(nombre) — Controla qué subagentes puede usar Claude.
  • Write(ruta) — Controla escritura de archivos nuevos. Sigue la misma sintaxis de rutas que Edit.
  • NotebookEdit(ruta) — Controla edición de notebooks Jupyter.
  • Task(nombre) — Controla qué tareas en background puede crear Claude.
  • Skill(nombre) — Controla qué skills puede ejecutar Claude.
  • MCP(servidor:herramienta) — Controla herramientas MCP. Alternativa a mcp__servidor__herramienta.

Prefijos de ruta para Read/Edit:

  • //ruta — Ruta absoluta desde la raíz del sistema.
  • ~/ruta — Relativa a tu home.
  • /ruta — Relativa a la raíz del proyecto.
  • ./ruta — Relativa al directorio actual.

Cuidado

Bash(ls *) coincide con ls -la pero NO con lsof. El espacio antes de * importa. Bash(ls*) coincide con ambos.

Ejemplos Prácticos

Settings mínimos de usuario

{
    "$schema": "https://json.schemastore.org/claude-code-settings.json",
    "permissions": {
        "deny": ["Read(./.env)", "Read(./secrets/**)", "Bash(curl *)"]
    }
}

Este es un archivo básico para ~/.claude/settings.json. Bloquea lectura de archivos .env y secrets, y prohíbe comandos curl. Es un buen punto de partida para proteger tus archivos sensibles.

Configuración enterprise con sandbox

{
    "permissions": {
        "allow": ["Bash(npm run *)", "Bash(git *)"],
        "deny": ["WebFetch", "Read(~/credentials)"]
    },
    "sandbox": {
        "enabled": true,
        "filesystem": {
            "denyRead": ["~/.aws/credentials"]
        },
        "network": {
            "allowedDomains": ["github.com", "*.npmjs.org"],
            "allowManagedDomainsOnly": true
        }
    },
    "allowManagedPermissionRulesOnly": true
}

Configuración para empresas. Permite git y npm, bloquea fetch web y credenciales, activa el sandbox con dominios restringidos, y fuerza que solo las reglas managed apliquen.

Restringir modelos disponibles

{
    "model": "sonnet",
    "availableModels": ["sonnet", "haiku"]
}

Fuerza Sonnet como modelo por defecto y solo deja que los usuarios elijan entre Sonnet y Haiku. Útil para controlar costos.

Entorno sin conexión (air-gapped)

{
    "env": {
        "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1",
        "DISABLE_AUTOUPDATER": "1"
    }
}

Desactiva toda la telemetría, reportes de errores, actualizaciones automáticas y el comando /bug. Ideal para redes restringidas.

Hook: lint automático después de ediciones

{
    "hooks": {
        "PostToolUse": [
            {
                "matcher": "Edit|Write",
                "hooks": [
                    {
                        "type": "command",
                        "command": "npx eslint --fix $(echo $CLAUDE_PROJECT_DIR)"
                    }
                ]
            }
        ]
    }
}

Cada vez que Claude edita o escribe un archivo, se ejecuta ESLint automáticamente. El hook se dispara después de que la herramienta Edit o Write termina.

Status line con modelo y costo

{
    "statusLine": {
        "type": "command",
        "command": "jq -r '\"[\\(.model.display_name)] \\(.context_window.used_percentage // 0)% context | $\\(.cost.total_cost_usd // 0)\"'"
    }
}

Muestra en la barra inferior el modelo activo, el porcentaje de contexto usado y el costo total de la sesión. Usa jq para formatear el JSON que recibe por stdin.

Usar AWS Bedrock con modelos pinneados

{
    "env": {
        "CLAUDE_CODE_USE_BEDROCK": "1",
        "ANTHROPIC_DEFAULT_OPUS_MODEL": "us.anthropic.claude-opus-4-8-v1",
        "ANTHROPIC_DEFAULT_SONNET_MODEL": "us.anthropic.claude-sonnet-4-6-v1",
        "ANTHROPIC_DEFAULT_HAIKU_MODEL": "us.anthropic.claude-haiku-4-5-v1"
    }
}

Configura Claude Code para usar AWS Bedrock. Al pinnear versiones específicas de cada modelo, evitas roturas cuando Anthropic lanza nuevas versiones.

Windows: configurar Git Bash

{
    "env": {
        "CLAUDE_CODE_GIT_BASH_PATH": "C:\\Program Files\\Git\\bin\\bash.exe"
    }
}

En Windows, si Claude Code no encuentra Git Bash automáticamente, usa esta variable para indicarle la ruta exacta.

Consejo

Agrega "$schema": "https://json.schemastore.org/claude-code-settings.json" al inicio de tu settings.json para obtener autocompletado y validación en tu editor.

Consejo

Usa /status dentro de Claude Code para ver todas las capas de configuración activas y de dónde vienen.

Consejo

Los arrays se fusionan entre niveles, no se reemplazan. Si defines permisos en usuario y en proyecto, Claude Code usa ambos.

Advertencia

Las reglas deny siempre ganan. Si un tool está denegado en cualquier nivel, ningún otro nivel puede permitirlo.

Advertencia

Los hooks se capturan al inicio de la sesión. Si los cambias mientras Claude trabaja, necesitas ir a /hooks o reiniciar.

Advertencia

El sandbox solo aplica a comandos Bash. Las herramientas Read, Edit y WebFetch no están afectadas.

Advertencia

Las reglas de permisos Bash para restringir argumentos de comandos son frágiles. Prefiere deny rules y WebFetch con dominios específicos.

Advertencia

Los settings de ~/.claude.json (editorMode, showTurnDuration, terminalProgressBarEnabled, autoConnectIde, teammateMode) NO van en settings.json. Si los mezclas, obtendrás un error de validación.

Nota

CLAUDE.md es contexto, no configuración forzada. Claude intenta seguirlo, pero no hay garantía de cumplimiento estricto.

Nota

Auto memory solo carga las primeras 200 líneas de MEMORY.md al inicio de cada sesión.

Nota

En rutas de permisos Read/Edit, /Users/alice/file es relativa a la raíz del proyecto. Para ruta absoluta, usa //Users/alice/file (doble barra).

Nota

includeCoAuthoredBy y ANTHROPIC_SMALL_FAST_MODEL están deprecados. Usa attribution.commit y ANTHROPIC_DEFAULT_HAIKU_MODEL respectivamente.

Resumen

Claude Code usa un sistema de configuración por capas donde los managed settings tienen máxima prioridad y los de usuario la mínima. Hay más de 100 settings y 60 variables de entorno organizados en categorías: modelo, permisos, sandbox, hooks, MCP, channels, worktree, skills, UI y más. Los arrays se fusionan entre niveles (no se reemplazan) y las reglas deny siempre ganan. Los settings de ~/.claude.json (interfaz local) no deben mezclarse con settings.json.

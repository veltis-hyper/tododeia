Los Modelos de Claude

Opus, Sonnet y Haiku: cuál elegir y por qué

Nivel: Principiante

Claude no es un solo modelo. Es una familia con tres miembros: Haiku, Sonnet y Opus. Cada uno tiene un trabajo diferente. Piensa en ellos como tres tallas de motor: pequeño, mediano y grande. En este capítulo vas a aprender qué hace cada uno, cuánto cuesta y cuál te conviene según tu proyecto.

Los tres niveles: Haiku, Sonnet y Opus

Imagina que vas a una tienda de herramientas. Hay tres taladros:

  • Haiku — El taladro portátil. Ligero, rápido y barato. Perfecto para colgar un cuadro.
  • Sonnet — El taladro intermedio. Hace casi todo lo que necesitas en casa.
  • Opus — El taladro industrial. Para trabajos pesados donde necesitas máxima potencia.

Los modelos de Claude funcionan igual. Haiku es el más rápido y barato. Sonnet es el equilibrio entre velocidad e inteligencia. Opus es el más inteligente pero el más caro.

La buena noticia: Sonnet maneja el 90% de las tareas del día a día. Solo necesitas Opus para cosas realmente complejas.

Cuándo usar cada uno

Aquí va una guía rápida:

  • Usa Haiku cuando necesites respuestas rápidas y baratas. Clasificar textos, responder preguntas simples, filtrar contenido. Es como enviar un mensaje de texto: rápido y al grano.
  • Usa Sonnet para la mayoría de tu trabajo. Escribir código, analizar documentos, crear contenido. Es tu herramienta de todos los días.
  • Usa Opus para tareas que necesitan pensar mucho. Razonamiento científico complejo, agentes autónomos, análisis legal profundo. Es como contratar al mejor especialista.

Los modelos actuales (junio 2026)

Ahora mismo hay tres modelos principales recomendados activamente por Anthropic. Son los que deberías usar en proyectos nuevos: Claude Opus 4.8, Claude Sonnet 4.6 y Claude Haiku 4.5.

Además, desde junio de 2026 existe una clase nueva por encima de Opus: la clase Mythos. La forman Claude Fable 5 (disponibilidad general), Claude Mythos 5 (acceso limitado vía Project Glasswing) y Claude Mythos Preview (un research preview solo por invitación para flujos de ciberseguridad defensiva, sin self-serve sign-up). Le dedicamos su propia subsección más abajo.

Claude Opus 4.8: el nuevo flagship

Opus 4.8 es el modelo tope de línea de la familia Opus desde junio de 2026. Reemplaza a Opus 4.7 como flagship; Opus 4.7 sigue funcionando pero pasó a la categoría de legacy activo. (Ojo: desde junio de 2026 existe además una clase Mythos por encima de Opus — la vemos en la siguiente subsección.)

Estos son sus números clave:

  • ID de API — claude-opus-4-8.
  • Ventana de contexto — 1 millón de tokens. Un token es un pedacito de texto — aproximadamente una palabra. 1 millón de tokens son varias novelas completas. (En Microsoft Foundry, Opus 4.8 se queda en 200K de contexto, no 1M.)
  • Salida máxima — 128,000 tokens. Con Batch API soporta hasta 300,000 tokens de salida usando el beta header output-300k-2026-03-24.
  • Precio — $5 por millón de tokens de entrada, $25 por millón de salida (idéntico al de Opus 4.7 y Opus 4.6).
  • Reliable knowledge cutoff — enero 2026. Conocimiento factual fiable hasta esa fecha.
  • Velocidad — moderada — piensa mejor, pero no es el más rápido.

Opus 4.8 mejora sobre Opus 4.7 en codificación, tareas agénticas, razonamiento y trabajo de conocimiento. Hereda casi todas las características que llegaron con la generación 4.7+:

  • Solo adaptive thinking — Opus 4.8 no soporta extended thinking con budget_tokens. Si lo intentas usar, la API devuelve un error 400. El único modo de razonamiento profundo es adaptive thinking: el modelo decide solo cuánto pensar según la dificultad del problema.
  • Effort levels con default high — Puedes guiar el esfuerzo con cinco niveles — low, medium, high, xhigh y max. En Opus 4.8 el valor por defecto del parámetro effort es high en todas las superficies (tanto en la API como en Claude Code). Si quieres otro nivel, tienes que fijarlo explícitamente.
  • Task budgets (beta) — Distinto de max_tokens. Le das al modelo una estimación de presupuesto para todo el loop agéntico (mínimo 20,000 tokens). Se activa con el beta header task-budgets-2026-03-13.
  • Nuevo tokenizer — Desde la generación 4.7 se usa un tokenizador distinto: el mismo texto puede consumir aproximadamente 30% más tokens que en Opus 4.6. Eso afecta tanto el costo como el tamaño efectivo de la ventana de contexto.
  • Imágenes de alta resolución — Soporta imágenes hasta 2576×2576 píxeles (3.75 megapíxeles), frente al límite anterior de 1568px (1.15 MP). Las coordenadas en la imagen son 1:1 con los píxeles reales — útil para señalar regiones específicas.
  • Sin temperature, top_p ni top_k personalizados — Opus 4.8 solo acepta los valores por defecto. Pasar valores distintos devuelve 400.
  • Thinking oculto por defecto — El campo de pensamiento viene vacío en la respuesta. Si quieres verlo, pasa thinking: {type: 'adaptive', display: 'summarized'}.
  • Fast mode — Disponible en Opus 4.8. Hasta 2.5x más rápido, con precio premium de $10/$50 por MTok (mucho más barato que el $30/$150 que costaba el fast mode en Opus 4.6 y 4.7). No es compatible con Batch API ni con Claude Platform on AWS.

En benchmarks, la familia Opus mantiene su posición fuerte en SWE-bench Verified, SWE-bench Pro, CursorBench y Vision Acuity (ver la sección de benchmarks). Opus 4.8 sube respecto a Opus 4.7 sobre todo en coding, tareas agénticas y razonamiento.

La clase Mythos: Fable 5 y Mythos 5

Desde junio de 2026 Anthropic introdujo una clase nueva que se sitúa por encima de Opus: la clase Mythos. Si Opus era el motor industrial, esto es el motor de competición. La forman tres modelos:

  • Claude Fable 5 (claude-fable-5) — el modelo más capaz de Anthropic con disponibilidad amplia. Disponible en general (GA) desde el 9 de junio de 2026.
    • Precio: $10 por millón de tokens de entrada, $50 por millón de salida.
    • Ventana de contexto: 1 millón de tokens. Salida máxima: 128,000 tokens.
    • Razonamiento: adaptive thinking siempre activo (no tiene extended thinking, igual que Opus 4.8).
    • Clasificadores de seguridad: Fable 5 incluye clasificadores que pueden rechazar ciertas solicitudes. Tenlo en cuenta si construyes flujos automáticos: una petición puede ser denegada por estos filtros.
  • Claude Mythos 5 (claude-mythos-5) — mismo precio que Fable 5, pero de disponibilidad limitada vía Project Glasswing. No tiene registro self-serve — solo clientes aprobados.
  • Claude Mythos Preview (claude-mythos-preview) — un research preview para ciberseguridad defensiva, solo por invitación.

¿Cuándo conviene Fable 5 sobre Opus 4.8? En tareas de hojas de cálculo, donde según los benchmarks de Anthropic supera a Opus 4.8 en todos los niveles de effort, resolviéndolas con menos turnos y entre 25% y 30% más rápido. También es notablemente más fuerte en benchmarks de trading. Para el resto del trabajo diario, Opus 4.8 (o directamente Sonnet 4.6) sigue siendo la opción más equilibrada en precio.

Claude Sonnet 4.6: el favorito de los desarrolladores

Sonnet 4.6 salió el 17 de febrero de 2026. Es el modelo que la mayoría de la gente debería usar. La documentación de Anthropic lo describe como la mejor combinación de velocidad e inteligencia para uso general — incluso por encima de Opus 4.6 en muchos workflows de producción.

Sus números:

  • Ventana de contexto — 1 millón de tokens (GA, disponible para todos).
  • Salida máxima — 64,000 tokens. Con Batch API, soporta hasta 300,000 tokens de salida usando el beta header output-300k-2026-03-24.
  • Precio — $3 por millón de tokens de entrada, $15 por millón de salida.
  • Reliable knowledge cutoff — agosto 2025 (training cutoff: enero 2026).
  • Velocidad — rápida.
  • Soporta — extended thinking y adaptive thinking.

¿Por qué es tan popular? Porque rinde casi igual que Opus en muchas tareas pero cuesta 40% menos en entrada ($3 vs $5 por MTok) y 40% menos en salida ($15 vs $25). En SWE-bench Verified saca 79.6%, contra el 87.6% de Opus 4.7. Es una diferencia real para coding agéntico de horizonte largo, pero para la mayoría del trabajo diario no la vas a notar.

Un dato revelador: el 70% de los desarrolladores que probaron Sonnet 4.6 lo prefirieron sobre Sonnet 4.5. Y el 59% lo prefiere incluso sobre Opus 4.5 (el modelo tope anterior).

Es el modelo por defecto en los planes Free y Pro de Claude. Si no sabes cuál elegir, empieza con este.

Claude Haiku 4.5: rápido y barato

Haiku 4.5 salió el 15 de octubre de 2025. Es el modelo económico, pero no te dejes engañar: es sorprendentemente capaz.

Sus números:

  • Ventana de contexto — 200K tokens (no soporta 1M).
  • Salida máxima — 64,000 tokens.
  • Precio — $1 por millón de tokens de entrada, $5 por millón de salida.
  • Reliable knowledge cutoff — febrero 2025 (training cutoff: julio 2025).
  • Velocidad — la más rápida de todos — 4 a 5 veces más rápido que Sonnet 4.5.
  • Soporta — extended thinking. No soporta adaptive thinking.

Haiku cuesta una tercera parte de lo que cuesta Sonnet. Y aun así, rinde a un nivel cercano al de Sonnet 4 a un tercio del costo y con más del doble de velocidad. En pruebas de código saca 73% en SWE-bench. Anthropic reporta también que supera a Sonnet 4 en tareas de computer use.

Es ideal para tareas de alto volumen. Si necesitas clasificar miles de mensajes, filtrar contenido, hacer routing (decidir a dónde enviar una solicitud) o desplegar subagentes dentro de una arquitectura multi-agente, Haiku es tu modelo.

Claude Code lo usa automáticamente para tareas simples. Cuando escribes algo fácil, Claude Code envía tu petición a Haiku para ahorrarte dinero.

Comparación de precios

Veamos los precios lado a lado. Los precios son por millón de tokens (MTok). Un millón de tokens es aproximadamente 750,000 palabras.

Piensa en los tokens como monedas de un videojuego. Cada palabra que le envías a Claude gasta monedas de entrada. Cada palabra que Claude te responde gasta monedas de salida.

Precios por millón de tokens (MTok). Para cada modelo: entrada / cache write 5min / cache write 1h / cache read / salida.

Opus 4.8 $5 $6.25 $10 $0.50 $25

Para ponerlo en perspectiva: si le envías a Sonnet 4.6 un documento de 10,000 palabras (~13,000 tokens), el costo de entrada sería de unos $0.04. Cuatro centavos.

Una nota sobre Opus 4.8 (y todos los modelos 4.7+): como el nuevo tokenizer consume aproximadamente 30% más tokens para el mismo texto, el costo real por documento sube proporcionalmente aunque el precio por MTok sea idéntico al de Opus 4.6.

Tres formas de ahorrar dinero

  1. Batch API (50% de descuento). Si no necesitas la respuesta al instante, puedes enviar muchas peticiones juntas. Claude las procesa cuando tenga capacidad y te cobra la mitad. Es como enviar paquetes por correo económico: más lento, pero más barato.

    Con Batch API, Haiku 4.5 baja a $0.50/$2.50 por MTok. Increíblemente barato.

  2. Prompt Caching. Si envías el mismo texto largo repetidamente (por ejemplo, un manual de instrucciones), puedes cachearlo. Hay dos opciones de duración:

    • Cache de 5 minutos — La escritura cuesta 1.25x el precio base. Es la opción por defecto y se amortiza con una sola relectura.
    • Cache de 1 hora — La escritura cuesta 2x el precio base. Útil cuando reutilizas el mismo contexto durante una sesión larga. Se amortiza con 2 relecturas.

    En ambos casos, cada relectura desde cache cuesta solo 0.1x del precio normal. Es como comprar una fotocopia en vez de imprimir de nuevo.

  3. Elegir el modelo correcto. No uses Opus para clasificar emails. Usa Haiku. Ahorras 80% sin perder calidad en tareas simples.

Precios especiales

Hay situaciones donde el precio cambia:

  • Fast Mode (Opus 4.8) — $10/$50 por MTok, hasta 2.5x más rápido. Mucho más barato que el fast mode de Opus 4.6 y 4.7, que costaba $30/$150 por MTok. No es compatible con Batch API ni con Claude Platform on AWS.
  • Inference geography (data residency) — Si pasas inference_geo: 'us' para forzar que la inferencia ocurra en Estados Unidos, se aplica un multiplicador 1.1x sobre todo el pricing. inference_geo: 'global' es el default y no tiene recargo. Este parámetro solo funciona en Opus 4.6 y posteriores; en modelos anteriores devuelve 400.
  • Endpoints regionales en Bedrock y Vertex AI — desde Sonnet 4.5 en adelante, las plataformas ofrecen endpoints globales y regionales. Los endpoints regionales y multi-region tienen un premium del 10% sobre los globales.

Estos multiplicadores se acumulan. Por ejemplo, en Opus 4.8 combinar Fast mode ($10/$50) con inference_geo us aplica el recargo 1.1x adicional sobre ese precio premium.

Capacidades compartidas y diferencias

Todos los modelos actuales comparten muchas capacidades. Pero también tienen diferencias importantes.

Lo que todos pueden hacer

Los tres modelos (Opus 4.8, Sonnet 4.6 y Haiku 4.5) pueden:

  • Ver imágenes — Les puedes enviar fotos, capturas de pantalla, diagramas. Entienden lo que ven. Esto se llama visión. Opus 4.8 acepta imágenes hasta 2576px (3.75 MP); los otros se quedan en el límite anterior de 1568px (1.15 MP).
  • Usar herramientas — Pueden llamar funciones externas, buscar en internet, ejecutar código. Esto se llama tool use.
  • Usar computadoras — Pueden controlar un mouse y teclado virtual. Esto se llama computer use.
  • Múltiples idiomas — Funcionan en español, inglés, francés, y muchos más.
  • Priority Tier — los tres tienen disponible el servicio premium con capacidad reservada.

Una capacidad que no es uniforme: el razonamiento profundo. Extended thinking (pensar internamente antes de responder con un presupuesto de tokens) está disponible en Sonnet 4.6 y Haiku 4.5. Opus 4.8 ya no lo soporta — solo trae adaptive thinking, donde el modelo decide solo cuánto pensar. Lo mismo aplica a Fable 5 (clase Mythos): adaptive thinking siempre activo, sin extended thinking.

Diferencias clave

  • Adaptive thinking — disponible en Opus 4.8 y Sonnet 4.6 (y siempre activo en Fable 5). El modelo decide automáticamente cuánto pensar.
  • Extended thinking (con budget_tokens) — disponible en Sonnet 4.6 y Haiku 4.5. Opus 4.8 ya no lo soporta (devuelve 400). Haiku 4.5 solo tiene este modo, no adaptive.
  • Ventana de 1 millón de tokens — Opus 4.8, Sonnet 4.6 y Fable 5 (GA, sin costo extra). Haiku 4.5 se queda en 200K.
  • Fast Mode — Opus 4.8 (igual que Opus 4.6 y 4.7). Sonnet y Haiku no lo tienen.
  • Salida máxima — Opus 4.8 y Fable 5 generan hasta 128K tokens. Sonnet 4.6 y Haiku 4.5 hasta 64K.
  • Soporte de imágenes de alta resolución — Opus 4.8 acepta hasta 3.75 MP. Los demás siguen en 1.15 MP.
  • Temperature / top_p / top_k personalizados — Opus 4.8 no los acepta. Los demás (Sonnet y Haiku) sí.

Reliable knowledge cutoff vs training data cutoff

Cuando le preguntas a Claude por hechos recientes, hay dos fechas que importan — y no son la misma:

  • Reliable knowledge cutoff — hasta esta fecha, el conocimiento del modelo es más amplio y fiable. Es la fecha que deberías usar como referencia mental.
  • Training data cutoff — rango más amplio de datos vistos durante entrenamiento. Cubre eventos posteriores, pero con cobertura más parcial.

Las fechas por modelo:

Modelo Reliable knowledge cutoff Training data cutoff
Opus 4.8 enero 2026 enero 2026
Sonnet 4.6 agosto 2025 enero 2026
Haiku 4.5 febrero 2025 julio 2025

Para datos posteriores al reliable cutoff, dale a Claude la información en el contexto o conéctalo a una herramienta de búsqueda web. No confíes en su memoria interna.

Cómo se llaman los modelos (nomenclatura)

Los nombres de los modelos siguen un patrón. Y el patrón cambió a partir de la generación 4.6 — vale la pena entender los dos formatos.

Modelos pre-4.6: el ID incluye fecha. Formato: claude-[nivel]-[version]-[YYYYMMDD]. Por ejemplo: claude-sonnet-4-5-20250929.

  • claude — Es Claude (obvio).
  • sonnet — El nivel (haiku, sonnet u opus).
  • 4-5 — La versión (4.5).
  • 20250929 — La fecha exacta. Esto se llama snapshot: el modelo concreto en ese día.

En modelos pre-4.6 también existen alias cortos sin fecha (como claude-sonnet-4-5) que apuntan al snapshot fechado más reciente de ese modelo. El alias no es un puntero evergreen — Anthropic lo deja apuntando a un snapshot concreto, pero lo expone con un nombre más cómodo.

Desde la generación 4.6: el ID ya no incluye fecha. Formato: claude-[nivel]-[version]. Por ejemplo: claude-opus-4-8, claude-sonnet-4-6, claude-opus-4-6.

El detalle importante: estos IDs sin fecha siguen siendo snapshots fijos, no evergreen. Los pesos del modelo detrás de claude-opus-4-8 no van a cambiar mañana. Cuando Anthropic libera una versión nueva (como pasó con Opus 4.8 sobre 4.7), es un ID nuevo (claude-opus-4-8), no una mutación del anterior.

Alias vs snapshot: cuál usar

El consejo cambia según la generación del modelo.

Para modelos pre-4.6:

  • Desarrollo y pruebas — el alias corto (claude-sonnet-4-5) es cómodo, pero técnicamente apunta a un snapshot concreto.
  • Producción — el ID con fecha (claude-sonnet-4-5-20250929) es la apuesta segura. Si Anthropic alguna vez moviera el alias, tu app no se entera.

Para modelos 4.6 y posteriores:

  • El ID sin fecha (claude-opus-4-8) ya es el snapshot fijo. No hay versión con fecha que añadir.
  • Puedes usarlo en producción con tranquilidad.

Es como la diferencia entre decir 'quiero Chrome 120' (pre-4.6, con fecha) vs 'quiero Chrome Opus 4.8' (post-4.6, el nombre ya identifica una versión fija). En ambos casos sabes exactamente qué te van a dar.

La historia de Claude: de Claude 1 a la clase Mythos

Claude ha evolucionado mucho en tres años. Aquí va un resumen rápido.

  • Noviembre 2023 — Claude 2.1 — Duplicó el contexto a 200K tokens.
  • Marzo 2024 — Claude 3 — Nacieron Haiku, Sonnet y Opus. Claude 3 incluyó visión (entender imágenes) y superó a GPT-4 en benchmarks.

  • Octubre 2024 — Claude 3.5 Sonnet v2 — Introdujo computer use. Claude podía usar una computadora como un humano.
  • Febrero 2025 — Claude 3.7 Sonnet — Introdujo extended thinking. El primer modelo que 'piensa' antes de responder.
  • Mayo 2025 — Claude 4 — Sonnet 4 y Opus 4. Extended thinking en toda la línea.
  • Octubre 2025 — Claude Haiku 4.5 — El Haiku más capaz hasta la fecha, 4-5x más rápido que Sonnet 4.5.
  • Noviembre 2025 — Claude Opus 4.5 — El precio de Opus bajó un 67%. De $15 a $5 por MTok de entrada.
  • Febrero 2026 — Claude Opus 4.6 y Sonnet 4.6 — 1M de contexto en GA, adaptive thinking y nuevo formato de IDs sin fecha.
  • 14 abril 2026 — Deprecation — Claude Sonnet 4 y Claude Opus 4 originales pasan a estado deprecated, con retiro previsto el 15 de junio de 2026.
  • 16 abril 2026 — Claude Opus 4.7 — Adaptive thinking como único modo, nuevo tokenizer, soporte de imágenes hasta 3.75 MP, SWE-bench Verified al 87.6%.
  • 20 abril 2026 — Retiro de Haiku 3 — El modelo más viejo de la familia 3 deja de funcionar en la API.
  • 9 junio 2026 — Clase Mythos — Anthropic estrena una clase por encima de Opus: Claude Fable 5 (GA) y Claude Mythos 5 (acceso limitado, Project Glasswing). Fable 5 supera a Opus en hojas de cálculo y trading.
  • Junio 2026 — Claude Opus 4.8 — El nuevo flagship de la familia Opus. Mejora coding, tareas agénticas y razonamiento sobre Opus 4.7; effort por defecto en high; fast mode más barato ($10/$50). Opus 4.7 pasa a legacy.

Ciclo de vida de un modelo

Anthropic clasifica cada modelo en uno de cuatro estados. Saber en qué estado está te ayuda a decidir si seguirlo usando o migrar.

  • Active (activo) — totalmente soportado y recomendado. Es la apuesta segura para proyectos nuevos. Hoy: Opus 4.8, Sonnet 4.6 y Haiku 4.5, además de Fable 5 (clase Mythos).
  • Legacy (legacy) — sigue funcionando pero ya no recibe actualizaciones. Podría pasar a deprecated en el futuro. Buen lugar para mantener integraciones existentes que no quieres tocar.
  • Deprecated (deprecado) — aún funciona pero Anthropic recomienda explícitamente migrar. Tiene un modelo de reemplazo y una fecha de retiro publicada. Hoy: Sonnet 4 y Opus 4 originales (retiro 15 junio 2026).
  • Retired (retirado) — ya no está disponible. Las requests al ID devuelven error. No hay vuelta atrás.

Dos garantías importantes de Anthropic:

  • Aviso mínimo de 60 días antes de retirar un modelo público. Tienes al menos dos meses para migrar desde que se anuncia el retiro.
  • Preservación a largo plazo de los pesos de modelos retirados. Eventualmente podrían volver a abrirse, aunque hoy no son consumibles.

Si quieres ver qué modelos están disponibles ahora mismo y sus capacidades, el endpoint /v1/models de la Models API te devuelve max_input_tokens, max_tokens y un objeto capabilities para cada uno. Útil para detectar uso de modelos viejos en tu codebase.

Modelos anteriores: todavía disponibles

Aunque deberías usar los modelos actuales, los modelos anteriores siguen disponibles por un tiempo. Aquí van los más relevantes.

Modelos legacy que aún puedes usar

  • Opus 4.7 (claude-opus-4-7) — el flagship anterior, reemplazado por Opus 4.8 en junio de 2026. Sigue costando $5/$25 por MTok y mantiene 1M de contexto, 128K de salida, adaptive thinking, el nuevo tokenizer y Fast mode. Pasó a legacy activo: funciona perfectamente, pero Opus 4.8 lo supera en coding, tareas agénticas y razonamiento. Si ya tenías una integración estable en 4.7, no hay prisa por migrar.
  • Opus 4.6 (claude-opus-4-6) — un flagship más antiguo. Sigue costando $5/$25 por MTok y mantiene 1M de contexto, 128K de salida y Fast mode. Es una opción razonable si no quieres lidiar con los cambios de comportamiento de la generación 4.7+ (sin temperature personalizada, nuevo tokenizer, adaptive-only). Posible retiro: no antes del 5 febrero 2027.
  • Sonnet 4.5 (claude-sonnet-4-5) — fue el rey del coding con 77.2% en SWE-bench. Mismo precio que Sonnet 4.6 ($3/$15). Superado por Sonnet 4.6, pero sigue funcionando bien. Posible retiro: no antes del 29 septiembre 2026.
  • Opus 4.5 (claude-opus-4-5) — trajo la reducción de precio del 67%. $5/$25. Buen modelo, pero Opus 4.6 y 4.7 lo superan. Posible retiro: no antes del 24 noviembre 2026.

Modelos legacy caros y deprecados

Estos modelos cuestan 3 veces más que los actuales y rinden peor:

Benchmarks: cómo se mide la inteligencia

Los benchmarks son pruebas estándar. Son como los exámenes que todos los modelos toman para compararse. Aquí van los más importantes.

Los benchmarks que importan

  • SWE-bench Verified — le dan al modelo un bug real de un proyecto de software. El modelo tiene que arreglarlo. Opus 4.7 resuelve el 87.6% (sube desde el 80.8% de Opus 4.6). Sonnet 4.6 resuelve el 79.6%. Haiku 4.5 el 73%.
  • SWE-bench Pro — versión más difícil del anterior. Opus 4.7 saca 64.3%, superando a Gemini 3.1 Pro (54.2%) y GPT-5.4 (57.7%). Opus 4.6 sacaba 53.4%.
  • CursorBench — mide qué tan bien trabaja el modelo dentro de un editor agéntico. Opus 4.7 saca 70% (vs 58% de Opus 4.6).
  • Vision Acuity — precisión en tareas visuales. Opus 4.7 saca 98.5% (vs 54.5% de Opus 4.6). El salto viene del soporte de imágenes hasta 2576px.
  • Rakuten-SWE-Bench — Opus 4.7 resuelve 3x más tareas que Opus 4.6, con mejoras de doble dígito en Code Quality y Test Quality.
  • OfficeQA Pro — tareas de productividad. Opus 4.7 comete 21% menos errores que su predecesor.
  • GPQA Diamond (referencia histórica) — preguntas de ciencias a nivel de doctorado. Opus 4.6 sacaba 91.3%; para comparar, Opus 3 sacaba 50.4%.
  • ARC-AGI 2 (referencia histórica) — problemas de lógica y abstracción. Opus 4.6 saca 68.8%. Sonnet 4.6 saca 58-60%.
  • Terminal Bench 2 (referencia histórica) — tareas de programación en terminal. Opus 4.6 tiene 65.4%; Anthropic reporta que Opus 4.7 resuelve casos que generaciones anteriores fallaban.

¿Qué significan estos números? Que la familia Opus resuelve casi 9 de cada 10 bugs reales de software en SWE-bench Verified y le saca ventaja real a los competidores en SWE-bench Pro. Opus 4.8 mejora a Opus 4.7 sobre todo en coding, tareas agénticas y razonamiento. Sonnet 4.6 está unos puntos por debajo, a una fracción del costo.

Fable 5 vs Opus 4.8. En la clase Mythos, Fable 5 sube otro escalón en tareas concretas. Según los benchmarks de Anthropic, supera a Opus 4.8 en hojas de cálculo en todos los niveles de effort: las resuelve con menos turnos y entre 25% y 30% más rápido. También es notablemente más fuerte en benchmarks de trading. Para la mayoría del trabajo diario, sin embargo, la diferencia no justifica el doble de precio ($10/$50 vs $5/$25).

Dónde puedes usar los modelos

Los modelos de Claude están disponibles en varias plataformas:

  • Claude API (directa) — la forma más común. Te registras en Anthropic y usas la API directamente.
  • Claude Platform on AWS — distinto de Bedrock. Se contrata a través de AWS Marketplace usando Claude Consumption Units. Nota: Fast mode no está disponible en esta plataforma.
  • AWS Bedrock — si ya usas Amazon Web Services. Los IDs empiezan con anthropic.claude-*. Desde Sonnet 4.5 en adelante, Bedrock ofrece endpoints globales y regionales. Los regionales tienen un premium del 10% sobre los globales.
  • Google Vertex AI — si ya usas Google Cloud. El formato es claude-modelo@fecha (en modelos con fecha) o claude-modelo (en 4.6+). Vertex AI ofrece endpoints global, multi-region y regional. Los multi-region y regional tienen el mismo premium del 10%.
  • Microsoft Foundry — disponible para modelos recientes. Ojo con un detalle: en Microsoft Foundry, Opus 4.8 ofrece 200K de contexto, no el millón de tokens que tiene en la Claude API y otras plataformas.
  • Claude.ai — la interfaz web. Todos los modelos disponibles según tu plan.
  • Claude Code — la herramienta de línea de comandos. Hace routing automático: envía tareas simples a Haiku y tareas complejas a Sonnet u Opus.

Un dato importante: los modelos con el mismo ID (sea snapshot fechado o ID sin fecha 4.6+) son idénticos en todas las plataformas. No importa si usas AWS, Google o la API directa. El modelo se comporta igual.

Planes de suscripción para Claude.ai

Si usas Claude a través de la web (claude.ai), hay varios planes:

  • Free ($0/mes) — Acceso básico a todos los modelos. Perfecto para probar.
  • Pro ($17-20/mes) — 5 veces más uso que Free. Acceso completo a Opus 4.8 y Cowork.
  • Max 5x ($100/mes) — 25 veces el uso de Free. Prioridad máxima. Claude Code completo.
  • Max 20x ($200/mes) — 100 veces el uso de Free. Cero latencia en la cola.
  • Team ($25-30/persona/mes) — Para equipos. Mínimo 5 personas.
  • Enterprise (precio personalizado) — SSO, controles de acceso, audit logs, compliance.

Si eres desarrollador individual, el plan Pro es el mejor valor. Si usas Claude Code intensivamente, considera Max.

Ejemplos Prácticos

Llamar a Opus 4.8 desde la API

import anthropic

client = anthropic.Anthropic()
message = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Analiza este código y sugiere mejoras"}]
)
print(message.content[0].text)

Usa el ID claude-opus-4-8 — desde la generación 4.6 los IDs ya no llevan fecha pero siguen siendo snapshots fijos. El parámetro max_tokens limita cuánto puede escribir Claude en su respuesta. Opus 4.8 NO acepta temperature, top_p ni top_k personalizados; pasarlos devuelve 400.

Usar Haiku para clasificación rápida y barata

message = client.messages.create(
    model="claude-haiku-4-5",
    max_tokens=100,
    messages=[{"role": "user", "content": "Clasifica este mensaje del cliente: 'Quiero devolver mi producto porque llego roto'"}]
)

Haiku es perfecto para tareas simples como clasificar mensajes. A $1 por millón de tokens de entrada, puedes clasificar miles de mensajes por centavos.

Usar la ventana de 1 millón de tokens

message = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=8192,
    messages=[{"role": "user", "content": documento_muy_largo}]
)

La ventana de 1 millón de tokens es GA (disponible para todos) en Opus 4.8, Sonnet 4.6 y Fable 5 (y también en los Opus legacy 4.7 y 4.6). No necesitas ningún flag beta ni parámetro especial — solo envía tu documento largo y el modelo lo procesará. El precio por token es el mismo sin importar el tamaño de la solicitud.

Adaptive thinking en Opus 4.8

message = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=128000,
    thinking={"type": "adaptive", "display": "summarized"},
    output_config={"effort": "high"},
    messages=[{"role": "user", "content": "Diseña la arquitectura del sistema..."}]
)

En Opus 4.8 ya no se usa extended thinking con budget_tokens (devuelve 400). Adaptive thinking es el único modo: el modelo decide solo cuánto pensar. Con display: 'summarized' recibes un resumen del razonamiento; por defecto el campo viene vacío. Los effort levels disponibles son low, medium, high, xhigh y max, y en Opus 4.8 el valor por defecto es 'high' en todas las superficies.

Task budgets en Opus 4.8 (beta)

message = client.beta.messages.create(
    model="claude-opus-4-8",
    max_tokens=128000,
    output_config={
        "effort": "high",
        "task_budget": {"type": "tokens", "total": 128000}
    },
    betas=["task-budgets-2026-03-13"],
    messages=[{"role": "user", "content": "Revisa el codebase y propón un plan"}]
)

Task budgets es distinto de max_tokens. max_tokens es un hard cap por request. Task budget es una estimación para todo el loop agéntico (mínimo 20,000 tokens) — le sirve al modelo para autorregular cuántos pasos dar. Requiere el header beta task-budgets-2026-03-13.

Ahorrar con Prompt Caching

message = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    system=[{
        "type": "text",
        "text": "Eres un asistente legal especializado en contratos...[texto largo]...",
        "cache_control": {"type": "ephemeral"}
    }],
    messages=[{"role": "user", "content": "Revisa esta cláusula"}]
)

El system prompt largo se cachea automáticamente. Con cache de 5 minutos, la primera vez pagas 1.25x del precio base. Con cache de 1 hora, pagas 2x. Las siguientes lecturas cuestan solo 0.1x en ambos casos. Si envías 10 preguntas con el mismo system prompt, ahorras mucho.

Batch API con 50% de descuento

batch = client.messages.batches.create(
    requests=[
        {"custom_id": "req-1", "params": {"model": "claude-haiku-4-5", "max_tokens": 100, "messages": [{"role": "user", "content": "Clasifica: texto 1"}]}},
        {"custom_id": "req-2", "params": {"model": "claude-haiku-4-5", "max_tokens": 100, "messages": [{"role": "user", "content": "Clasifica: texto 2"}]}}
    ]
)

La Batch API procesa muchas peticiones juntas con 50% de descuento. No recibes las respuestas al instante, pero pagas la mitad. Ideal para procesar grandes volúmenes. Nota: Fast mode no es compatible con Batch API.

Resumen del Capítulo

Claude tiene tres modelos principales recomendados: Haiku 4.5 (rápido y barato, $1/$5 MTok), Sonnet 4.6 (el favorito, equilibrio perfecto, $3/$15 MTok) y Opus 4.8 (el nuevo flagship desde junio 2026, $5/$25 MTok). Opus 4.8 mantiene el precio de Opus 4.7 y mejora en coding, tareas agénticas y razonamiento; soporta solo adaptive thinking (no extended thinking con budget_tokens), trae el effort por defecto en 'high' y usa el nuevo tokenizer que consume ~30% más tokens. Opus 4.7 pasa a legacy activo. Desde junio de 2026 existe además la clase Mythos por encima de Opus: Claude Fable 5 (GA, $10/$50 MTok, supera a Opus 4.8 en hojas de cálculo y trading) y Claude Mythos 5 (acceso limitado, Project Glasswing). Desde la generación 4.6 los IDs ya no llevan fecha (claude-opus-4-8) pero siguen siendo snapshots fijos. Para la mayoría de tareas, Sonnet 4.6 sigue siendo la mejor opción. Puedes ahorrar con Batch API (50% off), prompt caching (90% off en relecturas) y eligiendo el modelo correcto para cada tarea.
